## 3. 对机器指令中的写入操作进行核对

检查_start、_init、main、bb_init_pins、bb_probe、采样函数、等待函数和trap相关代码，结合寄存器基址及偏移核对存储指令；不是只搜索源码中的某个常量。

| 写入对象 | 地址或范围 | 机器指令中的行为 |
|---|---|---|
| SYSCTRL时钟使能 | 0x4002180C | main在0xB8写入旧值OR 0x21，打开bit0/bit5 |
| SYSCTRL软复位 | 0x40021810 | 0xD8置bit5，0x10C清bit5，保留其他位 |
| GPIOB输出、方向 | 0x40000100、0x40000104 | 操作bit2/bit3，保留其他位 |
| GPIOB开漏 | 0x40000158 | 操作bit2/bit3 |
| GPIOB上下拉 | 0x4000015C | 操作bit2/bit3及bit8/bit9 |
| GPIOB复用 | 0x40000168 | bb_init_pins在0x5FC、0x60C清除B2/B3对应3位字段，保留B0/B1等其他字段 |
| SRAM | .bss、栈、0x2000F000起邮箱 | 初始化、调用保存、采样、进度和完成标记 |
| CPU CSR | mtvec、mstatus | 设置异常入口、关闭全局中断；不是芯片JTAG控制寄存器 |

在所审查镜像的预期执行路径中，没有发现Flash控制器/NVR编程操作、向0x40021828 JTAG_EN写入钥匙或主动更改GPIOB0/TDO复用字段的操作。结束后为NOP循环，trap_handler为自循环。该镜像也没有调用硬件I2C初始化或UART打印。

范围限制：上述结果降低“旧应用主动改掉TDO或编程安全区”的优先级；不排除既有NVR状态、错误地址映射、异常执行、上电加载、安全逻辑或芯片内部集成问题。邮箱未逐项写入的旧内容不能视为当前寄存器的新采样。

## 6. 当前结论和下一步边界

已核实探针基本回环，以及旧ELF/BIN一致性；旧应用中没有找到主动关闭JTAG的预期操作；当前扫描配置的基础JTAG参数与历史成功配置一致。当前调查重点仍在目标端TAP是否获得有效时钟并脱离复位、安全/模式选择及TDO是否被选通。

仅凭现有PDF不能把这几种内部状态分开，也不能唯一判定TDO损坏。纯静态阶段不应继续猜一个未定义的H8档位或默认复用值。

如果老师能向设计方问一句最具体的问题：这批RISC-V COB在什么PADMUX电平、复位和安全条件下默认开放JTAG并使TDO输出？需要对应实物版本的明确条件说明，不一定需要完整RTL。若无法获得说明，则保留当前结论和证据边界，后续硬件验证另行安排。本轮不追加设备实验。
