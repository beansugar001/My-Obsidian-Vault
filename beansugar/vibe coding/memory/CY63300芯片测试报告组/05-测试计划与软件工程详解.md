## 2. 固件结构与启动机制详解（对照测试报告第4~5节核实过）

```
工程根/
├─ Makefile        主固件构建（firmware.elf/bin/hex/map）
├─ common.mk       子测试工程公共规则（test.zip里有，见第4节）
├─ link.lds        链接脚本（注意：不叫linker.ld）
├─ start.S         _start：gp/sp/.data拷贝/.bss清零 → _init → main
├─ trap_entry.S    中断/异常入口，存现场→调trap_handler→mret
├─ main.c          业务入口（协议测试：TA/设备/边缘节点消息签名验签）
├─ scheme.c/h      密钥演化、SM3签名、批量验证、时间布隆过滤器
├─ include/ lib/   头文件与驱动（uart/xprintf/risc_time/riscv_irq/
│                  trap_handler/HDURiscv_trng/sm3/bf/utils/sbrk/init）
├─ simple/         最小裸机测试
├─ coremark/       CoreMark 性能测试
├─ benchmarks/     MiBench 风格（adpcm/aes/blowfish/fft/gsm/sha…）
├─ spec_benchmarks/ SPEC2006裁剪（bzip2/mcf/sjeng/astar/hmmer/libquantum/lbm）
└─ vuln_tests/     安全漏洞测试套件
```

**内存布局**（link.lds，以 firmware.elf 实测为例）：
```
Flash 0x00000000-0x0003FFFF
  .init   @0x00000000 (108B, 含_start)
  .text   @0x0000006C (~9.4KB)
  .rodata @0x00002534
  .data   LMA在Flash（初值区）
SRAM 0x20000000-0x2001FFFF
  .data   @0x20000000（VMA，启动时从Flash拷来）
  .bss    @0x20000000 (15160B, 启动清零)
  heap    _end(0x20003B38) ~ 0x2001C000（_sbrk管理）
  .stack  @0x2001C000 16KB，栈顶 _sp=0x20020000
```
**启动地址 0x00000000**（ENTRY(_start)）。中断向量表不占 Flash——RISCV 版用 `mtvec` 寄存器指向 `trap_entry`（init.c 的 `_init()` 里 `write_csr(mtvec, &trap_entry)`），向量表本身是 SRAM 里的函数指针数组 `g_irq_vector[8]`。

## 3. 缺失文件的最小复原方案（万一前任不给完整工程）

test.zip 里的 `common.mk` 已经说明了一切。最小可编译骨架需要补：

1. `link.lds`——按第2节的内存布局写：ENTRY(_start)；flash ORIGIN=0x00000000 LENGTH=256K；ram ORIGIN=0x20000000 LENGTH=128K；段序 .init/.text/.rodata/(.data AT>flash)/.bss/.stack(16K)；导出 `_data_lma/_data/_edata/__bss_start/_end/_sp`；`__stack_size = 16K`。
2. `start.S`——`_start`：`la gp, __global_pointer$` → `la sp, _sp` → 拷 .data（_data_lma→_data.._edata）→ 清 .bss（__bss_start.._end）→ `call _init` → `call main` → 死循环。
3. `trap_entry.S`——RV32 全部 32 个通用寄存器 + mcause/mepc 压栈，`csrr mcause`，调 `riscv_trap_handler(mcause, mepc)`，恢复，mret。（test.zip 的 `riscv_irq.c` 里有 `riscv_trap_handler` 的原型，照着配。）
4. `lib/uart.c`——用 include/uart.h 的寄存器定义写：init（开 SYSCTRL bit8 时钟、GPIOC AFR1 把 PAD14/15 配功能4、BAUD=16e6/115200≈139、CTRL=TX_EN|RX_EN）、putc（等 !TX_FULL 写 TX_RX_BUF）、getc/tstc（STAT.RX_FULL）。
5. `risc_time.c`（现在是空的！）——`systick_Init/Get_counter/Get_overflow_count`。RISCV 版没有 ARM SysTick，用 `risc_time.h` 的接口自己实现：可用 FVT 的计数器、TIM@0x40001C00、或 mcycle CSR（`rdcycle`，tiny_riscv 若实现）。**benchmark 全部依赖它，不补没法跑性能测试。**
6. `main.c`——先写个 uart 打印 + LED/GPIO 翻转的最小 main 验证工具链，再逐步加测试项。

## 4. 编译与产物（报告第6节核实）

```bash
make              # 全量编译 → firmware.elf/bin/hex/map
make size         # 段大小
make disasm       # firmware.asm + firmware.lst(带源码)
make clean
make UART0_BAUDRATE=9600      # 临时改波特率
make ARCH=rv32im ABI=ilp32
```
产物：firmware.elf（GDB调试用）、firmware.bin（烧录用）、firmware.hex、firmware.map（查符号地址）。
查入口/段：`objdump -f firmware.elf`（start address 0x0）、`objdump -h`、`size -A`。

常见编译报错对照：工具链路径错（TOOLDIR）、undefined reference（源文件没进 C_SOURCES）、region overflowed（Flash/RAM 超）、unrecognized opcode（-march 不对，必须 rv32im）、cannot find link.lds（在子目录里跑 make）。

## 5. JTAG 烧录全流程（逐行注释版）

前置：CMSIS-DAPLink 接 H7；开两个 CMD 窗口。

**窗口1**（进 tinyriscv 工具目录）：
```
.\openocd.exe -f tinyriscv.cfg      # 成功会显示 JTAG 链与 IDCODE
```
**窗口2**（Windows 需启用 telnet 客户端功能）：
```
telnet localhost 4444
```
烧录序列（每行的寄存器含义都标注了，对应设计文档 4.2/4.5 节）：
```
init
halt                                # ★每次下载前先停CPU，否则Flash被取指占用
mww 0x4002180C 0x00080000           # PERI_CLKEN.bit19=1：开Flash控制器时钟
sleep 10
mww 0x40021810 0x00000000           # PERI_RST：解除Flash控制器复位
sleep 10
mww 0x40022004 0x00000001           # FLS_READ.read_cycle=01（16M时钟1等待）
mww 0x40022008 0x00100150           # FLS_COMMON（复位推荐值）
mww 0x4002200C 0x00820480           # FLS_WRITE1
mww 0x40022010 0x00100010           # FLS_WRITE2
mww 0x40022014 0x00000340           # FLS_WRITE3
sleep 10
mww 0x40022018 0x00007DFF           # FLS_ERASE1（扇区擦除时间）
mww 0x40022020 0xCA000340           # FLS_ERASE3（恢复时间）
sleep 10
mww 0x40022000 0x00000002           # FLS_CR.rwe_sel=10：扇区擦模式
sleep 5
mww 0x00000000 0x12345678           # 对0地址写任意值→触发扇区0擦除
sleep 500                           # ★等擦除完成！无状态寄存器只能等
mww 0x40022000 0x00000001           # rwe_sel=01：编程模式
sleep 5
load_image "路径/firmware.bin" 0x0 bin   # OpenOCD直接写内存→触发字编程
mww 0x40022000 0x00000000           # rwe_sel=00：回到只读保护
resume 0                            # 从0地址开始跑
```
> 提示：全片擦（rwe_sel=11 + FLS_ERASE2）慎用；验证烧录结果用 `mdw 0x0 8` 回读比对。若 JTAG 连不上：查 Vref（下载器 VCC 必须接 VDD_IO 3.3V）、共地、NRST 电平、以及保护等级是否锁了调试口（见报告02第13课 JTAG_EN 窗口魔数）。

## 6. 四大类测试的执行计划

### 6.1 性能测试（CoreMark + benchmarks + spec）
| 工程 | 内容 | 关注点 |
|---|---|---|
| coremark/ | 标准核心性能 | CoreMark/MHz；内存一定要放 SRAM；`QUICK_START.md` 有说明 |
| benchmarks/ | 13项 MiBench 风格（aes/blowfish/sha/fft/gsm…） | 每项独立计时，依赖 risc_time.c（**记得先补**） |
| spec_benchmarks/ | SPEC2006 七项裁剪版 | 编译内存大，注意 RAM 溢出 |

预期链路：串口打印各测试项耗时（tick）→ 换算 cycles/tick（16MHz）→ 与 60MHz 档位复测对比（改 OSC_CR 后注意 Flash read_cycle 要同步改！见报告02第5课）。

### 6.2 安全/漏洞测试（vuln_tests/）
- 三个编译开关：默认=安全观察模式；`make RUN_DESTRUCTIVE=1`=含空指针写等破坏性用例（**只在测试板跑，跑完重烧固件**）；`ENABLE_MTVEC_TAMPER=1`=mtvec 篡改探测。
- 用例覆盖：栈溢出回址覆盖、静态区越界（密钥表/策略字被改）、堆溢出/UAF/双重释放、整数溢出、空指针、未初始化内存、函数指针劫持、启动参数/镜像头/向量表篡改。
- 判定标准：芯片的 fault 机制（RISCV 版 `SYSCTL_CR0.fault_rst_en`）+ trap_handler 能否兜住异常而不是静默跑飞。**测试前把 fault_rst_en 的两种取值各跑一轮**，记录行为差异。

### 6.3 协议测试（根工程 main.c + scheme.c）
流程（报告附录3）：TA 初始化系统/主密钥 → 5 个 IoT 设备注册（ID+密钥）→ 密钥时间演化 → 各设备 SM3 签名消息 → 边缘节点批量验证 → 时间布隆过滤器 TBF 防重放 → 串口输出各阶段耗时。
关注点：SM3 软件实现 vs 硬件 HASH 引擎（0x40024000）的耗时对比可以顺带做——这就是你论文里的"软硬协同安全基线"素材。

### 6.4 侧信道测试（★你的主场★）
报告设备清单照抄 + 执行建议：

| 攻击 | 方法（报告原文要点） | 我的补充建议 |
|---|---|---|
| 计时攻击 | 固定密钥遍历随机明文记耗时；固定明文遍历密钥记耗时 | 用 risc_time 计数器；分析时间分布与密钥汉明重的相关性 |
| 功耗分析 SPA | 采 SM2 点乘等大功耗运算波形，找密钥依赖的重复模式 | 示波器≥500MSa/s；**注意芯片自带 random_clk 随机时钟门控和时钟加扰**（报告02第12课），先确认 ENC_CTL.Random_clk_enable 状态再定基线 |
| DPA/CPA | 固定集 vs 随机集功耗曲线，同点算 t 值，超阈值=泄露 | 采 thousands 条；用 S-box 输出做假设中间值（AES/SM4） |
| EMA | 近场探头+XYZ位移台扫热点+LNA放大 | 探头高度固定可复现；先扫 SKE/HASH 工作窗口 |

测试准备动作：① 把 VDDH 供电路径串一个采样电阻或用电流探头，剥离外围电路（报告清单里的"定制夹具"就是干这个）；② 线性低噪声电源替换 USB 5V；③ 触发信号用 GPIO 翻转（Pad 引出到 H4）让采集窗口对准加密运算。
