# CY63300 原样品 JTAG 失联及外设测试问题报告

**报告日期：** 2026-10-15  
**目的：** 请协助确认该芯片版本的 JTAG 引脚复用、PADMUX/复位/调试使能条件、TDO 输出条件和推荐诊断流程，以定位 JTAG 失联原因。

---

## 1. 问题摘要

这颗 CY63300 原样品在 2026-09-29 曾通过 JTAG 返回正确 ID `0x1e200a6f`，OpenOCD 识别出 RISC-V hart，并成功烧录、校验和运行诊断固件。之后同日再次访问时，JTAG 扫描开始返回全零，IR Capture 为 `0x00`（配置预期捕获值包含 `0x01`），后续排查一直没有恢复正确 ID。

目前在目标板接口处观察到 TCK、TMS、TDI 有命令相关的电平活动；TDO 在 U5-2/H7-16 未观察到可靠返回脉冲。底板到接口及绿色载板实际插接点的若干线路已测得低阻导通。当前 DAPLink 的独立 TDI→TDO 硬件回环通过 18/18，因此现有证据不支持把问题简单归因于当前 DAPLink 的基本收发故障。

**目前尚不能判定芯片损坏、TDO PAD 损坏或 NVR 安全锁定。** 最需要芯片方协助确认的是：这版 RISC-V 芯片的外部 PADMUX/复位状态如何控制 TAP 复位与使能，TDO 如何被复用到实际 PAD，以及该样品正常调试所需的上电和模式条件。

## 5. 软件与外设问题（与JTAG故障分开）

### 5.1 已有的软件执行证据

- 3248字节诊断程序曾成功烧录并校验；曾成功读取正确 TAP ID 和 hart。
- SRAM mailbox 完成标记及两组不同图样曾正确读回，支持 CPU 曾执行代码并写入 SRAM。
- 旧诊断固件的静态审查未发现直接改写 PAD6/TDO 或主动写 JTAG 禁用位的代码。但没有最后成功烧录镜像的现场哈希来证明磁盘源码与当时 Flash 每个字节完全一致。
- 新版3772字节 nCS 诊断固件当时只有构建记录，没有成功烧录记录；不能把该未证实固件当作失联原因。

### 5.2 I²C未跑通

- OLED 地址 `0x3C/0x3D` 的 GPIO 模拟探测未获得 ACK；后来 MPU 地址 `0x68/0x69` 也未获得有效 ACK。
- 时钟门控曾在 CPU mailbox 记录为开启，但 I²C 模块使能、有效 START/地址/数据事务和从机 ACK 并未同时形成证据闭环。

### 5.3 UART未跑通

- 用户报告 CH340和H4两侧分别做本地回环可用；CH340与芯片交叉连接时没有收到有效数据或启动 banner。
- UART跨设备链路、芯片实际波特率/系统时钟、芯片TX输出及当前固件是否会打印 banner 尚未全部确认。

## 6. 当前故障判断

目前最符合证据的故障范围是**目标端没有产生可被调试器识别的 JTAG 返回**。外部TCK/TMS/TDI活动、TDO外部线路导通和DAPLink独立回环通过，缩小了普通断线或探针基本采集失效的可能性；但尚不能在以下情况中作唯一选择：

1. 芯片实际使用的 PADMUX/JTAG 模式条件不正确；
2. TAP复位、时钟、使能或安全配置没有满足要求；
3. TDO复用/输出使能没有把 TAP 返回送到实际绑定PAD；
4. COB版本的PAD绑定、封胶内连接或芯片本体存在问题；
5. 其他未公开的上电、复位或调试进入条件。

手册提到 NVR/JTAG disable 机制，但**当前样品NVR值未读出**。不能把“可能的安全禁用机制”写成“芯片已锁定”。

## 7. 请芯片公司协助确认的问题

烦请结合这颗样品的 **CY63300 RISC-V版本、晶圆/批次和绿色COB载板版本**，尽可能给出明确的应用条件或原理图/RTL片段：

1. **JTAG PAD映射：** 对此RISC-V版本，TCK、TMS、TDI、TDO分别应连接到哪些逻辑PAD和封装/COB接点？手册复用表中 PAD0=TDI、PAD3=TMS、PAD6=TDO，以及 PAD4/PAD5标注的 SWDIO/SWCLK 应如何解释？实际TCK是否由PAD4、PAD5或其他专用路径提供？
2. **PADMUX电平：** 外部 PADMUX 在上电复位时的有效电平、是否需要外接上下拉、H/L分别选择什么模式？它是否参与JTAG使能，采样发生在何时？
3. **TAP复位和时钟：** TAP的复位源是什么？外部RST是否同时复位TAP？进入JTAG扫描前，RST、TCK及上电时序需要满足什么条件、保持多久？
4. **TDO输出路径：** TAP何时开始驱动TDO？TDO在非移位状态是否应保持高阻或固定电平？TDO_PAD输出使能、PAD复用优先级及可用于确认的测试序列是什么？
5. **调试使能/安全状态：** NVR1/NVR2中哪些具体位会关闭JTAG？关闭条件如何判定？是否存在安全的只读状态检查或官方恢复流程？请说明恢复流程是否会擦除Flash/NVR。
6. **电源要求：** 对本样品，VDD_IO约3.3 V、VDD测点约1.2 V是否符合正常工作状态？VDD、VDDH、VDDHOSC、EFUSE_VCC的正常接法、上电先后顺序和必要去耦是什么？
7. **最小复现建议：** 请提供适用于此版本的最小OpenOCD配置/扫描时序，以及若TCK/TMS/TDI有活动但IR Capture始终为0，芯片方建议优先检查的两到三项条件。
8. **版本对应资料：** 请确认目前手上的数字设计文档与该绿色COB样品的芯片变体、PAD复用表和绑定图是否完全对应；若不同，请提供对应版本的绑定表或应用说明。

## 9. 面向芯片公司的简短结论

原样品曾成功识别JTAG ID并运行诊断代码，之后JTAG链路返回全零。故障复现时，底板TCK/TMS/TDI有活动，TDO未观察到可靠返回；已测外部TDO线路低阻导通，当前DAPLink独立硬件回环18/18通过。PADMUX高低对照和多种扫描速度没有恢复ID。现有资料尚不能区分“模式/复位/使能或TDO复用条件未满足”与“COB内部绑定/芯片故障”。请协助确认该RISC-V版本的JTAG PAD映射、PADMUX真值表、TAP复位/使能条件、TDO输出使能及NVR调试禁用判定/安全恢复方法。

**本报告是故障定位请求，不预先认定芯片损坏、NVR锁定或TDO PAD损坏。**
