# CY63300 原样品 JTAG 失联及外设测试问题报告

**目的：** 请协助确认该芯片版本的 JTAG 引脚复用、PADMUX/复位/调试使能条件、TDO 输出条件和推荐诊断流程，以定位 JTAG 失联原因。

---

## 1. 问题摘要

该 CY63300 样品曾通过 JTAG 返回正确 ID `0x1e200a6f`，OpenOCD 识别出 RISC-V hart，并成功烧录、校验和运行诊断固件。现阶段 JTAG 扫描返回全零，IR Capture 为 `0x00`（配置预期捕获值包含 `0x01`），目标无法被正常识别。

目标板接口处观察到 TCK、TMS、TDI 有命令相关的电平活动；TDO 在 U5-2/H7-16 未观察到可靠返回脉冲。底板到接口及绿色载板实际插接点的若干线路已测得低阻导通。当前 DAPLink 的独立 TDI→TDO 硬件回环通过18/18，因此 DAPLink无问题。

**目前尚不能判定芯片损坏、TDO PAD损坏或NVR安全锁定。** 该RISC-V芯片版本的外部PADMUX/复位状态如何控制TAP复位与使能、TDO如何被复用到实际PAD，以及正常调试所需的上电和模式条件。

## 2. 问题与已记录现象

| 子系统 / 问题 | 已记录现象 | 当前判断与边界 |
|---|---|---|
| **JTAG扫描失效** | 目标扫描全零；IR Capture读到`0x00`而非预期的`0x01`；日志出现`dtmcontrol is 0`、目标未被examined | 目标JTAG链没有提供有效响应；这些错误本身不能唯一定位到TDO芯片损坏。 |
| **历史基线与当前差异** | 该样品曾成功返回ID `0x1e200a6f`、识别RISC-V hart，且曾烧录、校验并运行诊断固件；目前相同链路扫描失败 | 说明样品过去建立过调试通路；不能证明当前Flash内容、NVR状态或当前CPU运行状态。 |
| **TDO没有可靠返回** | 扫描时在U5-2和H7-16未观察到可靠的返回脉冲；早期有过测点/示波器设置不确定的波形读数，不作为TDO正常证据 | 当前可确认的是“未观察到可靠TDO返回”，不能据此直接定为PAD或芯片损坏。 |
| **TDO外部路径** | U5-2到H7-16约0.6Ω；H7-16到绿色载板实际插接对应点约0.8Ω | 已测外部线路和插接段低阻导通；不覆盖封胶内绑定、TDO复用和输出使能。 |
| **TCK/TMS/TDI输入** | H7-15/TCK、H7-13/TMS、H7-10/TDI在扫描期间观察到命令相关电平活动；已测底板路径低阻 | 输入活动到达接口测点；没有保存足以逐位确认完整同步时序的波形，也不能证明封胶内PAD实际收到有效信号。 |
| **DAPLink基本收发** | 与目标隔离、实际接通TDI→TDO回环后，10kHz、六种32位图样各重复三次，完整比较18/18通过 | 当前探针基本数字输出和采集在该回环条件下通过；这不等于目标连接时的电气条件、TAP或TDO路径正常。 |
| **扫描频率** | 1kHz、5kHz、50kHz等扫描尝试仍未得到正确ID | 单纯扫描频率不是目前最优先解释；频率测试不能代替复位、模式和PAD输出路径确认。 |
| **PADMUX模式** | H8跳帽可令PADMUX相关测点趋高或趋低；两种档位都未恢复扫描 | 外部高低档已做对照；芯片方未提供真值表，当前无法确认正确JTAG档位及采样时机。 |
| **复位** | 外部RST松开时约3.3V，按SW1可拉至约0V；扫描期间未观察到明确的意外拉低 | 外部复位网络有动作；内部TAP复位树是否释放、RST是否同时复位TAP仍未知。 |
| **电源** | VDD_IO测点约3.28V，示波器观察约3.1–3.3V；H5-5/VDD测点约1.2V | 外部测点有电压；VDD节点的供电角色、内部电源域状态和上电顺序仍需芯片方确认。 |
| **TDO对地电气检查** | 断电电阻约200–300kΩ；二极管档TDO与TMS读数接近 | 未发现明显硬短路；这些静态读数不能证明TDO动态驱动或绑定完好。 |
| **I²C无ACK** | GPIO模拟探测OLED地址`0x3C/0x3D`和MPU地址`0x68/0x69`均未获得有效ACK；系统时钟门控曾由CPU mailbox记录为打开 | I²C尚未跑通。时钟门控打开不等于模块使能、有效事务和从机ACK均正常；不能据此判定芯片I²C控制器损坏。 |
| **UART无banner** | CH340和H4端分别做本地回环可用；交叉连接没有收到有效数据或启动banner | 芯片端TX行为、实际波特率/系统时钟、当前固件是否打印banner、跨设备接收均未形成完整验证。 |
| **软件写入差异** | 调试器直接写部分外设寄存器时，曾出现回读值不符合预期；CPU邮箱写SRAM及历史Flash写入校验曾成功 | 不能据直接`mww`异常推导“芯片整体不可写”；访问路径和CPU执行路径需分开判断。 |


## 3. 软件与外设问题补充

### 3.1 已有的软件执行证据

- 诊断固件曾成功写入并校验；SRAM mailbox出现完成标记`MBOX=0x4D424F58`、`DONE=0x0000600D`，并读回CPU写入的`0xA5A55A5A`和`0x3C3C9696`。
- 这支持诊断程序曾执行至结束并能由CPU写SRAM，不等于当前CPU仍在运行，也不等于UART/I²C已通过。
- 对保留旧版固件的静态审查未发现直接改写PAD6/TDO或主动写JTAG禁用位的代码；但没有当时Flash镜像现场哈希，不能声称磁盘源码与当时烧入镜像逐字节一致。

### 3.2 I²C与UART尚未闭环

- I²C GPIO模拟探测没有ACK；硬件I²C控制器的模块使能、有效事务和从机ACK没有在同一次有效测试中全部确认。
- OLED模块不亮，不能继续作为已知正常的I²C从机对照。
- MPU模块的实际型号、nCS状态、供电、共地和总线波形没有全部形成独立证据。
- UART跨设备通信未通过；“12MHz晶振而波特率按16MHz计算”只是待验证假设，不能作为已确认根因。
## 4. 简短结论

该样品曾成功识别JTAG ID并运行诊断代码，目前目标JTAG扫描返回全零。底板TCK/TMS/TDI有接口活动，TDO未观察到可靠返回；已测外部TDO线路低阻导通，当前DAPLink独立硬件回环18/18通过。PADMUX高低对照和多种扫描速度没有恢复ID。现有证据尚不能区分“模式/复位/使能或TDO复用条件未满足”与“COB内部绑定/芯片故障”。请协助确认该RISC-V版本的JTAG PAD映射、PADMUX条件、TAP复位/使能、TDO输出及调试安全状态判定方法。
