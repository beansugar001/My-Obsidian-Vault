# CY63300 四小时学习路线

## 四小时后的能力

能区分 ARM 旧样例与 tiny_riscv 当前测试工程；能从 C 代码追到外设寄存器和物理引脚；能解释 I2C 地址、START/STOP、ACK、开漏和上拉；面对“跑不通”时能用证据判断问题位于电气侧还是控制器侧。

## 唯一心智模型

`CPU代码 -> 地址映射 -> 外设时钟/复位 -> GPIO复用 -> 开漏与上拉 -> I2C状态机 -> FIFO/状态/中断 -> 物理排针`

学习的全部内容围绕这条链展开。每遇到一个现象，都先问信号走到哪一层、上一层有什么可观察证据。

## 0:00-0:35：建立地图

只读 `01-芯片总览` 的第3、4、7节。掌握五个锚点：Flash 从 `0x00000000` 开始、RAM 从 `0x20000000` 开始、SYS_CTL 为 `0x40021800`、I2C 为 `0x40002800`、当前测试工程是 tiny_riscv。理解地址是 CPU 找到硬件寄存器的门牌号，不背完整地址表。

## 0:35-1:10：读一个好驱动

阅读当前工程 `lib/uart.c`，只追踪“开时钟、软复位、配置 AFR、设置参数、使能、观察输出”的顺序。把这六步迁移为 I2C 驱动骨架。启动汇编只知道它最后进入 `main()` 即可。

## 1:10-2:00：学会 I2C 的最低必要集合

读 `04-I2C排障指南` 第1、2节。必须能解释开漏加上拉、START/STOP、ACK/NACK、7位地址 `0x50` 与线上地址字节 `0xA0` 的区别。寄存器只理解 SYS_CTL 的 `PERI_CLKEN.bit5`、GPIO 的 `AFR1/OSOD`、I2C 的 `MODULE_CTRL/FIFO_STA/I2C_ADDR/I2CM_CTRL/I2C_STA/RAW_INTR_STA`。重点理解 `STOP=0` 为什么会让 SCL 被保持为低。

## 2:00-3:35：一个高收益综合练习

使用 `D:\project\新建文件夹\test\i2c_diag` 做“双通道差分诊断”。GPIO bit-bang 扫描绕开硬件控制器，回答电气连接和从机是否存活；硬件控制器扫描回答寄存器序列是否正确。先不看答案，分别人为制造四类故障：关闭 I2C 时钟门控、把 AFR 配到错误 PAD、令 STOP 为0、把地址从0x50改成0x51。每次只能观察 `d/b/c` 输出、`MODULE_CTRL` 读回、`I2C_STA` 和 `RAW_INTR_STA`，写下故障位于哪一层和下一条验证动作。恢复正确配置后再进入下一轮。

如果暂时没有硬件，就在纸上逐行模拟 `i2c_diag.c`，预测每种故障下 bit-bang 和硬件扫描谁成功；上板时再核对预测。

## 3:35-4:00：闭环表达

不看资料，用三分钟解释“从 `main()` 写 I2C 到 H4 上出现波形”的完整路径，并回答：bit-bang 有 ACK 而硬件控制器无 ACK，为什么可以排除上拉、接线和从机供电？讲不清的那一层，就是最后25分钟唯一需要回看的内容。

## 今天完全忽略

暂不学习 SM2/SM3/SM4、PUF、CJ_ENC/CJ_DEC、NVR 密钥布局、DMA、RTC、看门狗、CoreMark、SPEC、漏洞测试、升级协议、全部寄存器位和完整启动汇编。也不背整张引脚表。需要时查 `03-引脚与封装大全`。ARM Keil I2C 工程只作为已验证行为的参考，不能直接当作当前 tiny_riscv 工程烧录。
