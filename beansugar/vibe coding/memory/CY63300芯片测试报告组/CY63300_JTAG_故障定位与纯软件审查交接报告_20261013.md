# CY63300 RISC-V JTAG 全零故障：阶段性定位与纯软件审查交接报告

**版本**：v1.0  
**截止日期**：2026-10-13  
**用途**：交接给桌面版 ChatGPT / Codex，继续开展原理图、芯片手册、RTL、历史日志和 ELF 的**纯软件静态分析**。  
**当前约束**：用户已明确要求暂停新增硬件测量；本报告**不要求**再次使用万用表、示波器、改跳帽、换芯片或反复执行 OpenOCD。

> **阶段性结论（不是已证实的最终根因）**：两只 DAPLink 曾在连接目标时表现为 TDO 无有效响应；两块 COB 在同一测试环境下均无法正确返回 JTAG IDCODE。当前 DAPLink 的独立 TDI→TDO 回环在真正接线后 18/18 通过，目标外部供电与已验证的多段连接基本正常。当前证据更支持优先排查**共同的蓝色测试板 JTAG 连接／模式条件，以及 CY63300 内部 TAP 复位、使能和 TDO PAD 复用路径**。没有证据可以直接断言“芯片已损坏”“NVR 已锁定”“DAPLink 已损坏”或“CPU 已停止运行”。

## 4. JTAG 实际电气链路与审查边界

```text
计算机 / USB
      │
      ▼
当前 CMSIS-DAP（独立回环：18/18 通过）
      │
      ├── TCK ──► 蓝板 U5-1 ──► H7-15 ──► 绿色载板对应接点 ──► COB 输入
      ├── TMS ──► 蓝板 U5-3 ──► H7-13 ──► 绿色载板对应接点 ──► COB 输入
      ├── TDI ──► 蓝板 U5-5 ──► H10(1-2) ──► H7-10 / PAD0 ──► COB 输入
      ◄── TDO ── 蓝板 U5-2 ◄── H7-16 ◄── 绿色载板对应接点 ◄── COB/PAD6 输出

模式控制：H8-1=VDD_IO；H8-3=GND；H8-2 经板级连接至 PADMUX 网络
外部复位：SW1 控制目标 RST；DAPLink nRESET 未实际连接目标 RST
```

**重要限制**：这里的 H7/H8/H10/U5 命名来自蓝色测试板网表/历史实测。绿色载板必须称为“与蓝板 Hx-y **实际插接对应**的接点”；**不能以绿色载板丝印号码自动推断裸片 PAD 编号**。蓝板网表**不是** COB 键合线设计图。

## 5. 当前最可能故障区域：排序而非定案

| 优先级 | 候选故障区域 | 支持依据 | 与之矛盾／尚不支持的点 | 纯软件应寻找的决定性证据 |
|---|---|---|---|---|
| **P1** | **共用蓝板 JTAG 连接、模式选择或电气条件，尤其 PADMUX/H8、TDI 路由和 TDO 输出选通关联** | 两只 DAPLink、两块 COB 在相同环境下表现相近；探针独立回环有效；目标端全零 | 普通 TDO 插接段已低阻导通，原 COB 多条输入也已有动态波形；不能仅称“导线断了” | 网表逐引脚核对 + PADMUX 控制逻辑；检查是否存在与 JTAG 模式不兼容的默认上下拉、外设复用、输出使能或共享负载 |
| **P1 并列** | **CY63300 内部 TAP 复位／使能／PAD6-TDO 复用路径未满足条件** | DR 全零且 IR Capture `0x00`；输入有活动而输出无有效响应，与未选通或未工作的 TAP 相容 | 没有读到内部状态；缺完整 SoC 顶层与 pad ring/封胶绑定证据 | 建立从外部模式脚→Pad 控制→TAP reset/enable→TDO OE→PAD6 的条件链，找具体失效条件 |
| P2 | 共用电源时序、内部 POR 或 DAPLink 反向偏置的影响 | 曾测到 DAPLink 单独供电造成非零偏置；外部 RST 正常不保证内部复位域正常 | 目标先上电再接探针、完全掉电等已尝试未恢复；缺内部 POR 逻辑与电流路径证据 | 静态检查 reset tree、boot latch、VDDIO/CORE 排序要求和 DAPLink I/O 保护/上下拉路径 |
| P3 | NVR 安全使能使 JTAG 关闭 | 手册确实定义组合禁用条件 | 未测 NVR，旧 ELF 未见相应写入；第一块芯片曾在烧录后仍可 JTAG；第二块初始配置未知 | 静态还原 NVR Boot 装载与禁用逻辑，说明什么条件下两个 COB 会同时表现全零；不得宣称当前 NVR 值 |
| P4 | OpenOCD 普通配置和频率问题 | 早期 cfg 存在先 `init` 后设置速率的实验顺序陷阱；历史 10k/1000k 有差异 | 已在安全 cfg 中真正以 5k/50k 初始化，两者同样全零；IRLen/ID 设置有历史依据 | 仅比较配置与已保存日志；除非发现具体错误，否则停止频率试错 |
| P5 | 两只 DAPLink 均损坏，或两块 COB 独立损坏 | 理论可能 | 当前 DAPLink 已正确回环；两组设备同类故障更使共享因素优先 | 只有新的独立有效证据才提高其优先级；当前不建议新硬件实验 |

**谨慎的总体结论**：目前可以较有把握地把“普通 USB/命令通信失败”“当前探针基本 TDO 输入失效”“外部静态供电缺失”“已测载板 TDO 插接断开”从首要嫌疑中降级；仍**不能分开**“蓝板模式/路由有误”和“芯片内部 TAP/TDO 未启用”。

## 6. 芯片手册和旧固件已知事实（必须与推断分开）

### 6.1 JTAG Disable／NVR

手册描述：在启用 NVR1 装载配置、其 word1 `jtag_disable = 0x12345678`，且 NVR2 解码的 `prot_level > 3` 时，JTAG 可被关闭。手册还说明 NVR2 编码与保护等级的特殊映射；**数值大小与保护强弱不能凭直觉排序**。

- NVR1：`0x00040200–0x000403FF`；word1 的推导地址 `0x00040204`。
- NVR2：`0x00040400–0x000405FF`，含 OTP 相关定义。
- 实际 NVR 内容：**未读出、不可推断**。

手册另提到 `SYSCTRL + 0x28`（据 `0x40021800` 推得 `0x40021828`）JTAG_EN 的特殊两步写入及时序要求（512 个 PCLK 周期），并存在访问权限/可见性限制。**这是手册中的控制机制，不是目前可执行的软件“强制恢复命令”**：当前没有已证实可用的目标总线访问通道，禁止对该地址进行写入尝试。

### 6.2 RISC-V PAD 与参考 RTL

- 设计说明的 RISC-V 表存在 `PAD0 → jtag_tdi`、`PAD3 → jtag_tms`、`PAD6 → jtag_tdo` 等定义；**必须核对具体 AF 列、默认复用、TDO 输出使能及当前裸片版本**。
- 当地 `tinyriscv-master/rtl/debug/jtag_driver.v` 可帮助理解 Capture-IR 低位 `01`、TMS 控制 TAP 状态及 TCK 时序；**该参考 RTL 并未被证明就是实物 CY63300 的完整 SoC 顶层**。
- 对于 JTAG TCK / RISC-V PAD5 与手册中 ARM/SWD 的命名重叠，需要结合**目标变体实际 RTL**核实，不能将 ARM SWCLK 直接当作 RISC-V JTAG TCK 绑定结论。

### 6.3 旧版固件

保留的 3248 字节 ELF 为 RV32IM，旧版 `main` 配置 GPIOB.2/.3（PAD8/PAD9）进行软件 I²C 位扫，并向 SRAM 写入邮箱。静态审计未发现程序直接访问 NVR1/NVR2，未发现 JTAG_EN 禁用相关寄存器写入，也未发现直接关闭 JTAG 的指令。此结果**降低“这个已审计版本主动关闭 JTAG”的嫌疑**，但不能证明当时烧录镜像完全相同，更不能证明芯片当前 NVR/Flash 内容。

此前 GPIO SCL/SDA 未捕获活动只能记为“**无当前 CPU 执行正证据**”，不得用作 CPU 死机的判据；I²C 控制器使能失败、串口互发异常不能未经证据直接合并成同一硬件根因。

## 7. 已经识别的历史记录陷阱——桌面端必须纠正

1. **首轮 18/18 全零回环无效**：当时用户没有实际接回环线，故不能证明 TDO 接收损坏。后续真正接通并验证 0.9Ω 后，18/18 通过，应以**后续结果**判定当前 DAPLink 基本收发能力。
2. **旧“绿色8号到 H7-16 测得 OL”不能当作当前断路证据**：该测点具体对应关系存在疑问；之后原载板正确对应接点约 0.8Ω，新载板约 1.0Ω，均基本导通。
3. **两只 DAPLink 都出现目标 TDO 无响应**：不同探针序列号本身不再是优先怀疑当前探针损坏的理由。
4. **`scan_chain` 列表不是实时重扫**：原 cfg 含 `init`，故 cfg 载入后再改 `adapter_khz` 不构成真正新频率的初始化；已使用 `noinit` 版 cfg 完成 5/50 kHz 对照。
5. **OpenOCD 退出码 0／`Enabled=Y`／列表 `IrCap=0x01` 不是 JTAG 通过**：真实错误日志为 DR all-zero、IR saw `0x00`。
6. **OpenOCD 的 `nRESET=1` 是探针状态，不等于目标 RST 真实采样**；物理上 DAPLink nRESET 未接目标 RST。
7. **第二块 COB 未经历史成功验证**：两块同现象会提高共用环境优先级，但不能据此排除“同批工厂安全配置”或共同设计问题。
8. **TCK“大概 2V”只是回忆**：已看到方波属于事实，实际 Vmax/Vmin 未准确记录，不能直接断言电压幅值异常。
