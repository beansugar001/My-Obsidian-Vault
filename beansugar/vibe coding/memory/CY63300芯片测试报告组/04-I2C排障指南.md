## 1. I2C 两分钟原理（不会协议就没法排障）

I2C 是两根线的同步总线：**SCL 时钟 + SDA 数据**，都要求**开漏输出 + 上拉电阻**（空闲时两根线都被上拉电阻拉成高电平）。

一次标准的"主机写"波形：

```
        START        地址7bit   W  ACK   数据字节   ACK   STOP
SDA  ──╲___╲___╱╲__╱╲__╱╲__╱╲____╱╲__╱╲______╱╲__╱╲___╱╲___╱
           ╲__╱ ...                                  ╲_╱
SCL  ──────╲___╱╲__╱╲__╱╲__╱╲____╱╲__╱╲______╱╲__╱╲___╱╲____
```

三条铁律（排障全靠它们）：
1. **谁拉低谁知道**：任何器件（主机/从机）都只能把线拉低，"拉高"靠电阻。从机没响应 ACK 时 SDA 保持高 → 主机看到 NACK。
2. **START**：SCL 高时 SDA 下跳；**STOP**：SCL 高时 SDA 上跳。数据位只在 SCL 低时允许翻转。
3. **从机可以拉住 SCL 不放**（时钟拉伸 clock stretching）逼主机等——这是 I2C 唯一从机控制流量的手段，也是"总线卡死"最常见的成因。

地址字节 = 7位地址<<1 | 读写位（W=0/R=1）。0x50 的 EEPROM 写操作第一个字节是 0xA0——**但那是总线上跑的字节，配置寄存器里写的仍是 7bit 的 0x50**（前任已确认 CY63300 是"寄存器填 0x50、硬件自己拼 R/W 位"，别手贱左移）。

## 2. CY63300 的 I2C 控制器 10 分钟速成

基址 **0x40002800**（APB5）。这是一个**带 FIFO 的主从一体控制器**。

### 2.1 寄存器地图（全部抄自文档 4.19.1~4.19.20）

| 偏移 | 名 | 关键位域 | 复位值 | 备注 |
|---|---|---|---|---|
| 0x00 | MODULE_CTRL | bit0 **I2C_EN**、bit2 TX_FIFO_EN、bit3 RX_FIFO_EN | 0 | **总开关，复位全关** |
| 0x08 | TX_FIFO（写） | bit9 RESTART、bit8 **R/W_CONTROL(1读0写)**、[7:0]数据 | - | 只写；地址字节也从这个口发 |
| 0x08 | RX_FIFO（读） | [7:0]数据 | - | 同一偏移，读方向 |
| 0x0C | FIFO_STA | bit0 TX_EMPTY、bit1 TX_FULL、bit2 RX_EMPTY、bit3 RX_FULL、[11:8]TX_NUM、[19:16]RX_NUM | TX_EMPTY=1 | 轮询主力 |
| 0x10 | CLK_DIV0 | [23:0] SCL **高**电平拍数 | 0x20 | FSCL=FPCLK/(DIV0+DIV1+**2**) |
| 0x14 | CLK_DIV1 | [23:0] SCL **低**电平拍数 | 0x30 | 默认 16MHz → ≈195kHz |
| 0x20 | I2C_MODE | bit0 MS_MODE：0=从机 1=主机 | **0x1** | 主从互斥 |
| 0x24 | I2C_ADDR | [9:0] 地址（主从共用：主机=目标，从机=自己） | **0x133** | ⚠️复位值是10bit模式残留，7bit模式要覆盖低7位 |
| 0x28 | I2CM_CTRL | bit0 ADDR_MODE(0=7bit/1=10bit)、bit1 **STOP**(0=FIFO空后拉住SCL等续数据/1=发STOP结束)、bit2 HS_MODE、bit3 SBYTE、bit4 GCALL | 0 | ⚠️bit1是第一大坑 |
| 0x2C | I2CM_CODE | [2:0] 高速模式主机码 | 1 | 不用HS不动它 |
| 0x30 | I2CS_CTRL | bit0 GCALL_MODE（1=不响应广播） | 0 | 从机模式用 |
| 0x34 | I2C_FM_DIV | [7:0] Fast-mode divisor | 5 | 主机码/START字节传输用 |
| 0x38 | I2C_HOLD | [7:0] SCL 下降沿后 SDA 保持时间 =(值+1)×Tpclk | 5 | 主从共用 |
| 0x3C | I2C_STA | bit0 I2CM_WORK、bit1 I2CM_DATA、bit8 I2CS_WORK | 0 | WORK=1 表示传输进行中 |
| 0x4C | INTR_CTRL | RX/TX FIFO 阈值 [9:8]/[1:0]（01=4字节…） | 0x1 | 用中断才配 |
| 0x50 | INTR_EN | 各中断源使能（bit13 NACK、bit14 丢仲裁、bit16 AERR…） | 0 | 默认全关 |
| 0x54 | INTR_STA | 屏蔽后的状态 | | |
| 0x58 | RAW_INTR_STA | 原始状态（不受屏蔽影响） | | **排障先读这里** |
| 0x5C | INTR_UNMASK | 0=屏蔽 1=放开 | | |
| 0x60 | INTR_CLR | 写1清对应 RAW 标志 | | WO |

### 2.2 主机发送一次数据的完整软件序列

```c
// 目标：向 7bit 地址 0x50 的器件写两个字节 0x01 0x02
// PCLK = 16MHz，目标 FSCL ≈ 100kHz → DIV0+DIV1 = 158 → 取 DIV0=63, DIV1=95

#define I2C_BASE   0x40002800u
#define SYSCTL     0x40021800u
#define REG32(a)   (*(volatile unsigned int *)(a))

// ① 开时钟（不做这步后面全白搭！）
REG32(SYSCTL + 0x0C) |= (1u << 5);            // PERI_CLKEN.I2C = 1
// ②（可选）软复位 I2C：PERI_RST bit5 写1再写0
REG32(SYSCTL + 0x10) |=  (1u << 5);
REG32(SYSCTL + 0x10) &= ~(1u << 5);

// ③ 配引脚：以 SCL=PAD8(GPIOB2)、SDA=PAD9(GPIOB3) 为例（前任样例的选择）
#define GPIOB 0x40000100u
REG32(GPIOB + 0x04) &= ~((1u<<2)|(1u<<3));    // direction = 输入(开漏下无所谓，输入最安全)
REG32(GPIOB + 0x58) |=  (1u<<2)|(1u<<3);      // osod_type: 开漏使能！
REG32(GPIOB + 0x5C) |=  (1u<<(2+6))|(1u<<(3+6)); // 弱上拉（外部4.7k为准）
REG32(GPIOB + 0x68) = (REG32(GPIOB + 0x68) & ~0xFC) | (3u<<6) | (3u<<9); // AFR1: pad2=3(SCL), pad3=3(SDA)

// ④ I2C 控制器配置
REG32(I2C_BASE + 0x10) = 63;                  // CLK_DIV0 (SCL高)
REG32(I2C_BASE + 0x14) = 95;                  // CLK_DIV1 (SCL低)
REG32(I2C_BASE + 0x24) = 0x50;                // 7bit 从机地址，别左移！
REG32(I2C_BASE + 0x20) = 1;                   // MS_MODE = 主机
REG32(I2C_BASE + 0x28) = 0x1;                 // I2CM_CTRL: ADDR_MODE=0(7bit) | STOP=1
REG32(I2C_BASE + 0x00) = 0x0D;                // MODULE_CTRL: I2C_EN|TX_FIFO_EN|RX_FIFO_EN

// ⑤ 发数：第一个字带 R/W 位控制（0=写），后续是数据
while (!(REG32(I2C_BASE+0x0C) & 0x2)) {}      // 等不是 TX_FULL
REG32(I2C_BASE + 0x08) = (0u<<8) | 0x50;      // 地址字节，R/W_CONTROL=0(写)
while (!(REG32(I2C_BASE+0x0C) & 0x2)) {}
REG32(I2C_BASE + 0x08) = 0x01;                // 数据1
while (!(REG32(I2C_BASE+0x0C) & 0x2)) {}
REG32(I2C_BASE + 0x08) = 0x02;                // 数据2

// ⑥ 等完成：FIFO 空了，且 I2CM_WORK 归零（STOP 发完）
while (!(REG32(I2C_BASE+0x0C) & 0x1)) {}      // TX_EMPTY
while (  (REG32(I2C_BASE+0x3C) & 0x1)) {}     // I2CM_WORK == 0
// ⑦ 检查 NACK：RAW_INTR_STA bit13
if (REG32(I2C_BASE+0x58) & (1u<<13)) {
    REG32(I2C_BASE+0x60) = (1u<<13);          // INTR_CLR 清标志
    // → 从机没应答：查地址/接线/上拉/从机上电
}
```

**主机读**的差别：地址字用 `(1u<<8)|addr`（R/W_CONTROL=1）；等 `RX_NUM>0` 后读 0x08 收数据；读空后确认 RX_EMPTY。**一次传输里 R/W 位只由地址字决定**。

> ⚠️ 上面的序列是**从文档寄存器语义推演的参考实现**，两处需要上机确认：
> (a) 地址字是否真的经 TX_FIFO 发出（bit8/bit9 是否如文档所写有效）；
> (b) STOP 由 I2CM_CTRL 静态位控制，还是每次传输要重新写。
> 若发不出 START，先换"I2CM_CTRL 写 0x3（ADDR_MODE|STOP）再压 FIFO"的顺序试。

### 2.3 分频速查表（PCLK=16MHz）

| 目标 FSCL | DIV0+DIV1 | 推荐组合 (DIV0高/DIV1低) | 实际 |
|---|---|---|---|
| 100 kHz | 158 | 63 / 95 | 100.0k |
| 200 kHz | 78 | 31 / 47 | 200.0k |
| **默认复位值** | 82 | 32 / 48 | **194.8k**（不是100k！） |
| 400 kHz | 38 | 15 / 23 | 400.0k |

改主频后记得重算：FSCL = PCLK / (DIV0+DIV1+2)，PCLK = 主频 / pclk_div。

## 3. 十四条故障清单（按历史命中率排序）

**A. 程序侧（最常见）**

1. **时钟门控没开**——症状：寄存器写不进/读恒0，SCL/SDA 完全没波形。查：`PERI_CLKEN@0x4002180C` bit5；顺带确认 GPIOB 的 `gpio_pclken` bit0 也开了（配 AFR1 前提）。
2. **引脚复用没配或配错脚**——症状：SCL/SDA 无波形或信号出现在"错的脚"上。查：GPIOx `AFR1@0x68` 对应脚的 3bit 值；**并用小编号优先规则反查**：RISCV 版若 PAD0 的 AFR1 被配成 1（I2C_SCL），SCL 一定出在 PAD0，PAD8 怎么配都没用。注意 PAD0 复位功能是 jtag_tdi（RISCV版），如果你刚用 JTAG 烧完录，PAD0/PAD3/PAD6 正被 JTAG 占用——JTAG 会话结束后重新写 AFR1。
3. **推挽没开漏**——症状：主机能发 START 和地址，读数据全 0xFF 或从机 ACK 死活拉不下来；或两器件对顶总线发烫。查：`Gpio_osod_type@0x58` 开漏位 + 外部上拉。前任记忆明确写过："Slave 端这两个脚需按开漏/输入方向及 AF3 配置，不能当普通推挽 GPIO 输出"。
4. **I2CM_CTRL.STOP=0（或没写 I2CM_CTRL）**——症状：发完数据程序卡死在等 WORK=0，示波器看 SCL 被主机拉住不放。原因：STOP=0 时 FIFO 空后 I2CM 拉低 SCL 等你续数据。单次传输 STOP 必须置1。**前任记忆**："Master 发送队列空后应发 STOP 并等 WORK 清零，不要等待 DATA 自动变为 0"。
5. **地址习惯错**——症状：永远 NACK。寄存器里填 7bit 的 0x50；`I2C_ADDR` 复位值 0x133 不覆盖的话发出去的是错误地址。10bit 模式（ADDR_MODE=1）除非从机明确支持否则别碰。
6. **等错标志**——`I2C_STA.I2CM_DATA`（bit1）表示"正在收发数据位"，不是完成标志；完成要看 `I2CM_WORK`（bit0）归零 + FIFO 空。轮询别等错对象。
7. **中断没接对**——RISCV 版 I2C 中断走 `SYS_IRQ_FLAG@0x4002182C` bit3，要同时满足：I2C 的 INTR_EN 使能对应源 + INTR_UNMASK 放开 + `mie.MEIE` + `mstatus.MIE` + trap_handler 分发表注册 ISR。少一环"中断不触发"，但轮询模式可以完全绕开中断——**排障期先用轮询，别一上来开中断**。

**B. 电气侧**

8. **外部上拉缺失/过大**——症状：波形上升沿极缓（RC 充电脸）或根本到不了高电平，高速时全乱。SDA/SCL 各接 4.7k（3.3V 系统标准值；线长/负载大减到 2.2k）。内部弱上拉（pupd_type）只能救急。
9. **SDA/SCL 接反**——症状：有波形但乱码。对照报告03：底板 H4 排针脚8=SCL、脚9=SDA；COB 板焊盘 11/12/13=PAD8/9/10。万用表通断挡从排针一路量到芯片脚。
10. **COB 邦定线接触不良**——症状：时好时坏、温度/按压敏感、某个脚二极管读数异常。用出厂测试法：对 GND 施 -100µA 测各脚压降（应 -0.2~-1.0V 区间），逐脚对比找异常邦定点。
11. **从机没供电/没上电/电压域不匹配**——3.3V 主机对 5V 从机（或反之）都要查。同板共地（AMS1117 地、USB 地、从机地）。

**C. 协议/时序侧**

12. **从机时钟拉伸把总线锁死**——症状：SCL 被拉低回不来。救活姿势：主机侧关 I2C_EN（MODULE_CTRL bit0=0）让主机放手，从机侧软复位（PERI_RST bit5），实在不行整机断电。从机的拉伸时长由文档没写清楚的"FeedBack DELAY"机制控制（目录有标题正文缺）——从机模式排障优先怀疑它。
13. **重复 START / 读前写地址指针**——EEPROM 类器件：先写内部地址指针（写事务），再重复 START 发读。如果 I2CM 的 RESTART 位（TX_FIFO bit9）用法摸不准，就拆成"写事务→STOP→读事务"两次传输，多数器件都接受。
14. **速率超规**——从机只支持 100k 而你跑在默认 195k（复位分频值）上。**上电第一件事：显式写 CLK_DIV0/1，别赌复位值**。

## 4. 示波器排障实操（10分钟定位流程）

设备：双通道示波器 ≥1MSa/s，探头 x1 即可（I2C 边沿慢）。

1. **探头**：CH1=SCL（H4.8 或 COB 焊盘对应点），CH2=SDA（H4.9），地线接 GND。
2. **看空闲电平**：两根线都应是稳定 3.3V 高。哪根低 → 线上有器件拉住（步骤3救活）或无上拉。
3. **跑最小驱动**（上面 2.2 节代码，向空地址 0x00 发一个字节，故意让它 NACK）：
   - **完全没波形** → 程序侧问题：查时钟门控→AFR1→I2C_EN→FIFO 是否压进数据（TX_NUM 应从 1 变 0）。
   - **有 START + 8 个时钟 + 无第 9 个 ACK 时钟** → 地址发完从机没应答，但协议引擎活着：查从机地址/供电/接线。
   - **有 9 个时钟但 SDA 第 9 拍是高** → 正常 NACK（空地址本来就该 NACK）——**这证明主机控制器和引脚全通！** 换真从机地址即可。
   - **有 START 后 SCL 只蹦一两下就停** → 时钟拉伸（从机拉住）或 STOP 语义问题（清单一第4/12条）。
   - **波形歪（上升沿爬坡）** → 上拉问题（清单一第8条）。
4. **用示波器解码**（多数示波器带 I2C 解码）：直接显示地址和数据字节，与预期对比。
5. **扫描全地址**：0x08~0x77 逐个发地址字节记 ACK，两分钟画出总线上活着的器件表。ACK 表非空但目标器件不在 → 地址错；全空 → 电气/从机问题。

## 5. 两套参考实现思路（选一）

- **轮询版**（上面 2.2 的代码）：几十行、无中断依赖、排障期首选。跑通后加超时保护（每处 while 加循环上限，超时退出并返回错误码），防止时钟拉伸卡死整个测试程序。
- **中断版**：注册 ISR 到 `riscv_irq_register(HDURiscv_IRQn_I2C=3, ...)`，在 ISR 里读 RAW_INTR_STA 判断事件（NACK/ RX阈值/ STOP 完成），配合环形缓冲。量产/高吞吐再用；排障期别用。

## 6. 与前任结论的衔接（重要）

来自 2026-09-26 的 Keil 样例调试记忆，可直接复用的结论：
- Master/Slave 样例都用 `I2C_SLAVE_ADDR=0x50`，**实测两端保持 0x50，不要改成左移的 0xA0**。
- Master 用 **PAD8/PAD9（GPIOB2/B3，AF3）**——与本报告引脚表一致（PAD8/9 的 I2C 在复用表第2列，AFR1 值=3）。
- Slave 端可连续接收 0xA5/0x5A——说明从机控制器本身功能是好的。
- 那批样例是 **ARM 版工程（Keil）**；你现在这批材料是 **RISCV 版（GCC+OpenOCD）**。两版 I2C 外设寄存器相同，但**引脚复用表不同**（ARM 版 PAD0 默认 GPIO，RISCV 版 PAD0 默认 jtag_tdi）——移植样例代码时引脚配置段必须按 RISCV 版复用表重写。
