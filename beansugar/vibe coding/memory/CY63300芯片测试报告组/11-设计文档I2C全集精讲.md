## 1. 功能声明（PDF 6，原文照抄+翻译）

> I2C：**支持 master/slave 模式，i2c 时钟分频，7bit/10bit 地址等模式**

人话：一个控制器，两种人格（主机发起读写 / 从机被动应答），二选一；SCL 频率靠分频寄存器调；支持两种地址宽度。就这么多——**文档没有承诺 DMA、没有承诺高速模式细节、没有给任何传输示例**。

## 2. 系统级挂钩（用 I2C 前必查的四个开关）

| 挂钩 | 位置 | 复位值 | 说明 |
|---|---|---|---|
| **时钟门控** | `PERI_CLKEN@0x4002180C` bit5 | **0（关）** | 不开=I2C 寄存器全死。⚡当前板上读数 0x101（bit5=0），SOP 实验①正在验证调试器能否置位 |
| 软复位 | `PERI_RST@0x40021810` bit5 | 0 | 写1再写0=复位 I2C 控制器（bus 卡死自救用） |
| 中断标志 | `SYS_IRQ_FLAG@0x4002182C` bit3 | 0 | **仅 RISCV 版**；轮询此位=知道 I2C 出事了，具体什么事看 4.19 的中断寄存器组 |
| 中断向量 | `HDURiscv_IRQn_I2C=3`（test 工程 riscv_irq.h） | - | 8 源分发表的第 3 号 |
| APB 时钟 | SYSCTL_CR0.pclk_div[1:0] | 0(=1分频) | I2C 挂 APB，FSCL 公式里的 FPCLK=HCLK/pclk_div |

⚡注意：uart_init 只开 bit0+bit8；**开 I2C 时钟的代码目前整个工程里不存在**（前任没写），这是从零要补的第一行。

## 3. 时钟与分频（PDF 118，全文核心公式）

> **FSCL = FPCLK / (CLK_DIV0 + CLK_DIV1 + 2)**
> CLK_DIV0@0x10 管 SCL **高**电平拍数（复位 0x20=32）；CLK_DIV1@0x14 管**低**电平拍数（复位 0x30=48）

- 复位默认：16MHz/(32+48+2)=**194.8kHz**——不是 100k，想跑标准速率必须显式改
- 推荐值（FPCLK=16MHz）：100k→DIV0=63/DIV1=95；200k→31/47；400k→15/23
- DIV0/DIV1 都是 24bit，理论上可分出极低速率；高低拍数分开意味着可以调占空比
- ⚡若板上实际主频不是 16M（12M 晶振假设），这套数全要重算——与 UART 波特率疑点是同一个根源

## 4. 寄存器全集（4.19.1~4.19.20，PDF 117~127 逐个讲）

### 4.1 电源开关组
| 寄存器 | 偏移 | 关键位 | 复位 | 新手注释 |
|---|---|---|---|---|
| MODULE_CTRL | 0x00 | bit0 I2C_EN、bit2 TXFIFO_EN、bit3 RXFIFO_EN、bit1 RESERVED(**复位=1**) | 0x2 | 总闸。⚠️保留位复位值是1，读回 0x2 是正常指纹；**读回 0x0 反而说明时钟没到**（⚡SOP 用它判时钟通断就是这个原理） |

### 4.2 数据通道
| 寄存器 | 偏移 | 位域 | 说明 |
|---|---|---|---|
| TX_FIFO（写） | 0x08 | bit9 **RESTART**、bit8 **R/W_CONTROL**(1读0写)、[7:0]数据 | ⚠️文档只说"I2C 从 FIFO 取数发送"，**地址字节怎么组帧没有明说**——bit8/9 暗示硬件用 I2C_ADDR+这个控制位拼第一字节，但"数据字和地址字怎么区分"未定义，是**文档含糊点 #1**（⚡旧硬件扫描代码就是死在这：没产生 START、把 I2C_ADDR 当目标地址用，结果作废） |
| RX_FIFO（读） | 0x08 | [7:0]数据 | 同偏移异方向 |
| FIFO_STA | 0x0C | bit0 TX_EMPTY(复位=1)、bit1 TX_FULL、bit2 RX_EMPTY(复位=1)、bit3 RX_FULL、[11:8]TX_NUM、[19:16]RX_NUM | 轮询主力；⚠️bit3 的描述原文写"0x0: the TX FIFO is not full"——**复制粘贴错误，实为 RX**，文档笔误点 |

### 4.3 时序组
| 寄存器 | 偏移 | 说明 |
|---|---|---|
| CLK_DIV0/1 | 0x10/0x14 | 见第3节 |
| I2C_FM_DIV | 0x34 | Fast-mode divisor（主机码/START字节传输用），复位 0x5。高速模式细节文档没展开 |
| I2C_HOLD | 0x38 | SCL 下降沿后 SDA 保持时间 =(值+1)×Tpclk，复位 0x5，主从共用 |

### 4.4 模式与地址
| 寄存器 | 偏移 | 关键位 | 新手注释 |
|---|---|---|---|
| I2C_MODE | 0x20 | bit0 MS_MODE：0=从机/1=主机 | **复位值=1（主机）**；主从互斥 |
| I2C_ADDR | 0x24 | [9:0] | 原文："Both I2CM and I2CS use this register as **I2CS address**"——字面意思是**从机自己的地址**；主机模式的"目标地址"放哪？⚠️**文档含糊点 #2**（若主机也用它当目标，则每扫一个地址要改写一次；若不是，主机寻址机制 entirely 未定义）。另注：**复位值 0x133 是 10bit 模式残留**；7bit 模式下 bit6:3 全1111或全0000 是保留地址会触发 AERR |
| I2CM_CTRL | 0x28 | bit0 ADDR_MODE(0=7bit/1=10bit)、bit1 **STOP**、bit2 HS_MODE、bit3 SBYTE、bit4 GCALL | **STOP 语义（易错冠军）**：0=FIFO 空后 I2CM **拉住 SCL 不放**（等续数据）；1=FIFO 空即发 STOP 结束。单笔传输必须置1。⚠️**START 如何产生文档只字未提**——推测压入第一个 TX_FIFO 字即触发起始，但无原文支撑，**含糊点 #3** |
| I2CM_CODE | 0x2C | [2:0] MCODE 主机码 | 高速模式用，复位 0x1 |
| I2CS_CTRL | 0x30 | bit0 GCALL_MODE(1=不响应广播) | 从机专用 |

### 4.5 状态与中断四件套
| 寄存器 | 偏移 | 关键位 | 注释 |
|---|---|---|---|
| I2C_STA | 0x3C | bit0 I2CM_WORK、bit1 I2CM_DATA、bit8 I2CS_WORK | WORK=传输进行中；**完成判据=TX_EMPTY 且 !WORK**（⚡旧代码等 DATA 变 0 是错的，前任 Keil 笔记也验证过这点） |
| INTR_CTRL | 0x4C | RX/TX FIFO 阈值 [9:8]/[1:0]，TH_MODE bit16 | 01=4字节…11=12字节 |
| INTR_EN / INTR_STA / RAW_INTR_STA / INTR_UNMASK / INTR_CLR | 0x50/0x54/0x58/0x5C/0x60 | 19 个中断源 | 五级体系（使能/屏蔽后状态/原始状态/屏蔽控制/清零）。**排障先读 RAW(0x58)**：bit13 NACK、bit14 丢仲裁、bit15 广播、bit16 AERR、bit12 STOP 完成、bit9/8 RX 写/读溢出、bit4/3 TX 写/读溢出、bit7/6 RX 满/空、bit2/1 TX 满/空、bit5/0 阈值 |

### 4.6 目录里有但正文没有的
- **"4.4.2 I2C FeedBack DELAY 说明"**——目录列了，正文整节缺失。从标题推测是从机模式的时钟拉伸（stretch）时长控制机制，**从机会把 SCL 拉多久、能否配置，全部未知**。⚡这意味着：如果哪天总线被从机拉死，文档帮不了你，只能看 RTL 或实测。

## 5. ★引脚复用与 (i)/(io) 标记——本次核对的最大发现★

两版复用表（ARM/RISCV）的 I2C 标记**完全一致**，逐脚核对结果：

| Pad | SCL 标记 | SDA 标记 | AFR1值(SCL/SDA) | 主机SCL可用？ |
|---|---|---|---|---|
| Pad0 | **(i) 输入** | | 1 / — | ❌ |
| Pad1 | | (io) 双向 | — / 0 | SDA可 |
| Pad4 | **(i)** | | 1 / — | ❌ |
| Pad5 | | (io) | — / 1 | SDA可 |
| Pad6 | **(i)** | | 2 / — | ❌ |
| Pad7 | | (io) | — / 2 | SDA可 |
| **Pad8** | **(io) 双向** | | **3** / — | ✅ **唯一** |
| Pad9 | | (io) | — / 3 | SDA可 |
| Pad10~14 | **(i)** | | 3 / — | ❌ |
| Pad11/13/15 | | (io) | — / 3 | SDA可 |

**结论：14 个 I2C 候选脚里，能驱动 SCL 的只有 Pad8 一个。**
- **主机模式 = SCL 必须在 Pad8**（AFR1 值 3），SDA 可配任意 SDA 脚（Pad9=3 是天然配对）
- (i) 的 SCL 脚只适合**从机模式**（时钟输入）或监听外部主机
- ⚡这解释了为什么前任 Keil 样例（ARM 版）用 PAD8/PAD9 且只有它们被验证过——不是随手选的，是**唯一解**
- ⚡i2c_diag 引脚组 0（SCL=PAD8/SDA=PAD9）与硬件约束一致，是正确的默认；**引脚组 1（SCL=PAD0）在这个硬件上永远发不出主机时钟**——它只能用于验证"PAD0 作为 SCL 输入"的场景，不要再对它抱主机模式的期望
- 若从机模式：SDA+任一 (i) SCL 即可，配置自由度大

## 6. 文档含糊/缺失清单（排障时别指望文档的地方）

| # | 问题 | 影响 | 当前对策 |
|---|---|---|---|
| 1 | TX_FIFO 的地址字/RW位/RESTART 如何组帧未定义 | 硬件主机收发序列写不唯一 | 软件位扫先行；硬件扫按"两种解释都试" |
| 2 | 主机目标地址存放位置未明说（I2C_ADDR 字面是 I2CS 地址） | 扫描程序每个地址要改写谁不确定 | 同上；实测对照 |
| 3 | START 产生机制无描述 | 无法从文档确认扫描序列正确性 | 观察 RAW_INTR_STA 的 STOP/仲裁位反推 |
| 4 | FeedBack DELAY 整节缺失 | 从机时钟拉伸行为未知 | 遇总线拉死先软复位 PERI_RST.bit5 |
| 5 | FIFO_STA bit3 描述复制粘贴错误（写成 TX） | 阅读误导 | 按 RX 理解 |
| 6 | 无任何时序图/示例代码 | 新手无参照 | 用本报告组 04 的参考驱动 |

## 7. 自测五题（答不上就回对应节）

1. 上电后 I2C 寄存器读全 0，两个可能原因哪个概率大：控制器坏了还是某开关没开？（→§2，0x4002180C.bit5；顺带 MODULE_CTRL 保留位指纹 0x2 可判时钟通断）
2. 16MHz 下默认分频的 SCL 是多少？怎么改成标准 100k？（→§3，194.8k；63/95）
3. 想把主机 SCL 放 Pad14 行不行？（→§5，不行，Pad14 的 SCL 是纯输入，全芯片只有 Pad8 能驱动 SCL）
4. I2CM_CTRL.STOP=0 时发送完 FIFO 会发生什么？（→§4.4，拉住 SCL 等续数据，表现为总线卡死）
5. 传输完成的正确判据？（→§4.5，TX_EMPTY=1 且 I2CM_WORK=0；不是等 DATA 位）
