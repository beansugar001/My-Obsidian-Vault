# 10 · 外设写入对照实验 SOP（SYSCTL 时钟使能 vs SRAM 对照组）

> 日期：2026-09-28。目的：用两组对照实验回答"PERI_CLKEN.bit5（I2C 时钟使能）到底能不能写"。
> 执行环境：OpenOCD 0.10.0+dev-00914（tinyriscv 版）、10 kHz JTAG、telnet 4444。
> 背景结论（来自 RTL 审查，见 notes.md）：DM 的 SBA 通道 `sberror/sbbusy` 未实现、SBDATA0 写只产生一拍 we 脉冲，**写丢失是无声的**；本实验改用 OpenOCD 标准 `mww/mdw`（halt 后经标准调试路径），绕开手搓 DMI 的不确定性。

## 实验前置状态

- 板子 Type-C 供电、DAPLink 接 U5、H8-1/2 短接、跳线保持当前已验证可连状态
- 当前固件：i2c_diag.bin（Flash 0x0 已 verify）
- OpenOCD 已识别 TAP 0x1e200a6f 后再开始

---

## 实验①：SYSCTL 时钟使能寄存器（0x4002180C）

```tcl
reset run
sleep 1000
halt
mdw 0x4002180C 1          ;# 记录基线（预期 0x101 = GPIO|UART，固件 uart_init 所写）
mww 0x4002180C 0x00000121 ;# 置位 bit5（I2C 时钟使能）
sleep 200                 ;# 排除回读竞态
mdw 04002180C 1           ;# ★手敲时注意：0x4002180C
```

**读回 0x121 的正确解读（收紧后）**：证明**这一次**对该寄存器的写入+读回成功、bit5 读为 1。**不**等于 I2C 时钟已实际送达控制器、控制器可工作。后续还要：
1. `mdw 0x40021810 1` 查 PERI_RST——确认 bit5（I2C 软复位）为 0（未处于复位）；若为 1，写 0 解除后再验。
2. `mdw 0x40002800 1` 读 I2C MODULE_CTRL——时钟真送达的话，读回不再恒 0（至少保留位按文档有非零默认，如 bit1 RESERVED=0x1，即 0x2）。
3. 引脚级观察（无示波器条件下的替代）：`mdw 0x40000150` 读 GPIOB input，只能验证静态电平；**波形级验证必须靠后续 RAM 邮箱固件或逻辑分析仪**，不要用静态读数宣称"I2C 工作正常"。

**读回仍是 0x101 的正确解读**：本次写入未体现到读回值，**不能**立刻锁定为安全保护或芯片异常——先做实验②。

## 实验②：SRAM 对照组（地址已用 map 文件验证安全）

**地址安全性依据（i2c_diag.map 实测）**：
- `.data`=0 字节；`.bss`=0x34 字节（0x20000000~0x20000034，g_irq_vector 等）；`_end=0x20000038`
- 堆区 0x20000038~0x2001C000，栈区 0x2001C000~0x20020000（栈从 0x20020000 向下生长）
- **本构建未链接 sbrk.c，无任何动态分配** → 堆区全程无人触碰
- 选定划痕地址：**0x20008000**（堆区正中，距 .bss 上界 32KB-56B，距栈底 56KB）

```tcl
;# 前提：仍处于实验①的 halt 状态（或重新 halt）
mdw 0x20008000 1          ;# A0 = 旧值，记录
mww 0x20008000 0xA5A55A5A
sleep 200
mdw 0x20008000 1          ;# R1
mww 0x20008000 0x3C3C9696 ;# 写第二个不同值，排除"碰巧原值相同"
sleep 200
mdw 0x20008000 1          ;# R2
mww 0x20008000 0xA5A55A5A ;# 恢复（写回 A0 更好：mww 0x20008000 <A0>）
mdw 0x20008000 1          ;# 确认恢复
```

判据：R1=0xA5A55A5A 且 R2=0x3C3C9696 → SRAM 写读路径正常。

**失败时的排除顺序（先于下结论）**：地址是否落在 RAM 映射内（已由 map 证实）→ OpenOCD 目标状态是否正常（halt 是否成功、JTAG 是否还连着）→ 换一个同样安全的地址（如 0x20010000）复测一次。SRAM 对照失败是"调试写通道可能有问题"的**强证据**，但单凭它不定罪，须完成上述排除。

## 结果解释矩阵

| 结果 | 结论边界 | 下一步 |
|---|---|---|
| SYSCTL 读回 0x121 | 本次写+读回成功，bit5=1；不证明时钟已到控制器 | 查 PERI_RST bit5 → 读 0x40002800 是否脱离恒 0 → 引脚/邮箱级验证 |
| SRAM 对照成功 + SYSCTL 仍 0x101 | 指向 SYSCTL **该寄存器**的访问限制/写入语义/权限问题 | 核对手册复位域（该寄存器是否上电复位专用、写是否需先解锁）；对照 ANA_TRIM 里 jtag_disable 是否为 0x12345678（若被意外置位且保护等级>3，调试写会被拒） |
| 有效的 SRAM 对照也失败 | 指向 OpenOCD 目标状态 / 系统总线写通路 | 换 xpack OpenOCD 0.12 复测（cfg 需适配）；仍失败则整理证据联系旗捷 |

## 后续方案：RAM 邮箱固件（需另行授权）

用途：彻底绕开调试写通道与 UART——固件自己完成开时钟/位扫，结果写进约定 SRAM 邮箱（如 0x2000F000），调试器只 `mdw` 读（读路径是全链路唯一已被反复验证的部分）。
前提：需要烧录 Flash（**持久写入，执行前须用户明确确认**）。i2c_diag 已在板上，其实验①+②结果将决定是否走到这一步。

## 纪律（沿用 + 新增）

- 不擦 Flash、不写 Flash，除非用户明确授权
- 每次 mww 后 sleep ≥200 拍再读回；每次实验记录完整 telnet 会话日志
- 一次只改一个变量；两组实验间不复位、不重新上电（保持通道状态可比）
- 结论措辞遵守本 SOP 的"结论边界"列，不过度解读
