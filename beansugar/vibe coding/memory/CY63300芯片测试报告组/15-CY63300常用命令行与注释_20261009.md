# 15 · CY63300 常用命令行与注释

日期：2026-10-09（Asia/Shanghai）
用途：整理此前实际使用的 PowerShell/OpenOCD 命令，注明作用、前提与局限。
当前优先：USB 探针检查 → 只读 JTAG 识别 → 日志/邮箱/备份。仪器操作见第 14 份清单。
本次仅编写文档，没有执行这里的目标操作，也没有烧录。

## 1. 命令环境和通用规则

- 工具目录：D:\project\tools\tinyriscv-master\tools\openocd。
- 固件目录：D:\project\新建文件夹\test\i2c_diag。
- OpenOCD 版本：0.10.0+dev-00914-g4cb81306a-dirty。
- tinyriscv_10k.cfg：10 kHz；tinyriscv.cfg：1000 kHz。两份配置都在末尾执行 init、halt。
- 以下带 Set-Location 的块在 PowerShell 执行；标成 Tcl 的块只在已连接的 OpenOCD telnet 中执行。
- 每个 OpenOCD 命令都由独立 -c 参数传入。文件路径在 OpenOCD 内优先使用正斜杠。
- PowerShell 用反引号续行，反引号后不能有空格。为减少复制错误，大多数示例使用完整单行。
- 包含 Tcl 的 $old_clk(0) 等变量时，PowerShell 外层用单引号，避免 PowerShell 先展开它。
- shutdown 关闭 OpenOCD 服务，不给目标板断电，也不自动 resume CPU。
- sleep 的单位是毫秒；CPU 已 halt 时 sleep 1000 只让调试器等待，不运行固件。
- 只读内存与识别命令仍可能通过 cfg 暂停 CPU。“不改 Flash”不等于“完全不改变运行状态”。
- OpenOCD 报错、退出码或 SBCS 状态位不能代替具体读回/校验/波形证据。
- 第 10–12 节会改变目标状态或寄存器，先看前提；第 13 节烧录条目是历史参考，不是当前默认操作。

| 常用命令 | 含义 |
|---|---|
| targets | 查看目标和状态 |
| halt | 请求暂停 CPU |
| resume | 从当前 PC 继续 |
| resume 0 | 从地址 0 请求执行；不是复位，也不是重新烧录 |
| reset run | 请求复位并运行，涉及复位接线及配置 |
| reg pc | 读调试器提供的 PC；此目标曾有不可靠读数 |
| mdw 地址 N | 读 N 个 32 位字，N 不是字节数 |
| mww 地址 值 | 写一个 32 位字；寄存器可能有副作用 |
| mem2array 名称 32 地址 N | 将读取的字存入当前 Tcl 会话数组 |
| dump_image 文件 地址 字节数 | 从目标读数据并保存为本地文件 |
| verify_image 文件 地址 bin | 将本地镜像与目标读回比较，不负责写入/擦除 |
| load_image 文件 地址 bin | 向目标写数据；地址 0 是本项目 Flash，属于持久写入 |

## 2. USB 探针与占用检查

Windows PnP 名称只用于辅助定位；探针可能显示为通用 USB/HID。此前过滤“DAP”会匹配 Adapter，网络适配器结果不代表发现了调试探针。

~~~powershell
# 更精确地筛选调试器名称；没有结果也不能单独证明 USB 未枚举。
Get-PnpDevice -PresentOnly |
  Where-Object { $_.FriendlyName -match 'CMSIS|DAPLink|ST.?Link|J.?Link' } |
  Format-Table Status, Class, FriendlyName, InstanceId -Wrap -AutoSize
~~~

~~~powershell
# 列出 USB/HID 实例，插拔探针前后对比新增或消失项。
Get-PnpDevice -PresentOnly |
  Where-Object { $_.InstanceId -match '^(USB|HID)\\' } |
  Format-Table Status, Class, FriendlyName, InstanceId -Wrap -AutoSize

# 查看是否已有 OpenOCD 进程。关闭时优先在其窗口 Ctrl+C。
Get-Process -Name openocd -ErrorAction SilentlyContinue |
  Select-Object Id, ProcessName, Path
~~~

- unable to find CMSIS-DAP device：OpenOCD 未取得探针；先查 USB、驱动、占用和探针类型。
- Interface ready 后 all zeroes：探针已启动，目标扫描未得到有效回应；查目标电源、模式、复位和 JTAG 实际信号。

## 5. 查看寄存器与 PC：只在目标已识别后

~~~powershell
Set-Location 'D:\project\tools\tinyriscv-master\tools\openocd'

# 不写寄存器；halt 只改变 CPU 执行状态。
.\openocd.exe -f .\tinyriscv_10k.cfg -c "halt" -c "targets" -c "reg pc" -c "mdw 0x4002180C 1" -c "mdw 0x40021810 1" -c "shutdown"
~~~

0x4002180C 是时钟门控，bit5 为 I²C；0x40021810 是外设软复位，bit5 为 I²C。
历史 PC=0 不能单独证明程序没运行，需结合 fresh mailbox 与波形。

~~~powershell
Set-Location 'D:\project\tools\tinyriscv-master\tools\openocd'

# 定点读取 I²C 配置/状态；这些读数需结合时钟和复位状态。
.\openocd.exe -f .\tinyriscv_10k.cfg -c "mdw 0x40002800 1" -c "mdw 0x40002810 1" -c "mdw 0x40002814 1" -c "mdw 0x40002820 1" -c "mdw 0x40002824 1" -c "mdw 0x40002828 1" -c "mdw 0x4000280C 1" -c "mdw 0x4000283C 1" -c "mdw 0x40002858 1" -c "shutdown"
~~~

| 地址 | 含义 |
|---|---|
| 0x40002800 | MODULE_CTRL；bit0/2/3 为模块/TX FIFO/RX FIFO 使能 |
| 0x40002810、14 | SCL 高/低分频 |
| 0x40002820 | 主从模式 |
| 0x40002824 | I2C_ADDR；主机寻址用法仍需核实，读数不证明事务正确 |
| 0x40002828 | 主机控制 |
| 0x4000280C | FIFO 状态 |
| 0x4000283C | 控制器状态 |
| 0x40002858 | 原始中断状态 |

不要直接把 I²C 整个寄存器区连续 mdw：偏移 0x08 的读操作是 RX_FIFO，可能弹出收到的数据。配置/状态为 0 也不自动证明损坏。

## 7. 读取 SRAM 邮箱：摘要与完整版

~~~powershell
Set-Location 'D:\project\tools\tinyriscv-master\tools\openocd'

# 18 个 32 位字，即 72 字节；只读取现有结果，没有启动新测试。
.\openocd.exe -f .\tinyriscv_10k.cfg -c "halt" -c "mdw 0x2000F000 18" -c "shutdown"
~~~

~~~powershell
Set-Location 'D:\project\tools\tinyriscv-master\tools\openocd'

# 最新磁盘源码定义到索引 183，所以读 184 字覆盖整版布局。
# 芯片实际运行的版本必须先确认；旧版本并不定义所有这些字。
.\openocd.exe -f .\tinyriscv_10k.cfg -c "halt" -c "mdw 0x2000F000 184" -c "shutdown"
~~~

索引地址＝0x2000F000＋4×索引。184 字是 736 字节（0x2E0）。

| 索引 | 最新源码含义 |
|---|---|
| 0 / 1 | MBOX=0x4D424F58 / DONE=0x600D |
| 2 / 3 | 时钟门控前/后 |
| 4 / 5 | 复位寄存器前/后 |
| 6 | 释放态 SCL/SDA；bit0=SCL，bit1=SDA |
| 7 / 8 | 0x68/0x69 探测；0=ACK、1=NACK、2=总线卡死 |
| 9–15 | MODULE_CTRL、DIV0、DIV1、MODE、FIFO_STA、I2C_STA、RAW_INTR_STA |
| 16 / 17 | 早期版测试图样；最新 main 未重新写，不算 fresh 证据 |
| 18–57 / 58–97 | 两个地址的轨迹区 |
| 98 / 99 | 有效轨迹条数 |
| 100–130 | GPIO 自检 |
| 131–151 / 152–170 | 关闭/开启内部上拉后的样本 |
| 171–174 / 175–178 | 两次地址探测 ACK 拍的 DIR/IN/raw/PUPD |
| 179–183 | nCS GPIO 的 AFR1/OUT/DIR/OSOD/PUPD |

历史 mdw 100、179、191 个字是不同版本的读取长度。191 对最新源码多读了 7 个未定义字；旧版本读超过布局可能只是 SRAM 残留。
MBOX/DONE 不带版本号，也可能跨复位留存，需与本次启动和代码对应。早期 MODULE_CTRL=0x0F 是历史证据，后续 m[9]=0xFE 未被对应固件写入，不是模块使能读回。

## 9. Flash 备份：4 KB 与全片

以下为读取目标、写本地备份文件。时间戳避免覆盖旧备份。目录必须已存在，目标先稳定识别。读取期间 halt 防止应用自行改 Flash。

~~~powershell
Set-Location 'D:\project\tools\tinyriscv-master\tools\openocd'

# 本次 3772 字节镜像涉及前 4 KB；4096 是字节数。
$flashBackupPath = 'D:/project/新建文件夹/test/i2c_diag/flash_backup_' + (Get-Date -Format 'yyyyMMdd_HHmmss') + '.bin'
.\openocd.exe -f .\tinyriscv_10k.cfg -c "halt" -c "dump_image $flashBackupPath 0x0 0x1000" -c "shutdown"

# 文件存在和 4096 字节只是必要条件，还要看日志及下方校验。
Get-Item -LiteralPath $flashBackupPath | Select-Object FullName, Length
Get-FileHash -LiteralPath $flashBackupPath -Algorithm SHA256

# 与同一区域重新读回比较；仍然不写目标。
.\openocd.exe -f .\tinyriscv_10k.cfg -c "halt" -c "verify_image $flashBackupPath 0x0 bin" -c "shutdown"
~~~

若上一步报错，停止，不凭已经存在的旧同名文件认定备份成功。随机时戳、新建文件和 verify 有助于排除旧文件/部分文件。

~~~powershell
Set-Location 'D:\project\tools\tinyriscv-master\tools\openocd'

# 历史全片备份范围 0x40000=262144 字节，低速 JTAG 会很慢。
$fullBackupPath = 'D:/project/新建文件夹/test/i2c_diag/flash_full_' + (Get-Date -Format 'yyyyMMdd_HHmmss') + '.bin'
.\openocd.exe -f .\tinyriscv_10k.cfg -c "halt" -c "dump_image $fullBackupPath 0x0 0x40000" -c "shutdown"
Get-Item -LiteralPath $fullBackupPath | Select-Object FullName, Length
~~~

4 KB 只保护前 4 KB，不能支撑随后全片擦除。全片备份范围来自此前主 Flash 映射，不包含另行映射的 NVR。提速应先在相同连接状态下验证链路，不以跳过备份代替。

## 10. 请求执行与历史复位命令（改变运行状态）

前提：目标能识别、芯片内程序已确认、地址 0 是对应程序入口。先启动示波器 Single，再运行。

~~~powershell
Set-Location 'D:\project\tools\tinyriscv-master\tools\openocd'

# cfg 先 halt；resume 0 请求从地址 0 执行，等待后再 halt 读取。
# 它不是硬件复位，外设状态可能保留；以实际波形和 fresh stage 判断是否成功。
.\openocd.exe -f .\tinyriscv_10k.cfg -c "resume 0" -c "sleep 1000" -c "halt" -c "mdw 0x2000F000 184" -c "shutdown"
~~~

执行是否成功不能只看 PC 或旧 DONE。若程序有更长等待，1 秒可能不足，以波形/阶段和源码估计调整，不能默认等待越长就越可靠。

~~~powershell
Set-Location 'D:\project\tools\tinyriscv-master\tools\openocd'

# 历史复位测试，会改变整个目标状态；此前 reset run 曾导致扫描全零。
# 不把它作为当前 JTAG 恢复第一步。
.\openocd.exe -f .\tinyriscv_10k.cfg -c "reset run" -c "sleep 1000" -c "halt" -c "mdw 0x40003C08 1" -c "resume" -c "shutdown"
~~~

另一种捕获方法是退出 OpenOCD、仪器先 Single、再用板载复位/上电启动已确认程序，之后再连接并读结果。启动档位需已确认；不要在带电时换跳线。

## 11. SYSCTRL 历史写入对照（会写寄存器）

当前已有 CPU 邮箱门控证据，JTAG 尚未稳定时不优先重复。这里保留用于学习命令和必要的后续对照，不作为“无副作用读操作”。

~~~powershell
Set-Location 'D:\project\tools\tinyriscv-master\tools\openocd'

# Tcl 变量相关的 -c 内容用 PowerShell 单引号，避免 $old_clk 被提前展开。
# 保存原值，只置 bit5，读回，再恢复原值。中途故障可能阻止恢复。
.\openocd.exe -f .\tinyriscv_10k.cfg -c "halt" -c "mem2array old_clk 32 0x4002180C 1" -c "mdw 0x4002180C 1" -c 'mww 0x4002180C [expr {$old_clk(0) | 0x20}]' -c "sleep 200" -c "mdw 0x4002180C 1" -c 'mww 0x4002180C $old_clk(0)' -c "mdw 0x4002180C 1" -c "shutdown"
~~~

0x101→0x121 只证明本次 bit5 写入体现到读回。基线也可能是 0x00080021，不能硬套 0x101。恢复时关闭 I²C 时钟也可能影响应用，执行前确认当前测试目的。
mem2array 数组只属于当前 OpenOCD 会话；退出后不能在新进程里使用同名变量恢复。

### SRAM 两图样对照（写 RAM，条件性使用）

先重新核对“芯片正在运行的版本”的 map/堆栈和动态分配。本次磁盘 map .bss=0xB8、_end=0x200000B8、栈从 0x2001C000 起；旧 .bss=0x34 的结论不能推广到所有版本。
0x20008000 是此前选定地址，不是永远安全的固定空闲地址。不要使用 mailbox 0x2000F000 作为划痕测试位置。

~~~powershell
Set-Location 'D:\project\tools\tinyriscv-master\tools\openocd'

# 在已确认 0x20008000 未使用、目标 halt 成功时运行。
# 写两个不同图样，读回后恢复旧值；最后确认恢复。出错时人工处理恢复。
.\openocd.exe -f .\tinyriscv_10k.cfg -c "halt" -c "mem2array old_sram 32 0x20008000 1" -c "mdw 0x20008000 1" -c "mww 0x20008000 0xA5A55A5A" -c "sleep 200" -c "mdw 0x20008000 1" -c "mww 0x20008000 0x3C3C9696" -c "sleep 200" -c "mdw 0x20008000 1" -c 'mww 0x20008000 $old_sram(0)' -c "mdw 0x20008000 1" -c "shutdown"
~~~

两个图样均匹配才说明本轮该地址写读成功；同一值写后读到相同值无法排除碰巧与旧值相同。

## 12. 手工 DMI：历史接口与限制

~~~powershell
Set-Location 'D:\project\tools\tinyriscv-master\tools\openocd'

# 只读取 SBCS 状态，不发起新的目标地址读事务。
.\openocd.exe -f .\tinyriscv_10k.cfg -c "riscv dmi_read 0x38" -c "shutdown"
~~~

历史上还使用 riscv set_prefer_sba on、dmi_write 配置 SBCS/SBADDRESS/SBDATA，再读 SBDATA0。
本地参考 RTL 的 SBCS 状态实现不完整，sberror/sbbusy 为 0 不构成成功证据；本地 RTL 与实物是否完全同版也有局限。
单独 dmi_read 0x3C 可能读到此前地址的残留数据，不能把它当成新指定地址的结果。
当前不再把手工 DMI 写流程当作优先测试；标准读回、CPU mailbox 与实际波形更有价值。

## 13. 历史烧录相关命令（仅注释留档）

项目 AGENTS.md 规定 Flash 写入/擦除须明确确认；本次请求是写文档，未执行烧录。
当前先恢复 JTAG、核对镜像并备份，烧录需另外形成具体 SOP。以下命令全部以 # 注释，单独复制也不会执行：

~~~powershell
# Set-Location 'D:\project\新建文件夹\test\i2c_diag'
# .\flash.bat i2c_diag.bin
# 历史脚本内含 Flash 擦除模式、触发写和 load_image，不是只读检查。

# load_image D:/project/新建文件夹/test/i2c_diag/i2c_diag.bin 0x0 bin
~~~

## 14. 最常用的短顺序

1. PowerShell USB/HID 枚举，确认探针被电脑识别。
2. 10 kHz：targets → shutdown，并同时捕获 TCK/TDO。
3. 稳定识别后：读邮箱摘要、SYSCTRL 状态，保存日志。
4. halt → dump_image 前 4 KB → 本地大小/哈希 → verify_image 备份。
5. 确认芯片内固件版本，再按示波器 Single → 明确启动 → fresh mailbox 的顺序测 I²C。
6. 系统恢复后才考虑寄存器写对照与固件变更。
