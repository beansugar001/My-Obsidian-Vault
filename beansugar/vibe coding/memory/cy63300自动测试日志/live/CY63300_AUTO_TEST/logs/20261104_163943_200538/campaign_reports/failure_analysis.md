# 故障候选与证据边界

| 候选 | 支持证据 | 反证或限制 | 当前判断 | 信息增量最高的下一项 |
|---|---|---|---|---|
| SBA请求在仲裁中丢失、过早SUCCESS | 历史多种寄存器写失败且SBCS无错；参考原版CPU/UART竞争时0提交却SUCCESS，延迟也无用 | 未取得ASIC实现；CPU在历史实验已Halt，仍需确认其它主设备；原版缺陷不证明本芯片同因 | 参考RTL层高置信，实芯片层未定 | 索取ASIC SBA→互联真实提交反馈及活动主设备信息；预检通过后才考虑单次DIV0写 |
| V5.7增加的纯SBCS读取消待写 | V4.4与V5.7在SBDATA写之后确有此顺序差异 | 标准纯读无此副作用；参考DM无取消分支；控制竞争下立即读与延迟读结果相同 | 未获仿真支持，保留未知ASIC假设 | 先检查ASIC实现；实测需两个各自授权的阶段，不能在本轮自动A/B重写 |
| 写SBCS切换模式或读SBDATA过早 | 两历史读辅助函数写地址后立即取SBDATA，busy检查在后；参考没有真实busy反馈 | 不能证明历史每笔读当时未完成；V4.4也用同样辅助函数 | 可信的协议/观测风险，非定论 | 审核ASIC sbcs/busy，实现地址触发后先确认完成，再取数 |
| I²C寄存器内部写条件、时钟、复位 | 历史CTRL置位成功但清零失败；后续分频/CTRL也失效；PERI_RST曾释放失败 | 最新历史复位0/时钟20/default fingerprint只表明寄存器视图；本轮未读目标MMIO | 中等关注，机制未知 | 公司提供真实I²C寄存器/时钟/复位逻辑或受控内部CPU读写对照；本轮不执行代码 |
| grant被误当目标接受 | 参考候选在目标人工拒收时0提交却SUCCESS | 人工门控不是芯片时钟逻辑；真实桥接口未知 | 候选适用范围缺口已经复现 | 在候选桥接ready/error设计中加入目标接受确认，再做延迟/错误/超时测试 |
| 连续请求期间响应丢失 | 新用例109：候选2提交1响应；原版0提交2响应 | 压力测试在第一响应完成前发第二笔；未证明普通OpenOCD会产生此流量，也未跑真实DTM | 候选全握手支持FAIL，非芯片根因定论 | 离线修复rx/tx占用与应答顺序、地址数据保持，再集成真实DTM |
| 调试读通路/CSR不稳定 | V4.4 misa=4C80480A，V5.7=FFFFFFFF，本次=4C80680A | ID/DMSTATUS正确不能证明CSR全通路正确；历史芯片与内部实现需核对 | 独立异常仍未解释 | 索取公司misa期望与CSR路径；使用另行审核的只读诊断，不能忽略全1值后写入 |
| 本轮框架解析误判 | 初始化capture输出后echo重复，ID出现两次，脚本误判多个TAP | 两次ID相同；实际读出正确DMSTATUS/SBCS；不是芯片断连证据 | 已定位软件缺陷，离线修正；未实物重跑 | 审核修正、确认当前目标状态，再由用户决定是否新开独立只读阶段 |
| 当前I²C外部接线/从机故障 | 早期OLED及MPU测试无ACK | 本轮未做电气采集，不能沿用早期接线或OLED故障结论判断当前目标 | NOT_TESTED | 写通路安全验证后，再确认真实从机、共地、3.3V上拉、nCS/地址与START/STOP波形 |

证据类型：snapshots/historical中的原始日志为历史实测；本轮connect日志为当前实测；V59为参考模型计算；数字设计文档为文档定义；上表外推到ASIC的因果关系均为假设。离线stub展开的成功分支不是实物测试。
