## 本轮真正执行

1. 新阶段识别原芯片JTAG、DMSTATUS/SBCS，时钟/复位各三次初始为0。只写 PERI_CLKEN=1 开GPIO时钟，读回通过，I²C bit5仍0。无Flash/NVR/SRAM/FIFO写，无reset/resume。
2. 校验GPIOB_DIR=0、AFR1=0、PUPD=0、ODR=0，确保处于GPIO输入而非输出回读；IDR读3次均0x20，即PB2/PB3均采样低。
3. 写PUPD=0x300、读回后，IDR三次均0x2C，即PB2/PB3均高。
4. 保持DIR=0、AFR1=0，写ODR=0xC再读IDR三次均0x2C，写ODR=0再读三次仍0x2C。说明本次输入模式采样没有简单跟随ODR；与手册输入/输出读数区别相符。
5. 最终确认 DIR=0、AF=0、CLKEN=1，ODR=0、PUPD=0x300。共4次目标MMIO写（GPIO时钟1次、PUPD1次、ODR2次），没有产生I²C地址帧。每会话如running则halt一次；退出后CPU状态未再次观测。

手册原文位置：`D:/project/RISCV-63300/_analysis/design_doc_full.txt` 1378–1386行，`gpio_input_data`章节。输入读信号，输出读GPIO数据寄存器。对于硬件AF功能内部输入路径仍不能由此推导完整实现。

## 结论及边界

【已确认】在GPIO输入模式下，PB2/3无内部上下拉采样低，内部上拉可令两位采样高；保持输入时ODR切换未改变IDR。原先输出模式IDR=0x2C不能作为外部高电平证据，需在历史解释中纠正。
【候选】外部有效上拉未到芯片采样路径、实际物理网/Pad映射不一致、OLED供电/接头或板级连接差异、GPIO输入/复用实现差异。
【未证明】OLED接头真实电压、上升时间、外部上拉阻值/是否存在、SCL/SDA物理连通或芯片损坏。不能因本次输入采样低断定OLED坏或接线必错。用户此前反馈示波器约3.3V保留为历史电气观察，测点/模式/时刻未完全绑定本阶段。

## V131 旧ACK结论更正与实际修正尝试

【重大更正】V112A4 第九拍使用 DIR=0x8、ODR=0x9，PB3/SDA仍为输出。按手册输出IDR回读数据寄存器，故该脚本的NACK_INPUT不能作为真实从机NACK证据。旧日志保留但解释降级为“ACK未可靠测得”。不能称所有历史软件探测都正确，其他GPIO探测需逐个核查DIR。对此，前述清单“GPIO位模拟未采到ACK”应理解为历史报告，可信判定仍未完成。

本轮新V131脚本让ODR保持0，仅DIR决定拉低/输入释放；第九拍设计为DIR=0、SDA输入。实际执行未到第九拍：OSOD=0xC成功；DIR=0x8成功产生START请求；DIR期望0xC却读0x8，停止于首个地址位之前；错误清理DIR=0亦读0x8。共4次目标写尝试，未完整发送地址，ACK未采样，不能给OLED ACK/NACK定论。不能由此判实际引脚是否发生START。

独立恢复阶段确认OSOD=0xC、ODR=0、DIR=8后，只写ODR=0xC并读回成功，以开漏数据释放方式避免继续主动拉低。没有重复清DIR，没有再发地址；实际引脚电压未测。最后确认配置：CLKEN=1、RST=0、AF=0、OSOD=0xC、PUPD=0x300、DIR=8、ODR=0xC。会话结束后状态未重新读。
