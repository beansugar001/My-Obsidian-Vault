# CJPCBT021-G 样品的 SEHTAG CSR 探针仿真

样品以载板标识 CJPCBT021-G 记录。上一轮实物扫描发现唯一 TAP，IDCODE 为 `0x1E200A6F`。这说明 JTAG 链路可用。公开 RTL 和 TinyRISC-V 基线使用同一 IDCODE，流片配置仍待确认。

## 离线验证

使用 Icarus Verilog 执行公开 RTL（`189fff578a44b61a328af08e32e60ac890b19a91`，工作树干净）。探针读取 `0x803` 初值，初值为零时写入 1，再恢复 0。仿真监视 CSR 值、内部 `safety_check_en` 和 CPU 数据总线。测试平台把 SRAM 邮箱建模为五个可观察的字。

| 仿真条件 | CSR 读回 | 使能信号上升／下降 | 邮箱结果 |
| --- | --- | --- | --- |
| 公开 RTL 原样 | 0 → 1 → 0 | 1／1 | `0x5345600D`，探针通过 |
| 测试平台强制 CSR 存储恒为零 | 0 → 0 → 0 | 0／0 | `0x5345FA11`，探针判失败，符合对照预期 |

两组均检查了六次数据总线写请求，地址限定在 `0x2000F000–0x2000F010` 的对齐字。使能为高期间未出现数据总线请求。探针观察到五次 `0x803` 写使能，其中三次来自公开 RTL 对 `csrr` 的同值写回。初值异常、恢复失败或进入异常处理时，探针停止并在 x26 留下分支标记。该分支本轮未做故障注入验证。

复现命令为 `powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1`。原始记录为 `reference.log`、`zero_control.log` 和对应 VCD。仿真镜像 184 字节，SHA256 为 `378C0D0EDA46F394E14550CA6EC28C99EBDE28E9F3A16F5200FBD80942EF6DEE`。

## 实物验证顺序

本轮只执行仿真。先核对这批样品的 `0x803` 定义和复位值，再在本次接入的样品上只读确认现有固件并备份。若需运行探针，另行确定固件恢复方式和执行授权。历史记录中 Flash 自然启动已成功，SRAM 独立入口仍待确认。仿真镜像使用 `0x00000000` 作为链接入口，仍需核验实物启动、异常和邮箱路径。

即使实物得到 `0 → 1 → 0`，该实验也只验证控制 CSR 可读写。内存保护的实际行为需另行验证。
