# CY63300 的 SEHTAG 控制寄存器单次验证

上轮实物基线已确认 Flash 自然启动、CPU 对测试字的两组读写以及 JTAG 读邮箱。本轮用公开 RTL 仿真新增的单次触发逻辑。实物仍为 SRAM 基线镜像。

| 场景 | 观察结果 |
| --- | --- |
| 启动时 SRAM 存有旧触发值，随后收到错误值 | 启动清除旧值。错误值未触发任何 CSR 写操作 |
| 提交有效触发，参考 RTL 原样 | `0x803` 读回 `0 → 1 → 0`。使能信号上升、下降各一次。返回 `0x5345600D` |
| 提交有效触发，仿真强制 CSR 存储为零 | `0x803` 读回 `0 → 0 → 0`。返回 `0x5345FA11` |

有效触发消费后，程序只进行一轮控制位验证。参考 RTL 的三条 CSR 读指令仍产生同值回写。使能信号拉高期间仿真未观察到 CPU 数据总线请求。实物中的异常、取指和恢复行为仍待验证。

## 实物执行条件

1. 先独立核对当前启动扇区与上轮 SRAM 基线。上轮基线只占第一个 512 字节页，扇区 SHA256 为 `A5605F98BF115C70F49E2245079E0C5271CD0D91CE5ACA4B78C441AC9ADEC938`。保留该完整扇区作为恢复镜像。
2. 在基线核对一致后，计划只擦写第一个启动页，将 240 字节探针写到 `0x00000000`。镜像 SHA256 为 `744B59D77584A40ABC34C02C659F4F1C29FCBDBFDAAF6CD4A3E51EB5BA6DA6B7`。再次独立校验完整扇区。
3. 冷启动后通过 JTAG 核对邮箱标识 `0x53454833`、阶段为零和触发字为零。三项一致后才发送一次触发，读取初值、置位值和恢复值。
4. `0 → 1 → 0` 且完成码正确时，记录实物控制 CSR 响应。读回全零时记录实际反馈。若停在触发后阶段，保存邮箱及可用调试状态并停止。复位后的探针会重新进入等待状态。

本轮未擦写实物。实物阶段会替换上一轮已验证的基线镜像，并首次置位实物 `0x803`，需要针对这两项授权。
