# SEHTAG CPU 原生合法路径仿真

2026-11-16。基于 Repo_Fanglongrui 提交 189fff578a44b61a328af08e32e60ac890b19a91，GCC 8.3.0，Icarus Verilog 12.0。原仓库工作区干净。未接线或烧录。

## 结果

独立仿真副本从复位取指，固件开启保护，完成一个 32 字节对象的分配。CPU 只发起一次分配并完成一次指针写回，返回地址为 0x20000000，指针元数据被登记。CPU 随后执行一次对象内字写和一次读取。两笔请求均观测到安全使能与 BnBCache 查询有效，模拟存储与 CPU 读回均为 0x1234ABCD，mcause 一直为 0，固件写出完成标记 0x60。

## 仿真适配与结论范围

build_sim_adapter.py 生成独立的 CPU/译码副本，加入试验用分配编码、流水线等待、HAT 请求和写回、边界缓存登记。保护访存时将 BnBCache 索引绑定到执行级操作数，并将合法字读的总线数据转发到寄存器。固件的指令字由构建脚本做一致性检查。测试台以同步单字模型替代板级总线和 SRAM。

这验证的是适配后的合法正对照。追加的编码、控制和读回路径为本地仿真接口，尚无证据说明其对应现有样片。真实 BnBCache 判定的逐笔提交时序、负向场景、多对象和板级行为不在本轮结论中。该镜像只供仿真。

run.ps1 为复现入口。run.log 和 native_legal.vcd 保存结果，firmware_disasm.log 记录反汇编，compile_args.json 记录编译参数。
