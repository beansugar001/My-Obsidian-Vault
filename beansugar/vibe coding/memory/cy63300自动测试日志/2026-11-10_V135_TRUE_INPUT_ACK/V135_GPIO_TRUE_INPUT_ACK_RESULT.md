# V135 地址切离策略下GPIO输入ACK单帧测试

## 规划/范围
用户授权下一步。只发送一次7-bit 0x3C写地址（线上字节0x78）的GPIO模拟帧，不发送OLED控制/命令/显示数据。I2C时钟bit5关闭，仅GPIO时钟=1，RST=0。ODR低锁存=0，DIR输出用于拉低、DIR输入用于释放；第九拍DIR必须0，两线输入。每次目标GPIO写前先读取不同地址安全寄存器，以采用V133/V134中实测成功的访问策略；单次写失败立即停止并尝试输入释放，无自动重发。

## 源码准备
脚本生成初次因PowerShell字符串替换重载错误，未正确替换写函数；这是离线错误，尚未创建硬件阶段marker。检查后修复为完整字符串替换，并重新固定Tcl SHA，核对PARK、ODR初值、第九拍输入及STOP阶段。最终只执行一次硬件阶段。包装器沿用V115E_RESULT等历史标签，但stage为V135，不能按旧标签误认旧运行。脚本使用本机路径和探针，不适合脱离日志直接重跑。

## 实物结果
初始确认CLKEN=1、RST=0、DIR=0、AFR1=0、PUPD=0x300、ODR=0xC，IDR=0x2C。输入态下先设ODR=0，OSOD=0xC。通过DIR拉低/释放依次发送8位：0 1 1 1 1 0 0 0，即0x78。每次SCL释放后在输入模式检查PB2读高；SDA为1时也输入释放；为0时输出低（其IDR位只能表示锁存，不能当独立外部低电平验证）。

第九拍：DIR=0x0读回成功，SCL/SDA均为输入；IDR=0x2C，因此SDA输入为高，结果NACK_INPUT_HIGH。随后先拉低SCL，再拉低SDA、释放SCL、释放SDA产生STOP请求；最终DIR=0、IDR=0x2C。

结果GPIO_FRAME_NACK_INPUT_HIGH_STOP_INPUT_IDLE；33次目标GPIO MMIO写全部通过读回。本轮未写I2C控制器/FIFO、Flash/NVR/SRAM，未reset/resume；初始running时halt一次。最后已确认CLKEN=1、DIR=0、ODR=0、OSOD=0xC、PUPD=0x300、AF=0；退出会话后状态未持续监控。

## 与历史的差别
V131在第三次写方向失败，未到ACK；V135每次写前先读安全地址，整个方向切换通过。说明该策略在本轮GPIO位模拟中可用，但不能唯一归因内部地址边沿缺陷，插入读取还增加事务和时间。
V112旧第九拍SDA仍为输出，NACK结论不可靠；V135第九拍已确认SDA为输入，排除了这一个软件判读错误。旧日志保留并降级，不追溯声称旧帧有效。

## 可以和不可以得出的结论
- 可得：寄存器方向切换及一个0x78地址请求已按脚本完成，第九拍芯片GPIO输入没有看到SDA被拉低。不是单纯FIFO统计现象。
- 不可得：不能保证OLED接头端实际出现正确幅值/时序的完整I2C帧，也不能判断OLED坏、线必错或实际地址必为其他值。
- SBA逐笔GPIO访问非常慢（本阶段主机耗时约14s，包括连接、检查、逐位写读与STOP），不是活跃CPU的自然I2C时序；第九拍采样较晚、器件时间行为等仍是局限。无仪器情况下不能把寄存器轨迹当外部示波器波形。
- 没有看到ACK，不应发送完整OLED初始化或宣称显示成功。硬件I2C FIFO是否因写前地址切换而改善，本轮没有测试。

## 下一步分支
优先离线审计并把地址切离策略引入受控硬件I2C寄存器写（包括直接ADDR=0x3C后的I2C_EN），以区分临时地址锁存与总线写触发；新硬件事务前要确认干净空闲，不复用旧marker。可计划只发一字节，检查GPIO读回/输入语义及错误状态，不能因硬件RAW=0判ACK。
如继续GPIO探测，应由用户明确模块地址/同线束验证或安全改变外部负载；不盲发多个地址/重复帧。当前不需要为GPIO清FIFO而复位。
