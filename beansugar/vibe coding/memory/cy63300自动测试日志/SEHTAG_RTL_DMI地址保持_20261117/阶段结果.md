# CY63300 调试地址保持与 RIB 仲裁离线复核

Icarus Verilog 直接编译参考 TinyRISC-V 的 jtag_dm、RIB 与全握手模块。测试台从 DTM 请求接口发送 DMI 命令，以 m1 模拟取指，并用 m0 对简化的 SRAM 模型写入已知数据。模拟的 SRAM 译码接到 RIB 的 s2。测试不含 CY63300 流片的真实互联或 SRAM，也未接入 CPU 核。

| 验证 | 实际仿真结果 |
| --- | --- |
| 打开地址读触发，读取第二组计数副本 | 调试端口停在 `0x2000F110`，SBDATA0 为 `0xE8D` |
| 关闭读触发，写 SBADDRESS0 为 `0x2000F004` | 地址寄存器更新，实际端口保持 `0x2000F110`，测试台更新后 SBDATA0 为 `0xE94` |
| 继续关闭读触发，写 SBADDRESS0 为 `0x2000F02C` | 实际端口仍保持 `0x2000F110`，SBDATA0 为 `0xE9F` |
| 关闭触发阶段的 RIB 仲裁 | 调试获准 10 个周期，取指暂停 10 个周期。此统计已扣除测试台两次显式存储的周期 |
| 只读 DMSTATUS | 响应阶段调试端口获准 1 个周期 |
| 重新开启读触发并切换目标地址 | 调试端口更新为 `0x2000F02C`，SBDATA0 读到固定值 `0x52547000` |

关闭触发只能阻止这份参考实现用新 SBADDRESS0 更新内存端口地址。调试请求依然可能获得 RIB。SBDATA0 可以回传原地址的当前数据。测试台写入的三个值来自上一轮实物日志，用于复现旧地址数据变化的读回模式。尚未复现导致实物计数增长的 CPU 执行。

对应位置为参考 `rtl/debug/jtag_dm.v` 第 188、274、310 行及 `rtl/core/rib.v` 第 126–138 行。完整输入哈希、仿真波形与控制台日志保存在本目录。仿真通过不能证明实际硅片采用了这份仲裁或握手逻辑。

## OpenOCD 退出审计

实物原始扫描日志中的当前 Windows OpenOCD SHA256 为 `EECE42DE2378E4A7D2D0D71D1178D8B35E4C67839FE2C4D5EA964C2561127E27`。原始文件 `sba_control_20261117_144944_516690/openocd.log` 第 441–447 行显示，在 `shutdown command invoked` 后，清理阶段先写 DMI `0x10=0x40000005`，解码含 `resumereq` 与 `dmactive`，随后写 `0x10=0x00000000`。该会话退出前 CPU 已在运行。日志确认写请求和 DMI 成功响应，未独立验证芯片动作。历史会话若未记录退出扫描，不能仅凭 Tcl 中没有 resume 判断退出后的 CPU 状态。

本地 OpenOCD 参考源的 RISC-V 0.13 清理函数只释放软件状态，和以上二进制日志不同。它不能用于证明当前二进制没有退出副作用。本轮未连接实物。

下一步可离线把 CPU 核接回相同 RIB，运行已知完成后自跳转的最小固件，对比无调试、只读 DMSTATUS 和显式读三组的 PC、取指暂停与邮箱写使能，验证是否出现多次写回。后续实物实验要将清理阶段纳入扫描日志，并验证退出动作或在同一会话内完成所有状态采样。
