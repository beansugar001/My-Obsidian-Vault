# CY63300 冷启动提前执行的 SRAM 对照

上轮实物在上位机发送触发前已经完成 `0x803` 测试。新镜像仅使用普通 CPU 指令和 SRAM 邮箱，记录首次读值、比较值、退出时的读值、退出路径和两值异或。它保留原镜像首次加载指令的地址 `0x28`、两条 NOP 和条件分支的地址 `0x34`。为记录首次分支结果，分支目标和后续代码已经改变。若实物不能复现，原版故障仍待定位。

镜像长度为 172 字节，SHA256 为 `52BC806F7FCF73D13F829349A10C3649EC686710E1B40C3219253E2964E80E14`。Icarus Verilog 使用公开参考 RTL，执行了以下检查。

| 场景 | 首次读值 | 退出读值 | 路径和状态 |
| --- | --- | --- | --- |
| 启动时有旧触发值，清零后发送错误值，再发送正确值 | `0` | `0x53454152` | 错误值保持等待。正确值从等待路径退出一次，路径 2，完成码 `0x5741600D` |
| 测试台强制第一次读到触发值 | `0x53454152` | `0x53454152` | 首次直接退出，路径 1，完成码 `0x5741600D` |
| 测试台把第一个分支替换为 NOP | `0` | `0` | 首次直接退出，路径 1，异或非零，异常码 `0x5741FA11` |

仿真设置的后两项用于验证诊断能区分两种现象。三组均未观察到 CSR 写入或安全使能。

## 下一轮实物顺序

1. 完整读回当前启动扇区，确认与上轮 CSR 镜像的独立读回一致。该备份 SHA256 为 `3C25575736DC75A06CC59011B2FDA41701F9F0CA213DB00B24B97A29FE1500B1`。随后仅擦写首个 512 字节页，写入 172 字节镜像，并独立校验整个扇区。
2. 冷启动后先只读 SRAM 邮箱。若已退出，记录首次读值、比较值、路径和异或，并停止。读值等于比较值时优先查 CPU 读路径和触发字的启动清零。读值不同但进入退出路径时优先查分支或执行流。先排除记录错误，再归因。
3. 若保持等待，先写一次错误测试值，验证继续等待。再写一次有效值，验证只消费一次，读回路径 2 以及正常完成码。两次操作的目标仅为这份测试镜像的 SRAM 触发字。

本轮只进行离线仿真和文件检查。尚未替换实物 Flash。
