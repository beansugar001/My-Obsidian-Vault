# CY63300 SRAM 循环的直接跳转与间接返回对照

上一轮实物中，变值组计数随 CPU 运行持续增长，Halt 后固定为 433，完成标记一直存在。本轮制作两组共享同一加载与比较循环的镜像。两组均由 CPU 在第七次不匹配后修改测试字，预期第八次匹配。保留原 `0xF4` 的 LW、两条 NOP 和 `0x100` 的 BNE。第一组退出后走直接跳转，第二组经 `0x170` 的 JALR 返回。两组按顺序执行，返回方式选择还经过一个条件分支。

| 仿真组 | 返回前 | 返回后 | 停驻标记 |
| --- | --- | --- | --- |
| 直接跳转 | 第 8 次匹配，`0x52545000` | `0x52546000` | 共用 `0x52547000` |
| JALR 间接返回 | 第 8 次匹配，`0x52545000` | `0x52546000` | 共用 `0x52547000` |
| 将 JALR 替换成回到循环的仿真对照 | 写回计数增到 10，`0x52545000` | 0 | 0 |

正常参考 RTL 中，两组分别写回一次计数，完成后监视 70 个仿真周期，无额外数据总线访问。模拟回环中，计数增长但完成标记为零，与先前实物的“计数增长且完成标记有效”有差别，所以该仿真只验证返回标记能区分人为构造的回环。程序只读写约定的 SRAM 邮箱，不访问 SEHTAG CSR。

## 实物步骤

- 先独立读取当前 64 KiB 启动扇区，要求与有界等待备份一致，SHA256 为 `F17BF7BC07D860DD25957E9141B2CB38BDB6EB577322D3D4543477B8A134B65F`。
- 一致后仅擦写首个 512 字节启动页，烧入 372 字节镜像，镜像 SHA256 为 `FEE175B1B44A4AAB18892AB8BD7899B6A00E108DFCBAC9FDAE6865D562129A40`。烧录后独立读回整个启动扇区。
- 冷启动后只读 SRAM 邮箱 `0x2000F000–0x2000F033`。直接组、间接组计数分别在偏移 `0x04`、`0x10`，返回前后标记在偏移 `0x1C/0x20`、`0x24/0x28`，完成标记在偏移 `0x2C`。
- 两组预期是匹配值 `0x53454000`、匹配退出码 `0x4D415000`、计数稳定为 8。若只在间接返回组复现，优先检查返回模式、组顺序和路径选择分支。若返回后标记已写但计数仍变，优先检查返回后的路径或调试并发。

本轮只做离线构建与仿真，实物未操作。
