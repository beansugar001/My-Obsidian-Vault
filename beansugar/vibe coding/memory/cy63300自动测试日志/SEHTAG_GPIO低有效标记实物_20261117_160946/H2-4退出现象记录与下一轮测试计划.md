# H2-4 退出电平记录与下一轮测试计划

## 当前现象

| 已完成的对照 | 结果 |
| --- | --- |
| OpenOCD 初始化后立即退出 | H2-4 仍约 3.3 V。 |
| 单读 SRAM 后立即退出 | 0x2000F010 返回 8，退出后 H2-4 仍约 3.3 V。 |
| 冷启动后单读 SRAM，确认退出前读数再退出 | 0x2000F010 返回 8。会话仍打开时 H2-4 约 3.3 V，确认退出后测为低电平。 |
| 首次冷启动单读 SRAM 并定时退出 | 测量时 H2-4 已低，下降阶段未知。 |

分开观测那轮，SRAM 读完到退出命令之间约 33 秒，DMI 扫描数为 0。退出阶段记录到一次后台 DMSTATUS 读取、DMCONTROL 中的 resumereq，以及清除 dmactive。发起单独 DMSTATUS 读取这一步在该轮省略，现象仍复现。三项自动退出操作落在同一个电压观察区间，各自的影响待区分。

## 下一轮

目标是比较同样的上电、等待和退出流程下，前面那笔 SRAM 读取是否影响 H2-4 拉低。

- 两组使用当前标记固件、同一 DAPLink、同一 OpenOCD 版本和配置。每组独立冷启动。拔掉板子 Type-C 和 DAPLink USB，等待 10 秒，先接回 Type-C，几秒后接回 DAPLink USB。OLED 和 STM32 不参与。黑表笔固定 H2-2/GND，红表笔固定 H2-4。起点为约 3.3 V。
- A 组先做。初始化后等约 10 秒，把原 SRAM 读取的位置留空。随后等约 30 秒并保持会话打开。先记录 H2-4，收到读数后再明确触发退出。退出完成后立即再测一次。
- B 组重新冷启动，重复 A 组的时序，在同一位置只加一次 32 位 SRAM 读取，对象为 0x2000F010。记录实际命令、读回、退出前后电压及 DMI 扫描。两组均省略额外的独立 DMSTATUS 读取。
- 日志按阶段核对。A 组在初始化后、退出前应有 0 次 DMI 扫描。B 组只允许单读 SRAM 所需的扫描，之后的等待应有 0 次扫描。两组的等待若因人工反馈而不同，记录日志中的实际间隔。发生连接错误、等待期间出现额外扫描或无法取得退出前电压时，把该轮标为无效对照。

| 观察结果 | 判断 |
| --- | --- |
| A 组退出前高、退出后低 | 该条件下，退出时拉低可以在没有 SRAM 读取的情况下出现。 |
| A 组退出后仍高，B 组退出前高、退出后低 | 支持 SRAM 读取留下的状态与退出触发有关。复测一次同样的对照后再缩小到 SBA 状态或退出操作。 |
| 任一组在退出前已经低 | 下降窗口包含本轮退出前的步骤。保留日志，缩小到更早的观测区间。 |
| 两组始终高，或结果不一致 | 该轮无法复现稳定差异。核对实际起点、等待时长和 DMI 序列。 |

本轮工作为记录与规划，尚未执行上述 A/B 对照。
