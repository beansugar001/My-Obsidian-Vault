# 正常运行日志对照与示波器时序方案

## 对照日志

- V159C 独立冷启动后 OLED 显示 Hello，DAPLink USB 拔除。STM32 采集到 6 帧、123 字节全部 ACK，6 次 STOP。V159D 只接板子和 OLED 冷启动，显示结果 5/5。这组证据覆盖当时的 Flash 启动和 OLED 业务，测量时 OLED 在板上。
- 当前 496 字节 GPIO 标记镜像只接 Type-C 时，用户确认 H2-3 低、H2-4 高。这个基线与当前待测程序一致。
- A 组只初始化并退出，H2-4 保持约 3.3 V。延长等待到 116.362 秒仍高。
- B 组冷启动，单读 0x2000F010 返回 8，69.369 秒后退出，退出前约 3.3 V、退出后低。另一次直接读完即退出后仍高。那次沿用上电现场，且没有逐笔 DMI 跟踪，因此两轮同时存在上电历史和等待条件差异。
- B 组和延长等待的 A 组，退出日志均记录同顺序的后台 DMSTATUS、resumereq、清除 dmactive。日志只能记录主机侧事件时间。两轮从退出的 DMSTATUS 请求到最后一笔 DMCONTROL 请求分别约 13 ms 和 11 ms。

## 示波器实物计划

1. 先做一次 B 组捕获。保留当前诊断固件，OLED 和 STM32 断开。断电时固定探头。CH1 尖端接 H2-4，CH2 尖端接已用过的 U5-1/TCK 测点。两个地夹只接板上已确认的 GND，如 H2-2、U5-10/GND。探头本体和通道菜单都设为 ×10，DC 耦合，约 1 V/div。板上测点难以固定时，先只接 H2-4。
2. 冷启动，先确认 H2-3 约 0 V、H2-4 约 3.3 V。运行原 B 组单读 SRAM 流程，在退出门控处等待。此前的 SRAM 访问已完成，日志应记录等待中没有额外 DMI 扫描。
3. 触发源 CH2/TCK，边沿上升，电平约 1.5 V，先用 5 ms/div，把触发位置移到屏幕左侧附近，按 Single。通知已就位后才由主机释放退出。两组都用 TCK 触发，所以 H2-4 没有下降的对照也能抓到波形。保存两条曲线和同轮日志。若只有 CH1，则改成 H2-4 下降沿触发，电平约 1.5 V，触发点居中。未触发时记下轮后静态电压。
4. B 捕获后独立冷启动重做 A 组，只去掉 SRAM 读取，在同样的时间点设置触发并退出。优先把两轮从访问时点结束到 shutdown 的实际间隔控制在同一窗口，例如 70 秒附近。若人工回复超过目标，记录实际时间。完成 A/B 后，若需验证长短等待的影响，再用同样的冷启动、同一 B 序列改变等待时长，避免重用旧会话作为短等待样本。

两通道波形能把 H2-4 下降与 TCK 脉冲组对齐。精确区分是哪笔 DMI 命令仍需同步的数据线或可对照的主机时间标记。若退出脉冲后约 40 ms 内没有看到下降，但万用表稍后测到低，再调整为 20 ms/div，扩大退出后的观察时间。
