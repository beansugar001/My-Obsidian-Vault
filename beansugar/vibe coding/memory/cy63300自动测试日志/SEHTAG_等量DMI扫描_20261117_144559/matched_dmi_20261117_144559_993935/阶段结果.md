# CY63300 等量 DMI 扫描对照

采用同一双地址计数镜像，在同一会话中比较静默、纯读 DMI DMSTATUS，以及显式 SBA 读取固定 SRAM。CPU 保持运行，后台轮询关闭。每组有三窗，窗口持续 2100–2106 ms。每个读窗口为 54 条 DMI 操作，从该版 OpenOCD 的原始扫描记录逐条核对为 108 次 40 位 DMI DR 扫描。静默窗内未记录 DMI 扫描。窗口边界使用相同的读回操作。

| 窗口 | DMI 扫描数／窗 | 原计数增量 | 副本增量 |
| --- | --- | --- | --- |
| 静默 | 0 | 13、13、10 | 15、12、11 |
| 纯 DMI 读取 DMSTATUS | 108 | 59、59、75 | 60、59、78 |
| 显式 SBA 读取固定 SRAM | 108 | 82、82、80 | 79、77、81 |

纯读 DMI 即可显著提高计数增量。对齐扫描数后，SBA 的原计数平均增量为 81.3，仍高于纯 DMI 的 64.3，差值约 26%。SBA 窗口交替读取 `0x2000F004` 的 8 和 `0x2000F02C` 的完成码，全部正确。扫描日志中的窗口内写操作仅对调试模块的 SBCS 和 SBADDRESS0 做读事务配置，没有写 SBDATA0，也没有目标内存写入、暂停或复位。

纯 DMI 组的窗口只读 DMSTATUS。SBA 组包含不同的 DMI 地址、读写类型以及实际 SRAM 总线读。控制住扫描次数后，这些因素仍同时存在。下一步可增加一个只修改调试模块读配置、保持地址触发关闭且不读目标 SRAM 的等扫描数对照，以区分调试寄存器访问与 SRAM 总线读的影响。

首次调用队列计数接口时 OpenOCD 以 `0xC0000005` 异常退出，未留下有效窗口。第二次使用原始扫描日志完成九个窗口。主机解析器最初将 OpenOCD 的 Debug 回显也当作窗口标记，已修正并离线复核，未重新连接板子。第二次原始 OpenOCD 日志有完整结束标记及 shutdown，原封装未保存该次 OpenOCD 退出码。
