## 0. 一句话结论（可直接进组会）

> 栈项在样片上首次拿到可复现的三轮证据：整段栈的硬件边界判定**没有**成立——安全使能打开后，一笔未登记的栈写既不报异常（mcause 保持 0）也不提交（目标字保持注毒值 0xBBBBBBBB），CPU 就此停摆；返回地址保护只有"寄存器 + 正常返回基线"通过（ra 存到 28(sp)=0x000000E0，CPU 读回比较一致，3/3），**没有金丝雀也没有影子栈**；局部缓冲区软件长度检查在样片上 3/3 通过。

## 1. 本轮新解决的能力问题：怎么让样片真的重跑

前三轮复测都卡在"无法重启"，本轮定位到可用路径：

| 手段 | 结果 |
|---|---|
| `reg pc 0x0` + resume | **不可用**。写 PC 报 `Written PC (0x0) does not match read back value (0x2c062df3)`；即使读回变成 0x00000000，resume 后 2.5 s 内邮箱仍是注毒值 0x11111111，CPU 没有执行（`restart_20261120_1842`） |
| `reset run` / `reset halt`（默认 ndmreset） | **无效**。`Hart 0 didn't run coming out of reset in 1s/5s; dmstatus=0x430382`，mbox/栈帧完全不变 |
| `reset_config srst_only srst_nogate` + `reset run` | **有效**，但过程"不优雅"：TCL 当场报 `JTAG scan chain interrogation failed: all zeroes`、`dmstatus=0x0 / not authenticated`（SRST 把 TAP 一起复位了），命令返回 FAIL；**但芯片真的复位并从 Flash 重新启动**，下一次 OpenOCD 会话读到的就是新一次启动的现场 |
| STM32F103 主控断电/复位 | 不可用：该板 `task_plan.md` 写明硬件未连接、未授权做电源时序 |
| 重烧同一镜像（436 B program + verify） | **不重启**。reflash_reboot_20261120_1855：烧写 verified 后新会话读到的邮箱仍是上一轮注入的 0x11111111、结果块 r0 仍是 0x22222222，poison_before_flash_20261120_1850 注的栈帧毒值 0xBBBBBBBB/0x99999999/0x88888888/0xAAAAAAAA 完整保留 → 固件没有重跑 |
| reset_config srst_only srst_nogate + reset halt（19:00 复验） | 与上面一致：命令报 not authenticated / dmstatus=0x0，但芯片已重启并**跑过**（读到 0x4D533141、frame+16 已是复制后的 0x13579BDF）；随后 resume 成功、halt 超时（dmcontrol=0x80000000, dmstatus=0x00430c82）→ 只能"复位后开新会话读" |

因此本轮流程固定为两个会话：**prepare**（halt → 校验镜像字 → 清邮箱 → 注毒 → 回读确认 → SRST 复位）＋ **check**（重新连 → dump 邮箱/结果块/栈帧 → 同一会话 shutdown 前落盘）。三轮全部按此执行，`mbox_a==mbox_b`、`res_a==res_b`、`frame_a==frame_b` 均成立。

## 2. 镜像与固件的关键事实（可复核）

反汇编 `stack_check_20261120\firmware_disasm.log`：

- `dc: jal ra,170 <framer>`，返回点 `e0`；`170: sw ra,28(sp)` / `178: lw ra,28(sp)`
- `e8: lw t1,28(sp)` → `xor` with `auipc/mv t0`(=0xe0) → `seqz` → `f4: sw t2,0(s10)`（r0）
- `f8: sw t5,4(s10)`（r1，leaf 调用次数）
- `104: sw t0,0(s0)` 写完成标记 0x4D533141；`10c: csrw 0x803,t0`（t0=1）**打开 safety_check_en**
- `118: sw t1,8(sp)`（t1=0x5555AAAA）← 打开安全检查后的第一笔栈写
- `124: sw t0,16(s10)` 写 0x4D533143（"store 已过"标记）
- 陷阱入口 `188`：先 `csrw 0x803,zero`，再读 mcause/mepc（写 8/12(s10)）、`lw t3,8(sp)`（写 20(s10)）、写 0x4D533142（16(s10)=0x2000F110）

栈地址：初始 sp 写入 w1=0x2001FF00，`addi sp,sp,-32` 后帧基址 w2=0x2001FEE0；DataRAM 顶端 0x20020000。**该固件没有任何 HAT/BNB/标签登记指令**（CSR 写只有 mtvec 与 0x803），没有 .map/.ld/启动代码。

## 5. 与参考 RTL 的差异（引用时必须注明版本）

- 参考 RTL 版本：GitHub 提交 `189fff578a44b61a328af08e32e60ac890b19a91`（本机 `D:\project\RISCV-63300\三方测试\Repo_Fanglongrui`），其中 `rtl/core/tinyriscv.v:1240–1276` 把 `hat_enable` 固定为 0，HAT 操作码/地址/大小/标签输入也固定为 0 → 这版 SoC 无法驱动分配与释放。**用户已确认 CY63300 实际流片版本 hat_enable 非零**，流片 RTL 在堡垒机，本机拿不到。
- 参考模块仿真报"拒绝 + mcause=5、mepc=0"；**样片实测是"拦截 + 无异常 + 停摆"**（mcause=0、phase2 标记 0）。两者不是同一行为，不能互相背书。
- 参考仿真的边界比较只取访问起始地址、判定滞后一拍；样片因无法登记对象，**无法**验证"整笔访问覆盖地址范围"这条要求。

## 6. 历史现象的处置（不合并成根因）

1. **首轮 r0=0"ra 槽不匹配"**（`round_20261120_180518_145455`）：那是烧录后未经受控的残留启动，帧未清零；真复位 3/3 都是 r0=1。→ 该 0 不作为结论，属中断启动残留。
2. **"毒化复跑"轮**（`round2_poison_20261120_1820`）：`reg pc 0x0` 被拒、CPU 未重启，注毒值原样保留，该轮"frame+8/+28 未落地"的判断**作废**；本轮 SRST 轮证明 frame+28 其实写入了 0xE0。
3. **DM 读 CSR 与 GPR 串位**（`probe_20261120_1812`）：读 mcause 得到 0x2001FF00（=sp）、读 mepc 得到 0x007800E0（=ra）。→ 一律不采信 DM 读到的 CSR/GPR，改用固件自己写进邮箱的值。
4. **整数溢出旧轮的"拒绝后读回像冷启动初值"**：机制与本轮相同——热复位不清 SRAM，上一次运行的残留与"保持原样"不可区分；本轮的注毒法就是为消除这种混淆而设计的。
5. 首轮"烧录后即见 0x4D533141"（round_20261120_180518_145455）：18:50/18:55 的对照（重烧同一镜像后邮箱仍保留 0x11111111 注毒、固件未重跑）证明**烧写本身不触发重启**，首轮那次启动另有来源（此前的复位动作），因此该轮 r0=0 属未经受控的残留运行，不能作为一次有效观测。
## 7. 仍卡住的地方

- **无法登记对象**：固件里没有 HAT/BNB 指令，也没有 .map/.ld 说明栈对象边界；参考 RTL 的 SoC 端 HAT 输入固定 0。→ 第 ② 项的"登记后是否作出正确判定"在样片上无法闭环，只能记为待确认。
- **停摆的性质**：是"总线重试直到永远"还是"流水线冻结"，本轮只能从"DM 仍报 running、halt 能停住、内存不再变化"描述，无法进一步定性（缺单步能力：`step` 返回 -4）。
- **要区分"所有未登记 store 都停摆"还是"只有这个地址停摆"**，需要 v2 固件（见下），按约定换固件前要单独确认。

## 8. 建议的 v2 固件差异（未烧录，等确认）

在现有 436 B 镜像上增加（仍须 ≤512 B，Flash 第 0 页）：

1. 在 `118: sw t1,8(sp)` **之前**写一个"开始 store"标记（如 0x4D533150）→ 证明停摆在 store 上而不是更早；
2. 打开安全后先做一笔**写到邮箱 0x2000F000 的 store**，再写标记 → 区分"全部未登记 store 都停"与"只有栈帧地址停"；
3. 再对另一个未登记地址（如 0x20001000）做一笔 store + 标记 → 判断是地址相关还是全局；
4. 陷阱入口把标记写在 `csrw 0x803,zero` **之前**，避免"先关安全检查再写标记"掩盖真实时序。

风险：需要重新烧录同一 Flash 页；现有 3 轮证据已落盘，换镜像不破坏它们。
