## 4. 已知异常（不并入根因）
1) 溢出保持标志 w7=0（可复现）：同镜像 RTL 仿真 raw_recheck/simulation.log 的 word[7]=1，板上 4 轮均为 0；而同一轮里 w5（超长保持）=1。注毒证明 sw a0,28(s0) 确实执行（槽位由 0xAAAAAAAA 变为 0x00000000），即 a0=0。
   同一函数 destination_equal 内的 sw t0,0(a1)/sw t1,4(a1) 写回的是 pattern，而 xor/or/seqz 给出的却是 0 → 同一次比较里「存回数据」与「比较结果」矛盾。11-19 的 FIRST 镜像轮（observe_20261119_184043_531636）也是 oversize_preserved=0，LIVE 镜像轮 observe_20261119_204511 为 1 → 该比较链在板上不稳定，仿真恒为 1。
   结论：未确认根因，不并入「拒绝后读值回到启动初值」现象；建议下一轮用门级/后仿，或把保持标志拆成「写标志前再读一次目标」的独立观测点。
2) JTAG 后值只能证明「无残留变化」，不能证明「拒绝未被复制」：RAW 固件在写完成标记前已把源/目的恢复为原始值，所以完成标记后 JTAG 读到的是恢复值。区分「拒绝保持」与「恢复覆盖」靠 CPU 侧 before/after 快照（本轮已做）；若要用 JTAG 直接看拒绝后内容，需 BEFORE_RESTORE 镜像（LIVE 分支只有一次超长调用，11-19 observe_20261119_204511 已通过）。
3) 镜像溯源缺陷：run_board.py 里 RAW.previous 指向 program_20261119_183558_576423，其回读前缀实为 388 B 的 FIRST 镜像（前缀 sha 52A96655…，image_provenance.json 记录 archived_prefix_matches_raw_image=false），并未认证 RAW。真正认证 RAW 的是 raw_recheck/program_20261119_184321_421135。audit 只比 sector sha 与 verified，不校验前缀，故该错位不会被自动拦住。
