# CY63300 实物 CSR 读回与触发异常

## 烧录与独立校验

在 CJPCBT021-G 样品上，擦写前读取的 64 KiB 启动扇区与已验证的 SRAM 基线备份逐字节一致。实际发送一次第一个 512 字节页的擦除请求，然后写入 240 字节探针。独立读取整个启动扇区，SHA256 为 `3C25575736DC75A06CC59011B2FDA41701F9F0CA213DB00B24B97A29FE1500B1`，与预期逐字节一致。烧录记录在 `program_20261117_100436_858400`。

## 冷启动后的实物观察

用户重新上电后，JTAG 识别正确，CPU 为 running，DMSTATUS 为 `0x00430C82`，SBCS 为 `0x20040404`。首次读邮箱时，探针已给出完成结果，上位机判定等待前置条件失败。脚本实际发送的 SRAM 触发写入次数为 0。原始日志及停止记录保存在 `trigger_20261117_100852_601374`。

另开只读会话复核了两次 SRAM 邮箱和 Flash 起始 240 字节。两份邮箱二进制完全相同，Flash 起始内容与刚烧录的探针一致。只读复核日志在 `unexpected_done_readonly_20261117_100926_527799`。

| 字段 | 值 |
| --- | --- |
| 探针标识 | `0x53454833` |
| CSR 初值 | `0x00000000` |
| CSR 置位后 | `0x00000001` |
| CSR 恢复后 | `0x00000000` |
| 完成码 | `0x5345600D` |
| SRAM 触发字 | `0x00000000` |

该结果为实物 `0x803` 响应写入提供了证据。由于上位机尚未发送触发时程序已经完成，受控触发试验未通过。没有证据判断是等待循环的 SRAM 取值、分支、复位入口还是其他行为导致提前执行。反汇编确认观测文件中等待分支为 `0x34: bne t0,s4,0x28`，CSR 序列地址为 `0x68–0x9C`。现有记录仅覆盖 CSR 读写响应，未测试内存保护功能。

## 下一项判别实验

用只读写 SRAM 邮箱的等待循环对照程序记录首读值、比较值和分支结果，分别验证冷启动后保持等待、错误触发值仍等待以及正确触发值只进入一次。这个对照程序不访问 `0x803`，可将疑点缩小到启动与等待逻辑。样品当前保留探针镜像，保存了前一轮 SRAM 基线的完整扇区备份。异常后未再复位、触发或擦写。
