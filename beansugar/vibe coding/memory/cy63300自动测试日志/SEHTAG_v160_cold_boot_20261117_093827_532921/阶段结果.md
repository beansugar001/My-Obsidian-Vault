# SEHTAG 实物启动与 SRAM 邮箱基线

用户重新插拔后通过同一 DAPLink 连接，实物识别为 `riscv.cpu / 0x1E200A6F`，CPU 为 running。通过一次 OpenOCD 会话从 `0x2000F000` 采样两次，每次 68 字节，两次结果一致。未暂停 CPU，未写目标存储器或 CSR。

| 实物项目 | 值 | 判断 |
| --- | --- | --- |
| V160 邮箱标识 | `0x4D423160` | 与 V160 源码一致 |
| 运行阶段 | `0x16000005` | 已到 OLED 计数刷新 |
| 已完成帧 | 31 | 来自固件计数 |
| 最近完成的计数／当前目标计数 | 5／6 | 已完成至少一次计数刷新 |
| 完成码 | `0x00000000` | 这一采样点尚未到程序终点 |

基于用户的重新插拔记录和 V160 邮箱，启动路径及 CPU 写邮箱、JTAG 读邮箱链路通过。原始命令、日志、两份邮箱文件及 SHA256 在同一目录。

## 专用 SRAM 基线

136 字节镜像链接于 `0x00000000`，专用测试字为 `0x2000F014`。Icarus Verilog 在公开 RTL 的 CPU 核与测试台存储模型上通过两次 32 位读写，CPU 读回 `0x13579BDF`、`0x2468ACE0`，邮箱完成码 `0x5345600D`。测试台监视到 2 次读、7 次写（含邮箱），无 CSR 写入。镜像 SHA256 为 `EFD4837FE3CE916690714E976254B740F37B2460A2F1531F4460ABCF9E5F4DCC`。镜像尚未烧录，普通 SRAM 读写仅在此仿真中通过。

## 后续实物烧录与恢复

专用镜像覆盖 V160 的 Flash 入口。其中有 70 个字节需要从 0 改回 1。因此应先核验目标和历史备份，再使用经审计的 Main Flash 擦写流程。期望启动扇区由 136 字节镜像及后续擦除态组成。读取并校验整个扇区后才能启动。邮箱的预期值为基线标识 `0x53454231`、两个读回图样和完成码。

恢复目标是已备份的 V160 扇区，SHA256 为 `0808DA861C1BBD7B03BB88A3ECB625798B0A0797F114788529498EEC5428CA9C`。恢复后独立读回全扇区并逐字节比较，再利用原有 V160 邮箱确认运行。现有 V160 编程脚本绑定历史输入及已用 marker，后续操作需要基于实际快照审查并使用独立入口。此次未执行任何擦写或恢复操作。
