# CY63300 SRAM 有界等待对照

上一轮三组单次分支通过实物验证。本轮在离线镜像中加入向后分支和 32 次计数上限。与上一轮短间隔组相比，`0xF4` 的 LW、两条 NOP 和 `0x100` 的 BNE 连同指令编码保持一致。程序的其他分支、循环计数和返回路径加入了新指令。两组测试在同一个镜像中依次运行，期间无需上位机写入触发值。

| 场景 | 预期及正常仿真结果 |
| --- | --- |
| SRAM 内容始终为 `0x13579000`，与比较值不相等 | 迭代 32 次，最后读值 `0x13579000`，计数上限退出 `0x4C494000` |
| CPU 完成第 7 次不匹配后将 SRAM 改为 `0x53454000` | 第 8 次读到匹配值，匹配退出 `0x4D415000` |
| 测试台只修改第一组的第一次数据读回 | 第一组提前以匹配退出，记录次数为 1。第二组仍正常 |

公开 RTL 正常仿真共记录 40 次数据加载，两组均完成。受控对照让第一组提前退出以验证记录可区分两条退出路径。程序不访问 `0x803`。镜像长度 312 字节，SHA256 为 `1D50070764CF7244AA25FD2B8B4447B9F48A583B9D05A78F85D872A605C5E164`。

实物步骤为独立核对当前 64 KiB 启动扇区，要求与上轮备份 SHA256 `3D795D003895BE849C3B11114E3E15D86C30683C8E61E88ED09A0EF05DFD053D` 一致。仅擦写首个 512 字节启动页，独立读回整个扇区，之后冷启动并只读采样 SRAM 邮箱 `0x2000F000–0x2000F033`。完成码为 `0x4C576000`。若计数或退出原因异常，优先核对最后读值是否匹配、比较值和计数上限是否正确，再缩小到循环控制或读值。若两组都通过，早先无限等待的行为仍需用更接近原循环的对照验证。

本轮仅执行离线构建与仿真，实物未操作。
