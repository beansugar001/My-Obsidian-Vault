# V106/V107 重上电后 GPIO 状态结果（2026-11-09）

## 实测结果

用户按要求完全断开 Type-C 与 DAPLink 目标供电约 5 秒后重新连接；用户报告 V105 低保持期间未看到 Pad8 电压下降，重上电后示波器上的 Pad8/SCL 一直为高。

### V106：重上电后的只读时钟检查

- IDCODE=`0x1E200A6F`，CPU halted，DMSTATUS=`0x00430382`，SBCS=`0x20040404`。
- PERI_CLKEN=`0x00000000`，PERI_RST=`0x00000000`。
- GPIO 时钟关闭，按手册没有读取 GPIOB 内部寄存器；I²C 时钟 bit5 关闭，也未读取 I²C 内部寄存器。
- 目标 MMIO 写次数 0。
- 日志 SHA256：`C6C7A3BB19C6BD3C3C054916C2155154600C72865DDD1DEEA3AAEF962971C797`。

### V107：开启 GPIO 时钟并核对复位态

- GPIO 时钟开启前 PERI_CLKEN=`0`、PERI_RST=`0`。
- 只写一次 `0x4002180C <- 0x00000001`，仅打开 GPIO 时钟；读回验证成功。
- GPIOB ODR=`0`、DIR=`0`、CS_TYPE=`0`、OSOD=`0`、PUPD=`0`、AFR1=`0`、AFR2=`0`。
- IDR 连读三次均为 `0x20`，即 PB2/Pad8=0、PB3/Pad9=0、PB5=1。
- 用户确认示波器测量 Pad8/SCL 一直高。重上电后寄存器回到默认输入/AF0 状态，但输入 IDR 仍与 Pad8 外部电压观测不一致；V105 开漏输出设置读回改变也未让 Pad8 电压下降。
- 目标 MMIO 写次数 1；无 Pad 配置写、I²C 写或事务。
- 日志 SHA256：`A5CE0440B4B35090F8C943A98411C0E87B352B4073C38D685A100E12A63A8316`。

## 当前安全状态

- PERI_CLKEN=`0x00000001`（GPIO 时钟开，I²C 时钟关），PERI_RST=`0`。
- GPIOB Pad8/9 的寄存器处于默认状态：输入、AF1/AF2=0、ODR=0、OSOD=0、PUPD=0。
- V105 曾将 Pad8 配为输出低；方向清回输入的两次 SBA 写入未生效。随后已完全断电重上电，V107 读回 DIR=0，确认输出低状态已经由上电复位清除。
- 未有 V105 示波器自动捕获文件。用户报告 V105 的 1 秒低保持期间也没看到电压下降；本结论采用用户现场观察。

## 当前判断

可确认 GPIOB 方向/ODR/复用寄存器在重上电后恢复默认，时钟门控写入可见；Pad8 的外部高电平与 IDR 采样低仍矛盾。V105 的开漏/DIR 输出配置读回改变，但 Pad8 无低脉冲；DIR 清零写也未读回生效。GPIO 输入采样和输出驱动均未体现 GPIOB[2] 对 Pad8 的控制。两项 GPIO 线索尚未证明 I²C FIFO 卡住的根因。

下一步重点核对流片版 Pad mux/bonding 与手册/ARM 参考映射；不重复驱动 Pad8。本阶段不需要用户重新插拔。
