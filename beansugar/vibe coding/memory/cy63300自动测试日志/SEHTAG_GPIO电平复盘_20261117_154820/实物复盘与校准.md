# GPIO 电平不一致复盘与静态校准

同一 GPIO 标记镜像，用户在 DAPLink 断开并冷启动后测得 H2-3、H2-4 都约 3.3 V。接回 DAPLink、重新上电后，用户测得 H2-3 为 3.3 V、H2-4 为 0 V。两次手持读数来自不同上电和连接条件，不能直接归因于 DAPLink。

| 实物核查 | 结果 |
| --- | --- |
| 烧录镜像 | 两次只读回查 496 字节，与已独立验证的 Flash 镜像一致 |
| GPIO 配置 | CLK_EN=1、RST=0、GPIOC_DIR=3、AFR1/2=0、OSOD=0、PUPD=0 |
| GPIO 数据寄存器 | 两个会话都读到 ODR=3、IDR=3。设计手册说明输出模式下 IDR 反映数据寄存器，不能当作 H2-4 实测电压 |
| CPU 计数 | 两次会话的四轮采样中，第一组、第二组和第二组副本均为 8 |
| SRAM 邮箱 | 第一次首字为预期 `0x52544000`，完成字为 `0x52547000`。之后同步试验在入口检查停止，再次只读时，首字和完成字均为 `0x52547000` |

当前证据不能确定 H2-4 第一次拉高是重复写回路径、标记代码自身、引脚启动状态还是调试读回所致。当前程序未独立验证上电后 H2-4 确实先被拉低；仿真的 GPIO 寄存器读写只是模型。GPIO 实测与 JTAG 回读未得到同时、稳定且通过邮箱校验的一组样本。观察到计数为 8 也不能排除同一值被反复写入。本轮未再次烧录或主动变更 GPIO 配置。

修正后的验证路线先做静态校准。新镜像使用 V151 已验证的开漏低电平驱动方式，配置 H2-3 主动拉低，H2-4 释放为输入、内部上拉。校准镜像不运行计数程序、不访问 SRAM、不读写安全 CSR。2 个外设功能复用寄存器只清除 C0/C1 对应位，其余配置通过掩码保留。Icarus Verilog 在 GPIO 寄存器模型上确认 H2-3 低、H2-4 高，初始化完成后未发生额外写入。实物内部上拉的实际电平尚需万用表确认。

静态镜像长度 136 字节，SHA256 为 `79B6580535DC975F42C9E7F0B2FB42722C2FE23F6BD174EAA1540BA4976CE459`。若开展实物，先核对当前 64 KiB Flash 与 496 字节镜像备份一致，SHA256 `1CF87E6B000EFC9E92F2635FA031FA302645A5F771F21108A583A98A5695ED63`，只擦写首个 512 字节页。断开 DAPLink、OLED、STM32 并冷启动。黑表笔接 H2-2，红表笔分别测 H2-3、H2-4，记录是否为低、高。若校准通过，再按经实测的开漏方式重做独立标记，确认启动阶段有可区分的电平，避免将两脚高直接解释为重复写回。
