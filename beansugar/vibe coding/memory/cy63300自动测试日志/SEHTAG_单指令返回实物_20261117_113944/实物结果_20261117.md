# CY63300 单指令返回对照实物结果

只擦写首个 512 字节启动页，烧入 372 字节候选镜像。64 KiB 整扇区独立读回通过，SHA256 为 `F83AADCF46FA79E0C6D3CA6ED3659EDF7B2F9AD800ABC7583B5A2F7906227BF3`。与上轮扇区的唯一差异为 `0x170–0x173`，把间接 `JALR` 换成同一目标 `0x6C` 的直接 `JAL`。采样会话确认 CPU 为 running，且只读回查的 372 字节启动代码与新镜像完全一致。现场冷启动动作尚未收到用户单独确认。

| 项目 | 本轮实物 |
| --- | --- |
| 第一组计数 | 16 次均为 8 |
| 第二组计数 | 整块及逐字交替 16 次，从 47 增到 1176 |
| 两组的匹配值／退出码 | 均为 `0x53454000 / 0x4D415000` |
| 两组的返回前／后标记 | 均为 `0x52545000 / 0x52546000` |
| 共用完成标记 | 16 次均为 `0x52547000` |

第二组计数按采样顺序为 47、112、211、270、367、423、517、579、681、739、828、888、993、1049、1129、1176。其余字段一致。两种读取均走同一 JTAG 调试链路。重复增长仍然出现，因此在这组条件下，间接返回指令不是出现该异常的必要条件。本轮未操作 SEHTAG 控制寄存器。

下一步建议同时保留原计数字 `0x2000F010`，把同一个 CPU 计数再写入分开的 SRAM 字，保留固定哨兵值。冷启动后优先并排读取原值和副本。如果只有原地址变化，优先调查该字地址、写入或读回。如果两处计数同步增长，优先检查计数生成或重复写回的执行流。
