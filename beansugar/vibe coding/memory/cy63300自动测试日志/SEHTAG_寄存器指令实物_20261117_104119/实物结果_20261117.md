# CY63300 纯寄存器指令对照实物结果

样品为 CJPCBT021-G。擦写前读取的 64 KiB 启动扇区与 SRAM 等待对照备份逐字节一致。本次仅擦写第一个 512 字节页，烧录 196 字节镜像。烧录后的完整启动扇区独立读回与预期一致，SHA256 为 `1C9E931829EC1F340E5CB78059DA377FF0BDB07146CD1F697D9992FB0467FC72`。

用户重新上电后，JTAG 检测到唯一 TAP `riscv.cpu / 0x1E200A6F`，CPU 为 running。整块邮箱 `0x2000F000–0x2000F027` 读取 8 次，每次同时对 10 个字段逐字读取。16 组记录完全一致，全部符合镜像预期。两种命令都经同一 JTAG/调试链路。另读回 196 字节启动代码，与镜像逐字节一致。

| 项目 | 实物结果 |
| --- | --- |
| 源和目标不同的 ADDI +13 | `0x5741600D`，源值保持 `0x57416000` |
| 已稳定源值的原地 ADDI +29 | `0x5741601D` |
| 固定不等输入下，BEQ 不取／BNE 取 | `0x11111000`／`0x22222000` |
| 原地址 `0x94` LUI → `0x98` 原地 ADDI +13 | `0x5741600D` |
| 固定 SRAM 图样／完成标记 | `0x2D5A7000`／`0x53457000` |

这一轮未复现 `0x5741601A`。相同地址的 LUI/ADDI 在纯寄存器对照中正确，但上游指令、条件分支操作数和控制流与之前的 SRAM 等待程序不同。结果覆盖所测指令组合，尚不能定位原异常。未测试 `0x803` 或 SEHTAG 的内存保护。

建议下一轮固定代码布局和比较值，分别用寄存器常量、一次 SRAM 加载以及在该加载与分支之间增加间隔来驱动同一个条件分支。先验证一次执行路径，再加入等待循环，以区分负载相关时序与循环控制流。实物当前保留纯寄存器指令对照镜像。
