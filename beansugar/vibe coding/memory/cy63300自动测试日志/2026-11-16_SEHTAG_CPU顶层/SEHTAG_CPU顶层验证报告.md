# SEHTAG CPU 顶层访存保护验证

日期 2026-11-16。使用 Icarus Verilog 12.0，读取 Repo_Fanglongrui 的 main 分支提交 189fff578a44b61a328af08e32e60ac890b19a91。仓库源文件未修改。未连接实物。

## 仿真结果

实例化仓库 CPU 顶层 tinyriscv，在测试台提供已确定的抽象检查结果和普通访存输入。顶层的 RIB 请求与写使能接到单字模拟存储，检查接受次数、存储内容和实际 mcause 寄存器。

- PASS，允许时顶层输出请求和写使能，模型接受一次写入，读到新值，mcause 为零。
- PASS，拒绝时顶层请求与写使能为零，模型接受次数不增加，内容保持原样，mcause 读到 0x5。

此台验证了检查结果已确定后的执行级、顶层选择与 CSR 路径。测试台注入检查结果，未测 BnBCache 在途查询，也未接真实 RIB 仲裁和 SRAM。

## 时序审查

bnbcache.v 第 326 行起在时钟上升沿更新 check_valid_o。ex.v 第 236–237 行则组合产生访存请求和写使能，tinyriscv.v 第 466–476 行将相应通路选到 CPU 总线口。在已核对的这段接口上未看到明确区分「本次检查待完成」和「本次检查通过」的握手。当前阶段将真实检查时序标为待核，不能据此判定实际芯片是否提前提交。

建议与 RTL 作者确认本次请求与检查结果如何绑定，以及总线何时允许接受。验收条件为：待判定期间不提交，允许只提交一次，拒绝不提交并产生对应异常。
