# CY63300 有界等待计数的暂停对照

使用同一份 SRAM 有界等待镜像和同一次 JTAG 会话对照 CPU 运行、暂停前后的邮箱。JTAG 识别唯一 TAP `riscv.cpu / 0x1E200A6F`。发出一次 `halt 2000`，OpenOCD 确认 halted，DMSTATUS 由 `0x00430C82` 变为 `0x00430382`。本次会话没有写目标内存、修改 Flash、复位或恢复 CPU。

| CPU 状态 | 整块邮箱中 `0x2000F010` | 单字读取 `0x2000F010` |
| --- | --- | --- |
| running | 24、75、126、178、224、275、323、379 | 46、96、148、198、243、297、349、400 |
| halted | 8 次均为 433（`0x1B1`） | 8 次均为 433（`0x1B1`） |

运行期间按实际交替读取顺序的 16 个样本严格递增，暂停后全部相同。其余邮箱字在两种 CPU 状态下均相同，完成标记始终是 `0x4C576000`。两种命令均走同一个 JTAG 调试链路。计数变化与 CPU 运行状态有关，优先检查实际执行流和计数写回。调试访问与 CPU 运行并发所致的异常仍是候选。

上轮会话末为 1135，新会话首样本为 24，不能把两次会话拼成一个连续递增序列。三次 `reg pc force` 报告 `0x2C006DD3`，超出镜像地址范围，无法据此确定停在哪条指令。

下一项建议保持相同数据路径，分别用直接跳转和间接返回结束变值组。将返回前、完成标记前和终止路径分开记录，比较完成后是否还有计数字写回。本轮没有验证 SEHTAG 的内存保护能力。样品保持 halted。
