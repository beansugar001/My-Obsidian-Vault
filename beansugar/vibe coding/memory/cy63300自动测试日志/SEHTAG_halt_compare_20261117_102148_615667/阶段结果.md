# CY63300 运行与暂停下的 SRAM 读回对照

在同一次 JTAG 会话中分别读取运行态和暂停态。运行态 DMSTATUS 为 `0x00430C82`。一次 `halt 2000` 后，OpenOCD 确认为 halted，DMSTATUS 为 `0x00430382`。本轮未发送目标内存写入、恢复运行或复位命令。

| CPU 状态 | 32 字节邮箱读回 | 单字读取状态字 |
| --- | --- | --- |
| running | 8/8 完全相同 | 8/8 为 `0x5741601A` |
| halted | 8/8 完全相同，与 running 的样本一致 | 8/8 为 `0x5741601A` |

对应邮箱的首次及退出读值均为 0，比较值为 `0x53454152`，退出路径为 2，异或为 `0x53454152`。`0x5741601A` 超出固件定义的状态值。上一轮状态波动未在本会话复现，且 Halt 前已经稳定，因此无法用本轮数据判断上一轮波动是否由 CPU 重复写回造成。

反汇编中，成功路径先在 `0x94` 将 `0x57416000` 装入 t1，再在 `0x98` 执行一次 `addi t1,t1,13`。观测到的状态字恰好等于底值加两次 13。它是后续检查指令重复效果的线索。寄存器值、Flash 取指、SRAM 写入和调试读回仍是不同候选来源。

三次 `reg pc force` 均报告 `0x2C026DD3`，无法映射到探针指令地址，不能用它定位当前停在哪条指令。首次 SBCS 为 `0x20040404`，读内存后报告 `0x00150000`，两种 CPU 状态下均无脚本检查掩码内的 busy/error 位。这个状态变化同样保留在原始日志中。

建议下一步做只操作专用 SRAM 的纯寄存器指令对照。先验证独立源寄存器的 ADDI 与原地 ADDI，再验证取和不取的条件分支。另用独立读事务核对固定图样，判断异常来自生成或传输。样品留在暂停状态。
