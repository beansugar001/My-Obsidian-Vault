## 11. 注意力机制

### 11.1 注意力的动机

早期 Seq2Seq 模型通常把整个输入句子压缩成一个固定长度向量，再由 decoder 生成输出。这个设计有明显瓶颈：

- 输入越长，固定向量越难保存全部信息。
- decoder 生成每个 token 时都依赖同一个压缩表示。
- 翻译、摘要等任务中，输出位置往往需要关注输入的不同部分。

注意力机制的核心思想是：

> 生成当前 token 时，模型不必只依赖一个固定向量，而是可以动态查看输入序列的所有位置，并决定当前最应该关注哪里。

例如翻译 `I love natural language processing`：

- 生成“我”时关注 `I`。
- 生成“喜欢”时关注 `love`。
- 生成“自然语言处理”时关注 `natural language processing`。

注意力机制因此解决了两个问题：

- 缓解长句信息压缩问题。
- 学习源序列和目标序列之间的软对齐关系。

### 11.2 Query、Key、Value

现代注意力通常用 Query、Key、Value 描述。

- **Query, Q**：当前要查询的信息，表示“我现在需要什么”。
- **Key, K**：每个位置的索引特征，表示“我这里有什么可匹配的特征”。
- **Value, V**：每个位置真正被读取的信息，表示“如果关注我，就取走这些内容”。

Scaled Dot-Product Attention 的公式是：

$$
\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

解释：

1. $QK^T$：计算 query 和所有 key 的相似度。
2. $\sqrt{d_k}$：缩放因子，防止点积过大导致 softmax 饱和。
3. $\operatorname{softmax}$：把相似度变成注意力权重。
4. 乘以 $V$：按权重对 value 加权求和，得到当前输出。

### 11.3 为什么要除以 $\sqrt{d_k}$

如果 key/query 维度 $d_k$ 很大，点积 $QK^T$ 的数值方差会变大。softmax 输入过大时，会让概率分布过于尖锐，梯度变小，训练不稳定。

除以 $\sqrt{d_k}$ 可以让点积分布更稳定，使 softmax 不容易饱和。

### 11.4 Self-Attention

Self-attention 指 Q、K、V 都来自同一个序列。每个 token 都可以关注序列中其他 token。

例如句子：

```text
The animal didn't cross the street because it was tired.
```

模型需要判断 `it` 指代 `animal`。Self-attention 允许 `it` 直接关注 `animal`，而不必像 RNN 那样经过很多时间步传递信息。

Self-attention 的优点：

- 任意两个 token 可直接建立联系。
- 比 RNN 更容易捕捉长距离依赖。
- 可并行处理整个序列。
- 是 Transformer 的核心。

缺点：

- 标准 self-attention 复杂度为 $O(n^2)$。
- 长上下文时显存和计算成本很高。

## 12. Transformer

### 12.1 Transformer 的核心思想

Transformer 用 self-attention 替代 RNN 的顺序递推结构。它不再一个 token 一个 token 地读序列，而是一次性处理整个序列，并让 token 之间通过注意力直接交互。

核心组件包括：

- Token embedding
- Positional encoding / positional embedding
- Multi-head self-attention
- Feed-forward network
- Residual connection
- Layer normalization
- Dropout

### 12.2 Multi-Head Attention

单头注意力只在一个表示空间中计算 token 关系。Multi-head attention 将表示分成多个子空间，让不同 head 学习不同关系。

可能的注意力模式包括：

- 某些 head 关注相邻词。
- 某些 head 关注句法依赖。
- 某些 head 关注指代关系。
- 某些 head 关注分隔符、标点或特殊 token。

多头注意力的流程：

1. 将输入线性变换为多组 Q、K、V。
2. 每个 head 独立计算 attention。
3. 拼接所有 head 的输出。
4. 再经过线性变换得到最终表示。

优点：模型可以从多个角度同时理解序列关系。

### 12.3 位置编码

Self-attention 本身不包含顺序信息。如果不加入位置编码，模型无法区分：

```text
I love you
```

和：

```text
you love I
```

因此 Transformer 需要显式注入位置信息。

常见位置编码：

- **正弦/余弦位置编码**：原始 Transformer 使用，可外推到较长序列。
- **可学习位置嵌入**：把位置当作可训练参数。
- **相对位置编码**：关注 token 间相对距离。
- **RoPE**：旋转位置编码，常见于现代 LLM。

### 12.4 Feed-Forward Network

Transformer 每层除了 attention，还有逐位置前馈网络：

$$
\operatorname{FFN}(x)=W_2\operatorname{activation}(W_1x+b_1)+b_2
$$

它对每个 token 独立应用，作用是进行非线性特征变换。Attention 负责 token 间信息交换，FFN 负责对每个位置的表示进行加工。

### 12.5 Residual Connection 与 LayerNorm

残差连接形式为：

$$
x+\operatorname{sublayer}(x)
$$

作用：

- 改善梯度传播。
- 保留原始信息。
- 让深层网络更容易训练。

LayerNorm 对隐藏维度做归一化，稳定训练。常见两种结构：

- **Post-LN**：先 sublayer，再 residual，再 LayerNorm。
- **Pre-LN**：先 LayerNorm，再 sublayer，再 residual。

现代大模型多使用 Pre-LN，因为深层训练更稳定。

### 12.6 Transformer 三种范式

#### Encoder-only

代表：BERT。

特点：

- 双向上下文。
- 每个 token 可看左右两侧。
- 适合理解、分类、抽取、检索。

典型任务：情感分析、命名实体识别、句子相似度、阅读理解答案抽取。

#### Decoder-only

代表：GPT 系列。

特点：

- 使用 causal mask。
- 每个 token 只能看左侧历史。
- 根据前文预测下一个 token。
- 当前 LLM 主流架构。

适合任务：对话、续写、代码生成、问答、Agent 工具调用。

#### Encoder-Decoder

代表：原始 Transformer 翻译模型、T5。

特点：

- Encoder 双向编码输入。
- Decoder 自回归生成输出。
- Decoder 通过 cross-attention 关注 encoder 表示。

适合任务：翻译、摘要、改写、语法纠错。

### 12.7 Transformer 为什么取代 RNN

主要原因：

- **并行性更强**：RNN 必须顺序计算，Transformer 可并行处理序列。
- **长距离依赖更直接**：self-attention 让任意位置直接交互。
- **扩展性更好**：更适合大规模数据、大模型和分布式训练。
- **预训练效果更强**：Transformer 成为 BERT、GPT、T5 等模型的基础。

## 13. 预训练

### 13.1 预训练的基本思想

预训练是先在大规模无标注文本上训练通用语言模型，再把模型迁移到下游任务。

原因：

- 标注数据昂贵。
- 无标注文本丰富。
- 语言知识具有迁移性。
- 大模型可通过预训练学习语法、语义、事实、风格和部分推理模式。

预训练 + 微调/提示 是现代 NLP 的核心范式。

### 13.2 Causal Language Modeling

Causal LM 根据左侧上下文预测下一个 token：

$$
P(x_t\mid x_1,\ldots,x_{t-1})
$$

它使用因果 mask，禁止模型看到未来 token。GPT 类模型采用这种目标。

优点：

- 训练目标和生成过程一致。
- 非常适合开放式文本生成。
- 可自然扩展为对话、代码、工具调用等任务。

局限：

- 只能从左到右建模。
- 对纯理解类任务，有时不如双向 encoder 表示直接。

### 13.3 Masked Language Modeling

Masked LM 随机遮住输入中的部分 token，让模型根据左右上下文预测被遮住的 token。

例子：

```text
I love [MASK] language processing.
```

模型要预测 `[MASK] = natural`。

BERT 使用这种目标。

优点：

- 能利用双向上下文。
- 适合理解任务和表示学习。

局限：

- 预训练中的 `[MASK]` token 在下游真实输入中通常不存在。
- 不天然适合自回归生成。

### 13.4 Contextual Word Representations

静态词向量中，一个词只有一个固定向量。上下文表示中，同一个词在不同语境中会有不同表示。

例如：

- `river bank` 中的 `bank` 表示河岸。
- `bank account` 中的 `bank` 表示银行。

上下文表示解决了一词多义问题，是 ELMo、BERT、GPT 等模型的重要能力。

### 13.5 Scaling Laws

Scaling laws 描述模型性能随参数量、数据量和计算量扩大而提升的规律。

主要因素：

- 参数量
- 训练 token 数
- 计算量
- 数据质量
- 模型结构

但扩展不是无限免费的：

- 训练成本高。
- 数据污染风险增加。
- 推理延迟和显存成本上升。
- 安全、偏见、版权和隐私问题更复杂。

### 13.6 预训练工程

预训练是系统工程，不只是模型公式。

关键环节：

- 数据收集、清洗、去重。
- 低质量、重复、敏感和有害内容过滤。
- tokenizer 训练。
- 分布式训练。
- 混合精度和梯度累积。
- checkpoint 保存与恢复。
- 训练稳定性监控。
- benchmark 数据污染检测。

## 14. 后训练：SFT、RLHF、DPO

### 14.1 为什么需要后训练

预训练模型只学会“预测文本”，不一定会：

- 按用户指令回答。
- 保持对话格式。
- 拒绝危险请求。
- 给出清晰、简洁、有帮助的答案。
- 遵循人类偏好。

后训练的目标是把基础语言模型变成更可用、更安全、更符合人类偏好的助手。

### 14.2 SFT 指令微调

SFT（Supervised Fine-Tuning）使用高质量指令-回答数据继续训练模型。

数据形式：

```text
Instruction -> Response
```

作用：

- 让模型学会听指令。
- 学会问答和对话格式。
- 学会特定任务风格。
- 让输出更符合人类示范。

局限：

- 强依赖示范数据质量。
- 只能模仿示范，难以直接优化偏好排序。
- 数据覆盖不到的场景仍可能表现不佳。

### 14.3 RLHF

RLHF 是 Reinforcement Learning from Human Feedback。

典型流程：

1. 对同一 prompt 生成多个回答。
2. 人类比较回答优劣。
3. 用偏好数据训练 reward model。
4. 用强化学习优化语言模型，使其获得更高 reward。

常见优化算法：PPO。

优点：

- 能直接利用人类偏好。
- 可优化有用性、礼貌性、安全性等难以写成明确标签的目标。

问题：

- 训练流程复杂。
- reward model 可能被模型利用漏洞。
- 强化学习不稳定。
- 人类偏好本身可能不一致或有偏见。

### 14.4 DPO

DPO（Direct Preference Optimization）直接用偏好对训练模型，不显式训练 reward model，也不需要复杂 RL。

偏好数据形式：

```text
prompt, chosen response, rejected response
```

DPO 的直觉：

- 提高 chosen response 的概率。
- 降低 rejected response 的概率。
- 同时约束模型不要偏离参考模型太远。

优点：

- 实现更简单。
- 训练更稳定。
- 成本通常低于 RLHF。

### 14.5 SFT、RLHF、DPO 对比

| 方法 | 数据 | 核心目标 | 优点 | 局限 |
|---|---|---|---|---|
| SFT | 指令-答案 | 模仿高质量示范 | 简单稳定 | 不直接优化偏好 |
| RLHF | 人类偏好排序 | 用 reward 优化人类偏好 | 偏好建模强 | 流程复杂、不稳定 |
| DPO | 偏好对 | 直接优化 chosen vs rejected | 简洁稳定 | 依赖偏好数据质量 |

### 14.6 对齐的局限

后训练不能完全消除：

- 幻觉。
- 偏见。
- 安全绕过。
- 过度迎合。
- 复杂推理错误。
- 数据覆盖不足导致的失败。

对齐应与评测、RAG、工具验证、权限控制和人工审核结合。

## 15. Prompting 与高效适配

### 15.1 Prompting

Prompting 是通过设计输入提示来控制模型行为，不更新模型参数。

常见方式：

- **Zero-shot**：不给示例，直接让模型完成任务。
- **Few-shot**：给若干输入输出示例。
- **Chain-of-thought**：引导模型写出中间推理步骤。
- **Role prompting**：指定角色或身份。
- **Structured prompting**：要求输出 JSON、表格、步骤等结构。

好的 prompt 通常包含：

- 任务目标。
- 必要背景。
- 输入数据。
- 输出格式。
- 约束条件。
- 示例。
- 评价标准。

### 15.2 Prompting 的局限

Prompting 不改变模型参数，因此：

- 对稳定性要求高的任务可能不够可靠。
- 对复杂领域格式的长期适配有限。
- 容易受提示措辞影响。
- 上下文长度有限。
- 不适合注入大量永久性知识。

### 15.3 PEFT 参数高效微调

PEFT（Parameter-Efficient Fine-Tuning）指只训练少量新增或局部参数，而不是全量更新大模型。

动机：

- 全量微调显存和算力成本高。
- 多任务部署时保存多个全量模型成本大。
- 小规模任务全量微调容易过拟合。

常见 PEFT 方法：

- Prompt tuning
- Prefix tuning
- Adapter
- LoRA

### 15.4 LoRA

LoRA（Low-Rank Adaptation）冻结原模型权重，只训练低秩增量。

若原始权重更新为：

$$
W+\Delta W
$$

LoRA 将增量分解为低秩矩阵乘积：

$$
\Delta W=AB
$$

其中 $A$ 和 $B$ 的秩远小于原矩阵维度。

优点：

- 训练参数少。
- 显存需求低。
- 可为不同任务保存不同 LoRA 权重。
- 便于组合、加载和部署。

局限：

- rank 选择影响效果。
- 对非常复杂或大幅改变模型能力的任务可能不如全量微调。
- 目标模块选择很重要，如 attention projection 或 FFN 层。

### 15.5 Prompting、RAG、Fine-tuning 的区别

| 方法 | 是否改参数 | 适合解决 | 不适合 |
|---|---|---|---|
| Prompting | 否 | 临时任务控制、格式要求 | 稳定长期适配 |
| RAG | 否 | 外部知识、可更新知识、可溯源问答 | 改变模型风格和能力 |
| Fine-tuning/PEFT | 是 | 学习格式、风格、任务模式 | 注入大量频繁变化事实 |

## 16. RAG：检索增强生成

### 16.1 RAG 的动机

语言模型参数中的知识可能：

- 过时。
- 不完整。
- 不可溯源。
- 对私有知识不了解。
- 在不确定时产生幻觉。

RAG（Retrieval-Augmented Generation）通过检索外部文档，让模型基于检索结果回答问题。

基本流程：

1. 用户提出问题。
2. 系统将问题转为检索查询。
3. 从文档库中检索相关片段。
4. 将片段放入模型上下文。
5. 模型基于上下文生成回答。

### 16.2 RAG 系统组件

典型 RAG 包括：

- 文档加载器：读取 PDF、网页、Markdown、数据库等。
- 文本切分：将长文档切成 chunk。
- Embedding 模型：把 query 和 chunk 转成向量。
- 向量数据库：存储和检索向量。
- Retriever：召回相关 chunk。
- Reranker：对候选结果重新排序。
- Generator：基于检索上下文生成答案。
- Citation：给出来源引用。

### 16.3 Chunking

Chunking 是 RAG 成败关键之一。

需要权衡：

- chunk 太小：上下文不完整，语义断裂。
- chunk 太大：检索噪声增加，占用上下文窗口。
- overlap 太小：跨段信息丢失。
- overlap 太大：重复内容多，成本上升。

好的 chunk 应尽量保持语义完整，例如按标题、段落、列表、代码块或页面结构切分。

### 16.4 检索方式

常见检索方式：

- **Sparse retrieval**：如 BM25，擅长关键词精确匹配。
- **Dense retrieval**：基于 embedding，擅长语义相似。
- **Hybrid retrieval**：结合关键词和向量检索。
- **Reranking**：用更强模型对召回结果重排，提高精度。

### 16.5 RAG 的评估

RAG 不只评估最终答案，还要评估检索链路。

关键指标：

- Context recall：相关证据是否被检索到。
- Context precision：检索内容是否足够相关。
- Faithfulness：答案是否忠实于检索证据。
- Answer correctness：答案是否正确。
- Citation accuracy：引用是否真实支持答案。

### 16.6 RAG 的局限

- 检索不到正确证据，生成难以正确。
- 检索内容过多会干扰模型。
- 文档切分不当会破坏语义。
- 模型可能忽略证据或编造引用。
- 外部文档可能包含 prompt injection。

## 17. Agent 与工具调用

### 17.1 Agent 的定义

Agent 是能围绕目标进行规划、调用工具、观察结果并继续行动的模型系统。

典型循环：

```text
Plan / Thought -> Action -> Observation -> Next Action -> Final Answer
```

普通聊天模型主要生成文本；Agent 能与外部环境交互。

### 17.2 Tool Use

工具可以包括：

- 搜索引擎
- 计算器
- 代码执行器
- 数据库
- 浏览器
- 文件系统
- 邮件、日历、表格
- 企业 API

工具调用价值：

- 获取实时信息。
- 执行精确计算。
- 访问私有数据。
- 完成外部操作。
- 弥补模型参数知识不足。

### 17.3 ReAct

ReAct 将 reasoning 和 acting 结合。

- Reasoning：模型判断下一步需要什么。
- Acting：模型调用工具获取信息或执行操作。
- Observation：模型读取工具结果并继续决策。

这种模式让模型可以边想边查，而不是一次性凭记忆回答。

### 17.4 Agent 的核心难点

Agent 系统比单轮问答更难，因为它涉及多步决策。

难点：

- 任务分解是否合理。
- 工具选择是否正确。
- 工具参数是否准确。
- 中间错误会累积。
- 长任务容易偏离目标。
- 需要状态管理和记忆机制。
- 需要权限控制和用户确认。

### 17.5 Agent 风险

Agent 能采取外部行动，因此风险更高：

- 删除、发送、购买、提交等操作可能造成真实后果。
- 外部网页或文档可能注入恶意指令。
- 工具返回内容可能不可信。
- 模型可能误解用户意图。
- 权限过大时风险放大。

防护原则：

- 最小权限。
- 高风险操作前确认。
- 工具调用可审计。
- 区分系统指令、用户指令和外部内容。
- 对敏感数据做隔离和过滤。

## 18. Benchmarking 与 Evaluation

### 18.1 为什么 LLM 评测困难

大语言模型输出开放、任务多样，很难用单一指标衡量。

困难包括：

- 开放式回答没有唯一标准答案。
- 自动指标和人类偏好不完全一致。
- benchmark 可能被训练数据污染。
- 模型可能针对排行榜过拟合。
- 能力维度很多：知识、推理、代码、安全、鲁棒性、事实性等。

### 18.2 传统 NLP 指标

常见指标：

- **Accuracy**：分类正确率。
- **Precision**：预测为正的样本中有多少是真的正。
- **Recall**：真实为正的样本中有多少被找出来。
- **F1**：precision 和 recall 的调和平均。
- **BLEU**：机器翻译中常用，基于 n-gram overlap。
- **ROUGE**：摘要中常用，衡量与参考摘要的重叠。
- **Perplexity**：衡量语言模型预测下一个 token 的能力。

局限：这些指标往往只覆盖局部能力，不代表整体使用体验。

### 18.3 LLM Benchmark

常见 benchmark 类型：

- 知识问答：测试事实和学科知识。
- 推理：数学、多跳、逻辑。
- 代码：生成、修复、解释代码。
- 指令跟随：是否按要求完成任务。
- 安全：是否拒绝危险请求。
- 偏好评测：回答是否更符合人类偏好。

常见 benchmark：

- MMLU
- HELM
- AlpacaEval
- RewardBench
- GSM8K
- HumanEval

### 18.4 人工评测

人工评测更接近真实体验，但成本高、主观性强。

好的人工评测需要：

- 明确评分标准。
- 多个标注者。
- 盲评和随机化。
- 一致性检验。
- 记录失败案例。

### 18.5 评测维度

完整评测应覆盖：

- 正确性
- 事实性
- 有用性
- 指令遵循
- 鲁棒性
- 安全性
- 偏见
- 延迟
- 成本
- 可解释性
- 数据泄漏风险

### 18.6 评测陷阱

常见陷阱：

- 只看排行榜分数。
- 忽略实际业务场景。
- 使用污染过的测试集。
- 只测平均表现，不看失败模式。
- 只测英文或高资源语言。
- 不测安全和边界情况。

## 19. Reasoning 推理能力

### 19.1 LLM 推理是什么

LLM 推理指模型在数学、代码、逻辑、多步问答和规划任务中进行中间思考并得出答案的能力。

需要注意：LLM 的推理能力不等同于形式逻辑系统。它可能生成看似合理的步骤，但结论错误。

常见失败：

- 漏看题目条件。
- 中间计算错误。
- 逻辑跳步。
- 编造不存在的前提。
- 被提示措辞误导。

### 19.2 Chain-of-Thought

Chain-of-Thought（CoT）通过让模型写出中间推理步骤来提升复杂任务表现。

适合任务：

- 数学应用题
- 多跳问答
- 逻辑推理
- 复杂规划
- 代码解释

CoT 有效的原因：

- 将复杂问题分解为多个简单步骤。
- 增加中间计算空间。
- 降低一步到答案的难度。

但 CoT 不保证正确。模型可能写出流畅但错误的推理过程。

### 19.3 Self-Consistency

Self-consistency 让模型采样多条推理路径，再通过投票或一致性选择最终答案。

优点：

- 减少单条推理路径的偶然错误。
- 提升数学和多步推理稳定性。

缺点：

- 成本增加。
- 多数答案不一定正确。
- 如果模型系统性误解题目，多采样也未必有用。

### 19.4 Test-Time Compute

Test-time compute 指在推理阶段投入更多计算来提升答案质量。

方式包括：

- 多次采样。
- 搜索不同解法。
- 用验证器筛选答案。
- 分步检查。
- 让模型反思和修正。
- 工具辅助计算。

核心思想：**模型能力不仅取决于参数和训练，也取决于推理时给多少计算预算**。

### 19.5 Verifier

Verifier 是用于判断候选答案或推理步骤是否正确的模型或程序。

用途：

- 数学题验证最终答案。
- 代码题运行测试。
- 多个候选答案排序。
- 检查推理链中的错误步骤。

在可验证任务中，生成器 + 验证器通常比单独生成更可靠。

### 19.6 Speculative Decoding

Speculative decoding 用小模型先快速生成候选 token，再由大模型验证。

目标：

- 提高推理速度。
- 降低延迟。
- 尽量保持大模型输出分布不变。

它主要解决效率问题，不直接提升模型推理能力。

## 20. Tokenization 与多语种

### 20.1 Tokenization 的作用

Tokenizer 将原始文本切分为模型可处理的 token。

模型并不直接处理字符或词，而是处理 token id。Tokenization 会影响：

- 序列长度。
- 上下文窗口利用率。
- 训练和推理成本。
- 多语种公平性。
- 罕见词和特殊符号处理。

### 20.2 常见切分粒度

- **字符级**：粒度小，词表小，但序列长。
- **词级**：语义直观，但词表巨大，OOV 问题严重。
- **子词级**：在词和字符之间折中，是现代 NLP 主流。
- **Byte-level**：基于字节，几乎可覆盖任意文本。

### 20.3 BPE

BPE（Byte Pair Encoding）常用于训练子词词表。

基本流程：

1. 初始单位为字符或字节。
2. 统计最常见的相邻单位对。
3. 合并该单位对形成新 token。
4. 重复直到达到词表大小。

优点：

- 能处理未登录词。
- 高频词可用较短 token 表示。
- 低频词可拆成子词。
- 适合开放词表场景。

### 20.4 Tokenizer 对模型的影响

Tokenizer 不是中性工具，它会影响模型表现。

例如：

- 同一句中文可能比英文被切成更多或更少 token。
- 数学表达、代码、URL、表情符号可能被切得很碎。
- 低资源语言可能 token 效率较差。
- token 数不同会影响上下文窗口和 API 成本。

因此比较模型 perplexity、成本或上下文能力时，要考虑 tokenizer 差异。

### 20.5 多语种 NLP

多语种模型希望一个模型处理多种语言，并在语言之间迁移能力。

挑战：

- 高资源语言数据多，低资源语言数据少。
- 不同语言形态差异大，如中文无空格、德语复合词、阿拉伯语形态丰富。
- tokenizer 对不同语言效率不均。
- 文化、语境和知识分布不同。
- benchmark 常偏向英文。

### 20.6 跨语言迁移

跨语言迁移指模型在高资源语言上学到的能力能迁移到低资源语言。

常见方式：

- 共享子词词表。
- 多语种预训练。
- 平行语料对齐。
- 翻译增强数据。
- 跨语言 embedding 对齐。

局限：

- 迁移效果对语言相似性敏感。
- 低资源语言可能被高资源语言压制。
- 文化和地域知识难以简单迁移。

### 20.7 多语种评测

评估多语种模型时，应关注：

- 是否只在英文表现好。
- 低资源语言效果如何。
- 翻译任务和原生语言任务是否都测试。
- tokenizer 是否导致某些语言成本更高。
- 模型是否理解文化语境，而不是机械翻译。

## 后10章知识主线总结

第 11-20 章的主线可以概括为：

```text
Attention 解决动态对齐和长距离依赖
  -> Transformer 用 self-attention 构建可并行的大规模序列模型
  -> 预训练让模型从海量文本中学习通用语言能力
  -> 后训练让模型更会听指令、更符合人类偏好
  -> Prompting、PEFT、RAG、Agent 让模型变成可适配、可检索、可行动的系统
  -> Evaluation、Reasoning、Tokenization、多语种决定模型能否可靠、公平、高效地使用
```

一句话总结：

> 前 10 章让你理解神经 NLP 如何建模语言；后 10 章让你理解现代 LLM 如何被训练、适配、评测并组成可用系统。
