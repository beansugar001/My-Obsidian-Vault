> 目标：快速建立 STM32F103C8T6 的完整知识框架，先掌握主线与工程思维，再进入 Keil5 + 标准外设库实战。

# 0. 总体知识地图

STM32F103C8T6 可以理解为一台“面向硬件控制的小型计算机”：

```text
STM32F103C8T6
│
├── CPU：ARM Cortex-M3
├── Flash：存程序，掉电不丢
├── SRAM：存运行时数据，掉电丢失
├── GPIO：输入/输出数字电平
├── EXTI：外部中断
├── NVIC：中断调度
├── Timer：定时/计数/PWM
├── USART：串口通信
├── I2C：两线多设备通信
├── SPI：高速同步通信
├── CAN：多节点高可靠差分总线
├── ADC：模拟量转数字量
├── Watchdog：程序失控自动复位
├── RTC：实时时钟/低功耗唤醒
└── DMA：自动搬运数据
```

STM32 外设学习最通用的套路：

```text
1. 开时钟
2. 配 GPIO
3. 配外设
4. 使能外设
5. 读/写数据
6. 如有需要，配置中断
7. 中断完成后清标志
```

拿到一个新外设时，优先问自己：

```text
① 时钟在哪里开？
② GPIO 怎么配置？
③ 外设参数有哪些？
④ 怎么使能？
⑤ 怎么读/写数据？
⑥ 有没有中断？
⑦ 中断标志怎么清？
```

# 1. STM32 基础

## 1.1 MCU 是什么

MCU = Microcontroller Unit，微控制器。

它将 CPU、存储器和各种外设集成在一颗芯片中，特别适合实时控制：

```text
读取按键
↓
判断状态
↓
控制 LED / 电机 / 继电器
```

STM32F103C8T6 使用 ARM Cortex-M3 内核。

---

## 1.2 Flash 与 SRAM

### Flash

作用：

- 存程序代码
- 存常量
- 掉电不丢失

流程：

```text
C代码
↓
Keil编译
↓
机器码
↓
ST-Link下载
↓
写入Flash
↓
CPU执行
```

### SRAM

作用：

- 存变量
- 存数组
- 存栈
- 存堆
- 存临时运行数据

特点：

> 掉电数据丢失。

记忆：

```text
Flash = 长期保存
SRAM  = 临时运行
```

---

## 1.3 main() 为什么常有 while(1)

嵌入式设备通常不会“运行完就退出”，而是持续工作：

```c
int main(void)
{
    while (1)
    {
        // 持续读取、判断、控制
    }
}
```

所以 MCU 常见模式是：

```text
开机
↓
初始化
↓
进入主循环
↓
持续运行
```

---

## 1.4 RCC 与时钟

RCC = Reset and Clock Control。

可以理解成 STM32 的时钟分配中心。

大多数外设使用前，都需要先开对应时钟：

```text
开时钟
↓
配置外设
↓
使用外设
```

时钟不是“北京时间”，而是周期电信号：

```text
__    __    __    __
  |__|  |__|  |__|
```

STM32F103 常见系统主频可到 72MHz。

---

## 1.5 ST-Link

ST-Link 主要用于：

- 下载程序
- 在线调试
- 单步执行
- 断点
- 查看变量

典型链路：

```text
电脑
↓
USB
↓
ST-Link
↓
SWD
↓
STM32
```

---

# 2. GPIO 输出与 LED

## 2.1 GPIO 是什么

GPIO = General Purpose Input Output，通用输入输出。

例如：

```text
PA0 = GPIOA 第0号引脚
PB5 = GPIOB 第5号引脚
PC13 = GPIOC 第13号引脚
```

GPIO 两个最基本方向：

- 输入
- 输出

---

## 2.2 GPIO 输出高低电平

可以近似理解：

```text
GPIO = 1 ≈ 3.3V
GPIO = 0 ≈ 0V
```

所以嵌入式控制的本质链路是：

```text
软件修改寄存器
↓
GPIO电平改变
↓
真实硬件状态改变
```

---

## 2.3 LED 为什么有“高电平亮”和“低电平亮”

### 高电平点亮

```text
GPIO ── 电阻 ── LED ── GND
```

则：

```text
GPIO=1 → LED亮
GPIO=0 → LED灭
```

### 低电平点亮

```text
3.3V
 │
电阻
 │
LED
 │
GPIO
```

此时：

```text
GPIO=0 → LED亮
GPIO=1 → LED灭
```

因为 GPIO=0 时形成：

```text
3.3V → 电阻 → LED → GPIO → GND
```

这叫 Active Low，低电平有效。

---

## 2.4 推挽输出与开漏输出

### 推挽输出 Push-Pull

特点：

> 能主动拉高，也能主动拉低。

```text
输出1 → 主动输出高电平
输出0 → 主动输出低电平
```

常用于：

- LED
- 蜂鸣器
- 普通数字控制

常见标准库模式：

```c
GPIO_Mode_Out_PP
```

### 开漏输出 Open-Drain

特点：

> 只能主动拉低，不能主动拉高。

高电平通常依赖：

> 上拉电阻。

常用于：

- I2C
- 多设备共享总线
- 某些电平转换场景

常见模式：

```c
GPIO_Mode_Out_OD
```

一句话：

> 推挽能推也能拉；开漏主要负责往下拉。

---

## 2.5 上拉、下拉、悬空

### 上拉

```text
3.3V
 │
电阻
 │
GPIO
```

默认：

```text
GPIO = 1
```

### 下拉

```text
GPIO
 │
电阻
 │
GND
```

默认：

```text
GPIO = 0
```

### 悬空

如果输入引脚既没有明确高电平也没有明确低电平：

```text
GPIO ─── 空着
```

它的电平会受干扰影响，可能随机变化。

所以：

> 悬空不是“0V”，而是“状态不确定”。

---

## 2.6 点亮 LED 的基本流程

```text
开 GPIO 时钟
↓
配置 GPIO 为输出
↓
设置输出电平
```

典型标准库代码结构：

```c
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE);

GPIO_InitTypeDef GPIO_InitStructure;

GPIO_InitStructure.GPIO_Pin = GPIO_Pin_13;
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;
GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;

GPIO_Init(GPIOC, &GPIO_InitStructure);
```

输出：

```c
GPIO_SetBits(GPIOC, GPIO_Pin_13);    // 置1
GPIO_ResetBits(GPIOC, GPIO_Pin_13);  // 清0
```

# 3. GPIO 输入、按键与消抖

## 3.1 GPIO 输入本质

GPIO 输入是在判断外部电压：

```text
接近高电平 → 1
接近低电平 → 0
```

---

## 3.2 常见按键接法

```text
3.3V
 │
上拉电阻
 │
PA0
 │
按键
 │
GND
```

所以：

```text
没按 = 1
按下 = 0
```

常见代码：

```c
if (GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_0) == 0)
{
    // 按键按下
}
```

标准库输入模式：

```c
GPIO_Mode_IPU   // 上拉输入
GPIO_Mode_IPD   // 下拉输入
GPIO_Mode_IN_FLOATING // 浮空输入
```

---

## 3.3 按键抖动

真实机械按键不会瞬间稳定：

```text
理想：
111111000000

真实：
111010100000
```

一次按键可能被 MCU 识别成多次变化。

这叫：

> Debounce，按键消抖。

---

## 3.4 软件消抖

经典流程：

```text
第一次检测按下
↓
延时约20ms
↓
第二次确认
↓
确认有效
```

示例：

```c
if (KEY == 0)
{
    Delay_ms(20);

    if (KEY == 0)
    {
        // 有效按键
    }
}
```

等待松手：

```c
while (KEY == 0);
```

意思：

> 只要按键还保持低电平，就一直等待；松手后继续执行。

---

## 3.5 轮询和中断

### 轮询

CPU 主动不断问：

```text
按了吗？
按了吗？
按了吗？
```

### 中断

外设主动告诉 CPU：

```text
事件发生了
↓
通知CPU
```

一句话：

> 轮询是 CPU 找外设，中断是外设找 CPU。

---

# 4. EXTI 与 NVIC

## 4.1 上升沿与下降沿

```text
0 → 1 = 上升沿
1 → 0 = 下降沿
```

如果按键：

```text
没按=1
按下=0
```

那么按下就是：

> 下降沿。

---

## 4.2 EXTI

EXTI = External Interrupt/Event Controller。

作用：

> 检测 GPIO 边沿变化并产生中断请求。

典型链路：

```text
GPIO
↓
AFIO映射
↓
EXTI
↓
NVIC
↓
CPU
↓
IRQHandler
```

---

## 4.3 NVIC

NVIC = Nested Vectored Interrupt Controller。

作用：

> 管理中断使能和优先级，并决定 CPU 先响应谁。

---

## 4.4 抢占优先级与响应优先级

### 抢占优先级

决定：

> 能不能打断另一个正在执行的中断。

### 响应优先级 / 子优先级

当抢占优先级相同时：

> 决定等待队列中谁先响应。

记忆：

```text
抢占优先级 = 能不能插队
响应优先级 = 同级排队谁靠前
```

STM32 中：

> 数值越小，优先级越高。

---

## 4.5 中断标志位

中断处理完成后通常需要清 pending flag。

例如：

```c
void EXTI0_IRQHandler(void)
{
    if (EXTI_GetITStatus(EXTI_Line0) != RESET)
    {
        // 处理事件

        EXTI_ClearITPendingBit(EXTI_Line0);
    }
}
```

否则系统可能认为：

> 中断还没有处理完。

---

## 4.6 ISR 尽量短

ISR = Interrupt Service Routine，中断服务程序。

不建议：

```c
void IRQHandler(void)
{
    Delay_ms(1000);
    // 很多耗时任务
}
```

更好的思想：

```c
volatile uint8_t Flag = 0;

void IRQHandler(void)
{
    Flag = 1;
}
```

主程序：

```c
if (Flag)
{
    Flag = 0;
    // 真正处理任务
}
```

---

# 5. Timer 定时器

## 5.1 Timer 本质

Timer 可以理解成：

> 硬件自动计数器。

CPU 不需要自己在 while 里数数。

---

## 5.2 PSC、CNT、ARR

### PSC

Prescaler，预分频。

> 决定数多快。

### CNT

Counter。

> 当前数到多少。

### ARR

Auto Reload Register。

> 决定数到哪里产生更新事件并开始下一轮。

一句话：

```text
PSC 决定数多快
CNT 表示当前数到哪
ARR 决定数多久
```

---

## 5.3 Timer 核心公式

\[
T=\frac{(PSC+1)(ARR+1)}{f_{timer}}
\]

例如：

```text
f_timer = 72MHz
PSC = 7199
ARR = 4999
```

则：

\[
72MHz/(7199+1)=10kHz
\]

每次计数：

\[
0.1ms
\]

共 5000 次：

\[
500ms = 0.5s
\]

---

## 5.4 为什么要 +1

因为：

```text
0 ~ 7199
```

一共有：

```text
7200 个状态
```

所以是：

```text
PSC + 1
ARR + 1
```

---

## 5.5 Timer 中断

典型结构：

```c
void TIM2_IRQHandler(void)
{
    if (TIM_GetITStatus(TIM2, TIM_IT_Update) != RESET)
    {
        // 处理更新事件

        TIM_ClearITPendingBit(TIM2, TIM_IT_Update);
    }
}
```

注意：

```c
TIM_ClearITPendingBit(...)
```

清的是：

> 更新中断挂起标志位。

不是把：

- TIM2 整体清零
- CNT 清零

真正手动设置计数器：

```c
TIM_SetCounter(TIM2, 0);
```

---

## 5.6 500ms 翻转 LED 的频率

如果：

```text
每 500ms 翻转一次
```

则：

```text
亮 → 0.5s → 灭 → 0.5s → 亮
```

完整周期：

```text
1s
```

所以 LED 闪烁频率：

\[
1Hz
\]

注意：

> 72MHz 是时钟频率，不是 LED 最终闪烁频率。

---

# 6. USART / UART

## 6.1 TX 与 RX

```text
TX = Transmit，发送
RX = Receive，接收
```

接线：

```text
STM32 TX  → USB-TTL RX
STM32 RX  ← USB-TTL TX
STM32 GND ↔ USB-TTL GND
```

TX/RX 要交叉。

---

## 6.2 为什么必须共地

电压必须有共同参考点。

双方需要知道：

> “0V 在哪里”。

所以数字通信不仅要接信号线，还要：

> 共地。

---

## 6.3 115200 8N1

```text
115200 = 波特率
8 = 8个数据位
N = 无校验
1 = 1个停止位
```

UART 常见一帧：

```text
1个起始位
8个数据位
1个停止位
```

所以 8N1 通常约 10 bit / 字节。

115200 baud 实际最大有效字节吞吐大约：

\[
115200 / 10 \approx 11520 B/s
\]

---

## 6.4 TXE 与 RXNE

### TXE

Transmit Data Register Empty。

表示：

> 发送数据寄存器空了，可以写下一个数据。

### RXNE

Receive Data Register Not Empty。

表示：

> 接收寄存器里有新数据。

注意：

> RXNE 本身首先是状态标志，不等于中断。

如果开启 RXNE 中断：

```text
收到数据
↓
RXNE=1
↓
产生USART中断
↓
进入USART1_IRQHandler
```

---

## 6.5 printf 重定向

典型思路：

```text
printf
↓
fputc
↓
USART_SendData
↓
TX引脚
↓
USB-TTL
↓
电脑
```

例如：

```c
int fputc(int ch, FILE *f)
{
    USART_SendData(USART1, ch);

    while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET);

    return ch;
}
```

此后：

```c
printf("Hello STM32\r\n");
```

就可以通过串口输出。

# 7. I2C

## 7.1 基本特点

I2C：

> 同步、串行、半双工、多设备总线。

两根主要信号线：

```text
SCL = Clock，时钟线
SDA = Data，数据线
```

---

## 7.2 多设备如何区分

I2C 靠：

> 设备地址。

例如：

```text
0x3C → OLED
0x50 → EEPROM
```

一句话：

> I2C 地址回答“你是谁”。

---

## 7.3 开漏 + 上拉

SDA/SCL 通常使用：

> 开漏 + 上拉电阻。

原因：

多个设备共享总线时，如果都用推挽，可能一个强拉高、一个强拉低，形成冲突。

开漏规则：

```text
没人拉低 → 上拉电阻让总线=1
有人拉低 → 总线=0
```

---

## 7.4 START 与 STOP

### START

当：

```text
SCL = 1
```

时：

```text
SDA：1 → 0
```

### STOP

当：

```text
SCL = 1
```

时：

```text
SDA：0 → 1
```

---

## 7.5 ACK 与 NACK

I2C 每发送完 8 bit，通常第 9 个时钟用于应答。

```text
ACK  = SDA=0
NACK = SDA=1
```

ACK：

> 收到了，通常可以继续。

NACK：

> 不响应，或者“不要继续发了”。

NACK 不一定表示错误。

例如主机读多个字节：

```text
Byte1 → ACK
Byte2 → ACK
最后一个Byte → NACK
STOP
```

最后的 NACK 表示：

> 这个字节收到了，但后面不用继续发。

---

## 7.6 R/W 位

```text
R/W = 0 → Write
R/W = 1 → Read
```

7 位地址有时会左移一位，再加入 R/W 位。

例如：

```text
7位地址：0x3C
左移后：0x78
写：0x78
读：0x79
```

所以资料中看到不同“地址”时要注意表示方式。

---

## 7.7 软件 I2C 与硬件 I2C

### 软件 I2C

普通 GPIO 手工模拟时序：

```text
拉高
拉低
延时
读取
```

优点：

- 好理解
- 引脚灵活

### 硬件 I2C

使用 STM32 的 I2C 外设。

优点：

- CPU 占用更少
- 硬件处理时序

---

# 8. SPI

## 8.1 四根典型线

```text
SCK  = 时钟
MOSI = Master Out Slave In
MISO = Master In Slave Out
CS   = 片选
```

如果 STM32 是 Master：

```text
MOSI：STM32 → 从机
MISO：STM32 ← 从机
```

---

## 8.2 为什么 SPI 是全双工

因为：

```text
MOSI 和 MISO 是两根独立数据线
```

可以同时：

```text
主机发送
+
从机返回
```

---

## 8.3 I2C 与 SPI 的设备选择

```text
I2C：靠地址
SPI：靠CS片选
```

SPI 多一个设备，通常需要多一根 CS。

---

## 8.4 Dummy Data

SPI 本质是：

> 双方移位寄存器随 SCK 同步移位。

主机想读取从机数据，也必须产生 SCK。

所以主机常发送：

```text
0xFF
```

这样的 Dummy Data。

目的：

> 产生时钟，把从机数据一位一位移出来。

不是单纯为了“腾空寄存器”。

---

## 8.5 CPOL 与 CPHA

### CPOL

决定：

> SCK 空闲电平。

```text
CPOL=0 → 空闲SCK=0
CPOL=1 → 空闲SCK=1
```

### CPHA

决定：

> 第一个还是第二个有效边沿采样。

组合得到 SPI Mode 0~3。

---

# 9. CAN

## 9.1 基本特点

CAN 适合：

- 汽车
- 工业
- 多控制器
- 强干扰环境

两根线：

```text
CAN_H
CAN_L
```

它们组成：

> 差分信号。

---

## 9.2 为什么抗干扰

接收端更关心：

\[
V_{CAN_H}-V_{CAN_L}
\]

如果外界干扰让两根线同时增加 0.5V：

```text
CAN_H +0.5V
CAN_L +0.5V
```

差值可能基本不变。

所以：

> 抗共模干扰能力强。

---

## 9.3 CAN ID

CAN 不主要靠“设备地址”，而是：

> 消息 ID。

例如：

```text
0x100 = 电机转速
0x101 = 电机温度
0x200 = 电池电压
```

一句话：

```text
I2C地址：你是谁？
CAN ID：这是什么消息？
```

---

## 9.4 仲裁

CAN：

```text
0 = 显性位
1 = 隐性位
```

0 可以压过 1。

多个节点同时发送时：

```text
边发送
↓
边监听总线
↓
发现自己发1但总线是0
↓
说明输掉仲裁
↓
停止发送
```

所以：

> ID 数值越小，仲裁优先级通常越高。

低优先级帧等总线空闲后再重发。

这叫：

> 无破坏性仲裁。

---

## 9.5 120Ω 终端电阻

CAN 总线两端通常各接：

```text
120Ω
```

用于：

> 阻抗匹配，减少信号反射。

两个 120Ω 并联：

\[
120 \parallel 120 = 60\Omega
\]

所以断电时测 CAN_H 与 CAN_L：

> 常见约 60Ω。

---

## 9.6 CAN 收发器

STM32 通常不能直接接 CAN_H/CAN_L。

结构：

```text
STM32 CAN控制器
↓
CAN收发器
↓
CAN_H / CAN_L
```

一句话：

> CAN 控制器负责协议，CAN 收发器负责电气层。

---

# 10. UART / I2C / SPI / CAN 总对比

| 协议 | 主要线 | 同步/异步 | 双工 | 多设备方式 | 特点 | 典型用途 |
|---|---|---|---|---|---|---|
| UART | TX/RX | 异步 | 全双工 | 通常点对点 | 简单 | PC、调试、模块 |
| I2C | SDA/SCL | 同步 | 半双工 | 设备地址 | 线少 | OLED、传感器、EEPROM |
| SPI | SCK/MOSI/MISO/CS | 同步 | 全双工 | CS片选 | 快 | Flash、LCD、高速外设 |
| CAN | CAN_H/CAN_L | 总线同步 | 总线式 | 消息ID | 抗干扰、高可靠 | 汽车、工业、多节点 |

口诀：

```text
UART：两个设备直接聊
I2C：两根线，靠地址找设备
SPI：线多一点，靠CS，速度快
CAN：多节点广播，靠ID表示消息，差分抗干扰
```

---

# 11. ADC

## 11.1 ADC 是什么

ADC = Analog-to-Digital Converter。

作用：

> 把模拟电压转换成数字值。

GPIO 只能回答：

```text
高还是低？
→ 0 / 1
```

ADC 可以回答：

```text
这个电压大概是多少？
→ 0~4095
```

---

## 11.2 STM32F103 的 12 位 ADC

\[
2^{12}=4096
\]

所以结果范围：

```text
0 ~ 4095
```

如果：

```text
Vref = 3.3V
```

则：

```text
0    ≈ 0V
2048 ≈ 1.65V
4095 ≈ 3.3V
```

换算：

\[
V=\frac{ADC_Value}{4095}\times Vref
\]

---

## 11.3 ADC 分辨率

如果 Vref=3.3V：

\[
3.3/4096 \approx 0.806mV
\]

理论上每一级约：

> 0.806mV。

---

## 11.4 模拟输入模式

ADC 引脚通常配置：

```c
GPIO_Mode_AIN
```

作用：

> 让引脚工作在模拟采样状态，减少数字输入电路带来的额外干扰与功耗。

---

## 11.5 采样时间

ADC 一般经历：

```text
采样
↓
保持
↓
转换
```

采样时间太短，尤其信号源阻抗较高时：

> ADC 内部采样电容可能还没充到正确电压，导致结果偏差。

---

## 11.6 单次、连续、扫描

### 单次转换

```text
启动一次
↓
转换一次
↓
结束
```

### 连续转换

```text
转换
↓
转换
↓
转换
...
```

### 扫描模式

多个通道轮流：

```text
CH0 → CH1 → CH2 → CH0...
```

---

## 11.7 ADC + DMA

典型：

```text
模拟信号
↓
ADC
↓
DMA
↓
SRAM数组
↓
CPU处理
```

# 12. PWM

## 12.1 PWM 是什么

PWM = Pulse Width Modulation，脉宽调制。

它不是输出真正连续模拟电压，而是：

> 输出 0V / 3.3V 快速切换的数字脉冲。

---

## 12.2 两个核心参数

### 频率

\[
f=\frac{1}{T}
\]

表示：

> 一秒重复多少个周期。

### 占空比

\[
Duty=\frac{T_{high}}{T}\times100\%
\]

表示：

> 一个周期内高电平所占比例。

---

## 12.3 PWM 与 Timer

PWM 常用：

```text
PSC
ARR
CNT
CCR
```

其中：

```text
PSC：决定计数速度
ARR：决定周期
CNT：当前计数值
CCR：决定比较点/占空比
```

频率：

\[
f_{PWM}=
\frac{f_{timer}}
{(PSC+1)(ARR+1)}
\]

占空比近似：

\[
Duty\approx\frac{CCR}{ARR+1}\times100\%
\]

---

## 12.4 频率与占空比的关系

它们是两个不同概念。

频率：

> 波形重复得多快。

占空比：

> 一个周期内高电平占多少。

例如：

```text
Timer=72MHz
PSC=71
ARR=999
CCR=500
```

则：

```text
PWM频率 = 1kHz
占空比 = 50%
```

只修改 CCR：

```text
CCR=800
```

则：

```text
频率仍为1kHz
占空比变80%
```

但修改 ARR 时：

> 可能同时影响频率和占空比。

---

## 12.5 LED、电机、舵机

### LED

占空比越大：

> 平均亮度通常越高。

### 直流电机

通过驱动电路：

> 占空比通常影响平均功率和转速。

### 普通位置舵机

不是“占空比越大转得越快”。

通常：

> 脉冲宽度决定目标角度。

常见控制周期约：

```text
20ms = 50Hz
```

高电平脉宽约：

```text
0.5~2.5ms
```

具体看舵机型号。

---

# 13. Watchdog 看门狗

## 13.1 看门狗的作用

看门狗用于：

> 程序卡死、跑飞、死循环时，自动复位 MCU。

正常：

```text
执行任务
↓
喂狗
↓
继续运行
```

异常：

```text
程序卡死
↓
无法喂狗
↓
看门狗超时
↓
RESET
```

---

## 13.2 喂狗是什么

喂狗不是关闭看门狗。

而是：

> 重装看门狗计数器，让它重新开始计时。

---

## 13.3 IWDG

IWDG = Independent Watchdog。

特点：

- 使用独立低速时钟
- 主系统异常时仍可能继续运行
- 超时后复位
- 只要求“超时前喂狗”

适合作为：

> 系统兜底。

---

## 13.4 WWDG

WWDG = Window Watchdog。

特点：

> 必须在规定时间窗口内喂狗。

```text
太早 → 不行
窗口内 → 正确
太晚 → 不行
```

相比 IWDG：

> 能进一步检测“程序运行节奏异常”。

---

## 13.5 为什么不能无条件在 Timer ISR 喂狗

如果：

```text
main已经卡死
↓
Timer中断仍正常
↓
Timer ISR一直喂狗
↓
系统永远不复位
```

看门狗就失去意义。

正确思想：

> 确认关键任务真的正常以后，再允许喂狗。

---

## 13.6 看门狗不是万能的

如果程序业务逻辑错了，但仍然正常执行：

```text
错误控制电机
↓
仍然FeedDog()
```

看门狗不会知道业务逻辑错了。

所以系统可靠性需要：

```text
逻辑检查
+
超时检测
+
故障检测
+
看门狗
```

共同完成。

---

# 14. RTC 与低功耗

## 14.1 RTC

RTC = Real-Time Clock。

主要用于：

- 日期时间
- 长时间计时
- 闹钟
- 低功耗唤醒

和 Timer 区分：

```text
RTC：现在几点、多久后醒来
Timer：短周期精确定时、PWM、计数
```

---

## 14.2 32.768kHz

\[
32768=2^{15}
\]

非常方便二分频成：

\[
1Hz
\]

所以 RTC 常用：

> 32.768kHz 外部晶振。

---

## 14.3 LSE 与 LSI

### LSE

Low-Speed External。

外部低速晶振。

特点：

> 通常更准确，更适合 RTC。

### LSI

Low-Speed Internal。

内部低速 RC。

特点：

> 方便，但通常精度较差。

---

## 14.4 备份域与 VBAT

RTC 等位于备份域。

VBAT 可给备份域供电。

主电源掉电后：

```text
VBAT
↓
RTC继续运行
```

所以重新上电后时间仍能保持。

---

## 14.5 低功耗模式

常见：

```text
Sleep
Stop
Standby
```

功耗通常：

```text
正常运行 > Sleep > Stop > Standby
```

### Sleep

CPU 睡眠，很多外设仍可工作。

### Stop

CPU 和主要高速时钟停止，SRAM 通常保持。

### Standby

更深度休眠，功耗最低，恢复代价最大。

---

## 14.6 低功耗不只是 CPU 睡眠

还要考虑：

- GPIO 是否悬空
- 外设是否还运行
- ADC 是否关闭
- 无线模块是否休眠
- 传感器是否断电
- 时钟是否关闭

所以：

> 低功耗是系统级设计。

---

# 15. DMA

## 15.1 DMA 是什么

DMA = Direct Memory Access。

作用：

> 自动搬运数据，减少 CPU 逐字节参与。

例如：

```text
ADC
↓
DMA
↓
SRAM数组
```

CPU 不需要每个采样点都亲自搬。

---

## 15.2 DMA 常见方向

### 外设 → 内存

```text
ADC → SRAM
USART RX → SRAM
SPI RX → SRAM
```

### 内存 → 外设

```text
SRAM → USART TX
SRAM → SPI TX
```

---

## 15.3 外设地址与内存地址

ADC 例子：

```text
ADC_DR = 固定地址
```

所以：

```text
Peripheral Increment = Disable
```

而：

```text
buffer[0]
buffer[1]
buffer[2]
...
```

所以：

```text
Memory Increment = Enable
```

---

## 15.4 数据宽度

例如 ADC 12 位结果常存入：

```c
uint16_t
```

所以可以用：

> Half Word，16 bit 搬运。

USART 常见 8 bit：

> Byte 搬运。

---

## 15.5 Normal 与 Circular

### Normal Mode

```text
搬N个
↓
停止
```

### Circular Mode

```text
搬到数组末尾
↓
回到开头
↓
继续搬
```

注意：

> Normal 不等于一定产生中断。

是否中断取决于：

> 是否开启 TC 等 DMA 中断。

---

## 15.6 DMA 完成中断

DMA 搬完：

```text
Transfer Complete
↓
DMA中断
↓
NVIC
↓
CPU
```

所以：

> DMA负责搬，中断负责通知。

---

## 15.7 DMA 能做什么、不能做什么

DMA 能：

> 搬数据。

DMA 不能：

- FFT
- PID
- 滤波
- 协议解析
- 业务判断

一句话：

```text
DMA = 搬运工
CPU = 计算和决策
```

---

# 16. 整体嵌入式系统思维

一个典型系统：

```text
             输入
              │
      ┌───────┼────────┐
      ↓       ↓        ↓
     按键    串口     传感器
      │       │        │
     EXTI   USART     ADC
      │       │        │
      └───────┼────────┘
              ↓
             CPU
              │
          程序逻辑
              │
      ┌───────┼────────┐
      ↓       ↓        ↓
     LED     电机      通信
     GPIO    PWM      CAN/SPI
```

核心模式：

> 采集输入 → 程序决策 → 控制输出。

---

# 17. 中断与主程序的工程结构

一个比较典型的架构：

```c
int main(void)
{
    Hardware_Init();

    while (1)
    {
        if (KeyFlag)
        {
            KeyFlag = 0;
            // 按键业务
        }

        if (TimerFlag)
        {
            TimerFlag = 0;
            // 周期任务
        }

        if (SerialFlag)
        {
            SerialFlag = 0;
            // 通信业务
        }
    }
}
```

中断：

```c
void EXTI0_IRQHandler(void)
{
    KeyFlag = 1;
}

void TIM2_IRQHandler(void)
{
    TimerFlag = 1;
}

void USART1_IRQHandler(void)
{
    SerialFlag = 1;
}
```

工程思想：

> 中断尽量快速采集/置标志，复杂业务放主循环。

# 18. 易错点汇总

## GPIO

错误：

> 上拉默认 0。

正确：

```text
上拉 → 默认1
下拉 → 默认0
```

---

## 开漏

错误：

> 开漏需要上下拉。

正确：

> 开漏通常需要上拉来得到高电平。

---

## I2C

不要混：

```text
SCL = 时钟
SDA = 数据
```

START：

```text
SCL=1时，SDA 1→0
```

STOP：

```text
SCL=1时，SDA 0→1
```

ACK：

```text
SDA=0
```

NACK：

```text
SDA=1
```

---

## Timer

```c
TIM_ClearITPendingBit(...)
```

不是清 CNT。

它清的是：

> 中断 pending flag。

---

## USART

RXNE：

> 首先是“接收寄存器非空”的状态标志。

不是中断本身。

---

## SPI

Dummy Data 的作用：

> 产生 SCK，把从机数据移出来。

---

## CAN

CAN ID：

> 消息标识符，不等同于设备地址。

I2C 地址：

> 找设备。

CAN ID：

> 表示消息是什么。

---

## PWM

PWM：

> 数字脉冲，不是真正模拟输出。

直流电机：

> PWM 占空比通常影响转速。

普通位置舵机：

> 脉宽通常决定角度，不是“占空比越大越快”。

---

## 看门狗

不要：

> 无条件定时器中断喂狗。

应该：

> 确认关键任务正常后再喂。

---
